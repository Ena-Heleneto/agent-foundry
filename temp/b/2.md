# @packages/skills 包 的构建代码的评审与优化

  1. **讨论阶段**  
    本轮是 Spec Kit 启动前的原始需求讨论。围绕 `packages/skills` 尚未完成的构建与发布工作，结合仓库现状，逐项确认需求范围、兼容边界和验收条件。版本回退机制与测试范围在本轮讨论中确定。

  2. **交付产物**  
    讨论结束后，将已确认的需求、验收条件和相关调研结论整理成一份 Spec Kit 提示词，保存到项目临时目录。

  3. **流水线交付顺序**  
    先完善测试环境的发布流水线。测试环境通过约定的验收后，再扩展到生产环境。

  4. **开发协作**  
    开发阶段，将彼此独立的调研、核对和审查工作尽量交给多个子代理并行处理。主代理继续推进手头工作，子代理得出结论后主动汇报。
    程中，在不影响主代理开发的情况，附属工作尽可能使用多个子代理同步进行，主代理不需要等待子代理，当子代理有结论后，汇报处理即可
