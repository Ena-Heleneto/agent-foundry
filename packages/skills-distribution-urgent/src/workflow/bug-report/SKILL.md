# 缺陷报告

## 标准输入

调用方提供缺陷描述、可检索的需求/设计/历史材料集合、代码范围、报告目录或落点判定策略、时间格式及仓库格式约定。缺陷现象、触发条件或期望行为缺失时先补充；没有明确修复授权时只调查和写报告，不修改代码。

## 标准规则

检索调用方提供的材料，公开列出命中关系和依据，不扫描某种工具专有的默认目录。单关联或多关联的报告落点按调用方明确策略选择，报告保留全部关联；无关联或策略不足时请求指定落点，未明确前不创建报告。

报告包含八项：时间、关联材料、现象与期望/实际差异、可复现步骤、影响范围、带代码位置的逻辑流程图、拟修复方案、代码路径及行号。未复现或证据不足如实标注，不能把推测当已验证原因；图一图一事，术语用大白话解释。文件名及格式检查遵循调用方约定。

报告保存并检查后展示路径与关键结论。是否继续修复取决于当前真实授权：仅要求报告则询问修复；用户此前已明确授权修复时不重复索取同一许可。拒绝修复则保留报告结束，不实施代码改动。
