# 测试词

用下面这些提示词检查 skill 是否会触发，并确认输出行为符合预期。

## 直接调用

- `使用 $document-changed-symbols 给这个 TypeScript 文件新增一个辅助函数和一个变量。`
- `使用 $document-changed-symbols 修改这个 Vue 页面，所有改动的函数和变量上方都要写文档注释。`
- `使用 $document-changed-symbols 重构这个 Python 函数，并新增一个模块级常量。`

## 自然语言触发

- `帮我改这个页面，每个改动的函数和变量上方都要写文档注释。`
- `新增一个查询方法和状态变量，所有新增或修改的声明都要有注释。`
- `修复这个 bug，同时给本次改动到的函数、常量、变量补文档注释。`
- `改代码的时候，给每个改动的函数、方法、变量和常量上方写文档注释。`
- `这个 patch 里所有改动的符号上方都要补注释。`

## 预期检查

- Agent 会在编辑前或编辑过程中识别本次改动的声明。
- 每个新增或行为发生变化的符号上方都有文档注释。
- 已经准确的旧注释会被保留。
- 因本次改动变得不准确的旧注释会被同步更新。
- 不会给无关旧代码批量补注释，也不会做无关格式化。

## 反向测试

- `更新生成出来的 snapshot。` 预期：除非用户明确要求，否则不要给生成产物手写注释。
- `只格式化整个文件。` 预期：没有代码符号语义变化时，不新增文档注释。
- `改一个 JSON 多语言文案。` 预期：纯数据内容不添加文档注释。
