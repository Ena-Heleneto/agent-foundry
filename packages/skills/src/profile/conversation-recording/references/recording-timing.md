# 会话记录的触发和保存时机

项目级安装即启用记录。每条新用户消息都进入本流程，包括问候和普通问答。先取得当前轮的实际归属核验结果并保存，再执行业务或发出回复。Linux 下的宿主入口为 Codex CLI 0.171.0 分页交互会话。空白启动时等待首条用户消息。归属不符或无法核实时，沿会话归属规则继续当前任务。[会话归属与身份](session-scope.md)

## 首条消息与普通轮次

1. 核实本轮入口和会话身份后，使用首次开启日定位记录。在首个业务动作前，将本轮用户原文写入主记录并读回。首条原话确认后，用独立的工具调用开始业务。[逐项保存规则](save-events.md)
2. 随本轮继续，将新出现且可取得的普通发言和业务事件按实际发生顺序逐项写入对应的主记录块或本轮详情。保留已确认范围，使用真实轮次和事件定位。按资料契约处理内部维护、提交例外及写入缺口。[共用资料契约](storage-contract.md)

## 普通末轮

先确定即将发出的完整答复。在主记录的本轮块预存一份标明待发送的原文，用当前真实轮次定位。按逐项保存规则读回主记录，再将读回确认的同一文本发给用户，保留其空白与换行。发送前编辑文本时，在同一位置更新并重新读回。

待发送状态表示该文本已保存。实际发出由宿主的发言事件确认，取得该事件时关联其真实定位。退出核验从主记录读回末轮原文，与宿主实际发出的完整答复逐字比较。

## 停止或退出

会话被用户停止、中断或关闭时，保留已经确认的主记录、详情及附件。按实际可核实状态保留待发送文本或记录缺口。之后能够继续且归属可核实时，沿原轮次和已确认位置处理仍可取得的内容。普通回复走上面的发送前保存时机，因此用户在收到末轮后即可退出。[保存确认与失败恢复](storage-contract.md#保存确认与失败恢复)
