# 逐项保存主记录、详情和附件

核实归属、会话 ID、轮次 ID、首次工作目录及本地开启时间。按[资料契约](storage-contract.md#选择资料根)核对项目内目标位置和 Git 可见性。每次写入按[会话协调](resume-records.md)读回现有内容，保留其他轮次。使用现有工具逐项写入、确认实际新增范围；部分失败按[缺口规则](write-failures.md)处理。

## 主记录

从 [主记录模板](../template/record.md) 建立 `records/<开启日>/<会话ID>.md`。首条用户原话单独写入并读回，随后开始业务。一条宿主轮次一个块，块日期取该轮首条用户消息的本地日期。按真实事件定位和顺序保留发起、同轮补充和最终回复；在实际发生处插入「补充」。过程短句仅陈述已发生的活动，普通问答省略过程及详情链接。

对多行原文使用可逆的 Markdown 表示。保留空行和代码围栏，将块引用和列表的外层前缀与原文分开；在事件定位处注明原文行尾状态，读回时去除外层前缀并比对字符、空白和换行。将事件定位作为轮次块内的 Markdown 注释保存。无法完整还原的范围按实际缺口记录。

## 详情及附件

1. 本轮有可留存的可见进度、可见推理摘要、工具活动或附件时，以[详情模板](../template/detail.md)建立 `details/<会话ID>/<轮次ID>.md`。逐项记录实际事件定位和原文；参数、输出及发言各自保留可还原的格式。使用不与原文冲突的围栏，明确是否有末尾换行。
2. 附件逐个写入详情同级的 `attachments/`。先读回已记录的事件和文件。已确认的同一事件及附件直接复用；目标存在且内容不同时选择另一安全文件名，按实际来源关联，保持已有文件和链接。对新写入原件读回核对 SHA-256 后再给对应事件添加链接。相对链接按路径段进行 UTF-8 百分号编码。缺少原件时保留来源和缺失范围。
3. 读回详情，核对轮次身份、事件顺序和已确认附件。详情文件可打开后，在主记录块添加独立的「查看经过」相对链接，并读回验证目标。详情暂未确认时先保留主记录的发言和已确认事件。

本次读回结束后返回业务。仅为保存、复制、断点核对或读回产生的内部工具活动不进入待保存事件。
