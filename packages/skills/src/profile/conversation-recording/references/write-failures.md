# 写入失败与重试

用实际工具结果和读回结果判定本次保存。写入、复制或读回未完成时，从已经核对的文件及事件定位确认可用范围，指出仍缺失的轮次、字段、块或附件以及已知原因。保留已有身份、轮次和确认内容，按会话锁协调检查和保存。[保存确认与资料契约](storage-contract.md#保存确认与失败恢复) · [会话写入协调](resume-records.md)

## 继续任务前提示缺口

在下一次业务调用或普通回复前，先发出用户可见的提示。说明具体受影响的记录、原因和可回查的已确认内容，然后继续用户任务。资料区暂不可写时，直接在会话提示原因和范围。工具错误回包可作为判断依据，用户可见提示负责交代实际结果。

实际路径或工具结果表明索引目标拒绝写入时，在提示中明确说明「索引写入失败」和实际原因。详情已读回确认时，附上当轮详情路径和轮次锚点。写入结果尚无法核实时，说明索引保存未确认及对应原因。

| 失败位置 | 保存判断和恢复条件 |
| --- | --- |
| 索引 | 先读回核对详情及附件。把已确认的详情路径和轮次锚点作为可继续交接的范围。索引块保留待补，恢复可写后补对应链接。 |
| 详情 | 保留此前读回确认的块，并说明本轮未确认部分。索引只关联已确认的真实详情。缺少已确认目标时暂缓本轮索引。 |
| 附件 | 核对已经写入的其他原件和详情字段。失败附件在详情保留实际来源定位与缺口，其他已确认内容仍可使用。补得原件后再核对实物、摘要及有效链接。 |
| 资料区 | 发生根路径冲突或资料区整体不可写时，保留原资料位置，在本轮说明受影响的保存范围。恢复后从原位置读回检查。 |

## 可写后从实际断点重试

在会话归属可核实且资料区恢复可写时，重新取得会话锁并读回索引、详情和附件。以实际事件定位核对目标，已有确认部分直接复用。先补已有可靠原文或原件的部分，核对详情及附件后再补索引。用本次读回确认新补的内容，更新相应缺口并保留其余缺档。[成对保存规则](paired-save.md) · [断点续写](resume-records.md#按真实事件定位续写)

原文或原件已经不可取得时，在已知的轮次、事件或附件位置标明缺档，写入可确认的原因和来源。资料区仍不可写时，缺口沿本轮用户可见提示保留。下一次允许重试时沿原位置核对，先前通过读回的材料继续供下游使用。
