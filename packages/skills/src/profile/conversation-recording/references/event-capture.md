# 内容采集与提交边界

完成[会话与轮次归属核验](session-scope.md)后，从当前工具的实际调用和回包取得原值。需要补查时，只读已核实父会话的当前轮及必要来源位置，按[逐项保存规则](save-events.md)写入主记录或当轮详情。

## 识别发言来源

写入首条用户原文或补写本轮发言前，先核对宿主标记的实际来源。Codex CLI 0.171.0 分页会话中的 `response_item` 消息可在 `internal_chat_message_metadata_passthrough.content_item_kinds` 提供内容项类型。类型与 `content` 项能逐项对应时，按位置核对。保留真实用户输入 `user.text` 的原值及事件定位，用户附件按下文核对原件。将 `agents_md.instructions` 和 `environments.environment_context` 用于项目及环境核验，从用户发言采集中跳过这两类宿主附带项。

内容项类型缺失或无法对应时，从宿主独立标识的用户发言事件核对原文及轮次。能够确认属于同一次实际输入的多种表示只保存一次。仍无法核实的内容保留具体来源缺口。

## 可见进度原话

在已核实的当前轮事件范围内检查宿主已展示的助手消息。Codex CLI 0.172.0 的进度原话来自 `response_item` 中 `type=message`、`role=assistant`、`phase=commentary` 的消息。逐项保留 `content` 里可见 `output_text` 的 `text`，用真实事件标识或消息来源位置及内容项序号定位，和工具事件按宿主顺序写入详情。仅出现进度原话也应建立详情。助手最终答复沿主记录的发送前保存规则处理；私有推理和未向用户展示的内容跳过。无法取得原话时标明实际缺口。

## 工具原值和顺序

- 在详情保留实际工具名称、调用标识、工作目录、参数和回包。用已取得的 `call_id` 或稳定来源位置关联调用及结果，按宿主发生顺序记录。Code Mode 包裹多个工具时，保留外层调用与可辨认的内部工具、参数和回包顺序。参数保持结构、取值及类型，文本原文保留空白、换行及行尾。工具自己的工作目录随调用留存，会话归属沿用原仓库和父轮次。
- 流式命令按实际命令会话号把 `exec_command` 的首段与 `write_stdin` 的后续回包关联，保留各段定位、原文顺序和最终退出状态。对截断的返回保留可见原值与截断范围。能从已核实的同一来源读到完整原件时，另行比对来源、字节数和摘要并保存。只有摘要、不可读路径或不透明值时，标明对应缺口和实际原因。
- 只使用父会话实际可见的子代理派发、交互及回传。用实际父轮次和 `agent_thread_id` 关联 `SubAgentActivity` 及对应工具事件。保留可见的 `spawn_agent`、`list_agents`、`followup_task` 参数、结果和回传原文。参数只留下不透明值时，保留其实际可见形式并标明缺少明文。空工具回包按空值记录，后续回传仍按其实际事件保存。
- 按实际用途选择事件。为办理用户另行委托的读取、审查、修改或派发而执行的调用属于业务。为执行记录流程而读取 Skill 及其资料、核对归属、定位采集来源、写入、复制附件、检查断点及读回的调用属于记录维护。两类用途分别调用，即使工具名或文件路径相同。完成读回后结束本次保存。

## 改动文件和附件

密钥、环境变量值和认证文件按仓库提交约定排除；详情标明省略范围及仍可保存的操作信息。

- 用本轮实际操作、返回或能够归属到该操作的文件前后状态核对改动文件。在主记录的过程短句概括已经证实的操作。并行或预存差异以实际操作证据判断归属，未能归属的范围明确标记。工具在仓库外工作时也保留其真实工作目录。
- 附件从实际用户输入、工具回包或经核实的可读原件取得。对 `image_url` 的数据地址、MCP 图像 `data` 和内嵌资源 `blob`，解码实际返回的字节。若工具只返回资源链接，用宿主的资源读取工具取得原件再核对。只有路径提示、摘要或不可读取的返回时，详情标明具体缺口。
- 把取得的原件按字节保存，并在所属详情块保留来源事件、相对链接与 SHA-256。读回目标核对字节和摘要后确认该附件。原件与表示形态不明确时，以实际取得的字节和来源说明为准。[逐项保存规则](save-events.md#详情及附件)

## 每次实际提交及其结果

1. 进入本次提交前，先保存原始用户请求和已实际发生的修复。修复、日常检查与实际提交分别调用。主记录和详情沿正常规则保留首次提交前以及两次提交之间的已确认改动。
2. 从本次实际提交步骤开始，到它的对应结果回复发出，暂停对该提交及该结果的记录写入。提交调用、回包和对应结果回复均按这一次的实际边界跳过。只出现工具结果时，以工具结果完成为该次边界结束点。结果作为末轮回复时沿提交例外处理。[共用资料契约](storage-contract.md#主记录详情与附件)
3. 本次提交失败后结束该次跳过范围。随后的修复、修复所产生的工具活动和发言照常采集、保存并读回。再次执行实际提交时重新进入独立跳过范围。对应普通后续回复按[保存时机](recording-timing.md)继续记录。

恢复时按真实调用、结果和回复定位沿用同一判断。只对已有可验证依据的提交步骤及其对应结果应用例外，保留各次提交之间的普通修复。
