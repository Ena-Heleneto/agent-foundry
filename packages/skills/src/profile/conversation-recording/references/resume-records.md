# 会话写入协调和断点续写

先实际核对当前轮次及会话的归属。跨启动恢复须核实原会话和本次恢复前入口。归属不明时跳过记录区读写和会话正文补读，继续用户任务。归属可核实时使用原开启日、原线程及原仓库归属定位成对文件。[会话归属与身份](session-scope.md)

## 在同一持锁范围内保存

1. 核对资料根和目标路径后，用原日详情目录下的 `attachments/<会话>/` 作为该会话的稳定协调位置。在已验证的 Linux 环境，用现有终端工具在该目录上取得独占 `flock`，或用同一工具调用内持有目录描述符并执行等价的 `flock`。同一会话各次保存复用同一真实目录。文件替换期间保持该目录稳定。
2. 取得锁后读回成对文件、对应附件及目标轮次，核对线程、原仓库、首次工作目录和开启日。核对详情事件、附件实物及索引指向的确认范围，以此确定断点。从查断点到保存附件、详情和索引，再到实际读回，使用同一次持锁范围。完成读回后释放锁，继续业务调用。[成对保存规则](paired-save.md)
3. 从重新取得锁和读取现状开始重试，以实际文件状态判断哪些部分已经确认。等待超出工具可用时间或实际位置有冲突时，沿[资料契约](storage-contract.md#保存确认与失败恢复)说明受影响的保存范围。

## 按真实事件定位续写

- 使用已有索引与详情的路径和原轮次锚点。按原开启日续写，恢复日只表示本次发生时间。合格恢复尚未建档时，从本次首条可得消息开始，在原开启日建立成对文件。
- 逐项按宿主轮次、事件类别及实际事件标识核对已确认记录。没有独立事件标识时，使用经验证可再次取得的来源位置。共用调用 ID 的工具请求、回包及多个回包分段各自保留可区分的位置。相同标识且归属一致的已确认事件只保留一次。相同正文的不同真实事件分别保存，保持实际顺序。
- 将真实事件定位随详情写入。同一位置的附件或字段已确认时复用原记录。索引缺失或未关联时，结合已确认的详情及附件确定可继续的范围。没有新事件、待补的内容或关联时，读回确认后结束保存。
- 已知事件曾发生且原文已不可取得时，在其真实轮次和可知位置写下缺档与实际原因。同一缺档沿原定位保留。实际发出的普通末轮可取得时，关联同一轮的预存位置，并以宿主确认的原文和事件位置为准。[普通末轮时机](recording-timing.md#普通末轮)
- 对恢复时可取得的发言和工具活动继续按操作用途判断。保留两次提交间的修复，按每次实际提交及对应结果定位执行例外。记录维护活动沿同一边界处理。[内容采集与提交边界](event-capture.md#每次实际提交及其结果)
