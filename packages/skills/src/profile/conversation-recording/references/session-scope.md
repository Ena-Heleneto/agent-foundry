# Codex CLI 会话归属与身份

Hook 先用当前项目位置和当前线程的宿主元数据核验归属，再读取已有记录或会话正文。遇到非交互入口、工作树范围不符、证据缺失或冲突时，跳过自动记录及正文补读，继续用户任务。

当前线程的只读来源是 Codex 已有的宿主状态目录，通常为 `~/.codex/`。按当前线程 UUID 精确定位，读取所需字段即可。主记录、详情与附件统一写入项目内的资料根。

## 核对仓库与当前轮次

1. 由实际安装的脚本位置确定目标项目。以回调所给的有效路径核对 Git 工作树，`PostToolUse` 使用 Hook 进程的工作目录核验会话归属，并把回调所给的工具工作目录用于详情。
2. 使用回调中的会话 UUID、轮次 UUID 和事件文件路径。事件文件解析后须位于 `CODEX_HOME` 的 `sessions/` 下，且 `rollout-*-<UUID>.jsonl` 的会话标识与回调一致。
3. 以只读方式打开 `thread_history_1.sqlite`。数据库位于 `CODEX_SQLITE_HOME`，未设置时位于 CLI 状态目录。按线程查询 `thread_turns` 中字节偏移最大且唯一的轮次，要求与回调轮次匹配、状态为 `inProgress` 且偏移有效。强制中断后可能还存在偏移更早的 `inProgress`，按实际索引位置识别当前轮。
4. 在事件文件中按索引的字节偏移无缓冲定位。先核对顶层 `type=event_msg` 和 `payload.type=task_started`，再读取轮次元数据。`payload.turn_id` 须与回调一致，`payload.turn_attribution.turn_trigger` 须为 `user`。类型、轮次或触发证据不符时结束核验。
5. 从事件文件首行读取 `session_meta`，核对会话 UUID、`originator=codex-tui` 和首次目录。首次目录和当前有效目录均属于目标 Git 工作树时进入保存流程。

## 首次建档与按轮续写

业务子代理回复的 `SubagentStop` 回调携带父会话及子轮次身份。使用分页索引核对父会话最近有效的用户轮，确认父轮以及目标子线程的 Git 工作树。子线程的首次派发必须关联当前父会话，目标子轮必须对应父会话内的实际派发或补充活动。核对后读取该子轮的最终回复事件，使用可核实的宿主时间续写父会话记录。

**首次交互。** 用匹配会话文件名的本地日期作为开启日，跨午夜发首条也沿用该日期。

**后续轮和交互式恢复。** 继续核对当前轮次、原会话归属及有效工作目录。用原会话文件名中的本地日期和线程 UUID，按[断点续写规则](resume-records.md#按真实事件定位续写)定位已有文档。

## 随记录保存的身份

在主记录及实际详情中保留同一组可核实的身份信息，包括宿主线程 UUID、规范化仓库根、首次有效工作目录、实际本地开启日，以及入口证据。入口证据保留宿主版本与事件来源、已核实的活跃轮次 ID、触发类型和实际用于核验归属的目录。恢复时保留原有会话身份，在本轮证据中标明恢复后的有效工作目录。保存结果以实际读回确认。

已验证 UUID 用作新会话的初始目录名，也用于标题改名后的定位。使用线程 UUID 与真实仓库根共同确认归属，按原开启日定位主记录及实际详情。复用前核对已存的线程、仓库根、首次工作目录与开启日。证据冲突时保留现有文件，停止对该会话的自动写入。满足恢复条件但尚未建档时，按原开启日定位，从恢复后的首条消息开始保存。[共用资料契约](storage-contract.md)

项目级 Hook 的字段取证使用 Linux 上的 Codex CLI 0.172.0 分页会话。
