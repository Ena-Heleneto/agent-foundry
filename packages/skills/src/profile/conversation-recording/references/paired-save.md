# 成对保存对话索引和详情

取得已核实的会话身份、原仓库、首次工作目录和本地开启日后，用宿主现有文件工具保存。依项目的本地资料位置解析真实资料根，默认使用业务仓库外的目录。创建目录或写文件前，核对真实资料根和目标所在位置。发现路径冲突、越出资料根或无法核对归属时，保留已有内容并说明缺口。[会话归属与身份](session-scope.md) · [共用资料契约](storage-contract.md)

## 确定本次保存范围

开始保存时，确定已经发生、符合记录范围且有真实定位的发言、工具活动和附件。按宿主轮次归组，在每轮内沿实际发生顺序保存，为每个事件保留真实标识或经核对的稳定来源位置。相同文字的不同事件分别保留。每轮在索引和详情各有一块，沿用同一安全锚点，例如宿主轮次为 UUID 时使用标题 `## turn-<轮次 UUID>`，并保留原始轮次标识。

将业务操作与记录维护分别调用。业务发言、业务工具、用户要求查阅记录及实际派发按原范围留存。仅为整理本次记录而产生的保存、复制、断点核对和读回调用属于记录维护。以调用用途和事件定位识别这些调用，即使业务读取与维护读回用的是同一个工具，或都访问资料区，也各按实际用途处理。

## 保存并确认详情与附件

按[会话写入协调](resume-records.md)在同一次持锁范围内核对原文件、保存并读回。

1. 以原开启日和已核实的会话基名定位 `records/YYYY-MM-DD/details/<会话>.md` 与同日的 `index/<会话>.md`。已有文档先核对身份并保留其他轮次和已确认内容。
2. 用文件工具将可取得的附件原件按字节复制到详情同级的 `attachments/<会话>/`，选择安全且可区分的文件名。从实际保存位置读回并与原件核对 SHA-256。详情里的附件链接使用相对路径，逐段对空格、非 ASCII 字符和 URL 保留字符做 UTF-8 百分号编码，保留 `/` 分隔符。沿链接解码得到的路径与摘要应和实际读回结果一致。
3. 在详情写入共用身份及本轮对应块。按实际顺序保存可取得的用户和助手原文、工具名称、完整可取得的参数和输出、工具工作目录，以及指向原件的相对路径与 SHA-256。参数保持原有结构和值。发言和文本输出各用独立的 Markdown 原文块，直接保留字符、空白和换行。选择与内容不冲突的围栏，注明原文是否以换行结束，读回时按原始行尾核对。只取得截断内容、引用线索或部分字节时，具体标记欠缺的字段或原件及原因。
4. 从实际详情文件读回，核对身份、轮次锚点、事件原值和顺序、附件相对路径及摘要。附件不可取得时，读回核对详情中的对应缺口。以实际读回的内容确认保存范围。

## 写索引并结束保存

详情核对通过后更新索引。为本轮写入内容要点、已观察的执行结果、实际改动文件和 `../details/<会话>.md#<轮次锚点>` 链接。改动文件按本轮证据填写，核实没有改动时写明无。再次读回索引并沿链接定位已确认的详情块，核对两份文档属于同一身份及轮次。

完成上述读回后结束本次保存，回到原任务。下一次保存只处理新的范围内业务事件，沿用对记录维护活动的识别结果。详情未能确认时暂缓更新对应索引块。索引未能确认时保留已确认的详情和附件，按[写入失败与重试](write-failures.md)指出具体缺口。[保存确认与失败恢复](storage-contract.md#保存确认与失败恢复)
