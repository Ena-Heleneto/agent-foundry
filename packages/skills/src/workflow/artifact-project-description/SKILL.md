# 项目交付描述

## 标准输入与写入边界

调用方提供源材料及其用途、目标文件、上下文标识与适用格式要求；需要兼容旧资料时同时提供候选旧路径。材料可以是本地文档、用户输入或已授权读取的工具结果，不要求特定目录结构或工作流工具。缺少必要材料/目标时先读取已有上下文并报告缺项，不凭某个工具的默认文件名猜测或写入。

先检查目标及调用方声明的旧候选：新旧内容不同则报告冲突并停止写入；目标存在优先读取目标，缺失才读取旧候选；不搬迁或覆盖旧资料。产物注明来源、适用任务/子任务、实际时间与调用场景；不适用标明，不编造标识。写后按目标仓库提供的格式要求检查，并读回确认；格式操作失败明确报告，不宣称完成。

## 结案与幂等

调用方必须提供已完成验收的结案依据、任务实际结果及剩余事项；阶段小结或设计方案不能当结案。缺证时报告未完成，不生成冒充结案的成果。

按“目标、范围、实际成果、后续事项”组织，逐项区分已交付、未完成及未验证，链接实际产物与证据，不把计划预测当成果。目标明确允许结案覆盖更新时才写入；同次结案重复调用沿用同一事实和生成时间，内容保持一致，不因时间戳重写制造差异。源事实实质变化并再次结案后才更新。
