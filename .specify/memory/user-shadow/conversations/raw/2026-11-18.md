````text
你的目标适合**在 `profile` 集合中拆成 3 个独立 skill**，每个都有自己的目录和 `SKILL.md`。

两种做法的区别是：

| 做法 | 适用情况 |
|---|---|
| 一个 skill 拆成多个文档 | 仍是同一种能力，只是内容较多，将细节放到 `references/` 按需读取 |
| 一个集合包含多个 skill | 职责、触发时机不同，需要分别发现、调用和验证 |

按我们讨论的职责，可以组织成这样，名称暂定：

```text
profile/
├── collection.config.ts
├── conversation-recording/
│   └── SKILL.md
├── conversation-analysis/
│   └── SKILL.md
└── shadow-profile/
    └── SKILL.md
```

三个 skill 分别负责落盘、分析、画像，集合配置声明这三项。每个 skill 内容较多时，仍可再拆附件文档。

**同属一个集合不代表自动依次执行**。“先确认原文已保存，再分析，再更新画像”的交接关系，需要在各自职责中明确。
````
