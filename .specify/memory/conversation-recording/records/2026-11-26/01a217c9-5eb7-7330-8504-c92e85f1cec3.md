我们一个一个处理， 1. 自定义 --outDir 产物不完整 是什么意思

---

<!-- foundry-message 回复 558 -->

### 主代理 · 回复

`--outDir` 是让构建把产物放到你指定的目录。比如：

```bash
pnpm --filter @foundry/skills run build --mode release --outDir /tmp/skills-release
```

预期 `/tmp/skills-release` 里既有安装脚本和 `curl/skills.tsv`，也有映射表列出的 8 份技能正文。**实际是安装脚本和映射表进了 `/tmp/skills-release`，8 份正文却全写到了默认的 `packages/skills/dist/skill/`。**

原因是 Vite 生成的文件遵循 `--outDir`，复制技能正文的插件还在用写死的 `dist/skill`。所以命令能报成功，但如果只拿 `/tmp/skills-release` 去打包，就会漏掉全部技能正文。用默认目录构建时，两部分恰好落在同一个目录，所以看不出这个问题。 [T008 实测记录](/home/by152/workspace/ena/agent-foundry/feature/init/specs/skills/003-skills-release-pipeline/implementation/T008.md:29)

什么，我没懂 ，什么原因导致的报错

### 主代理 · 回复

报错出在 `parse(frontmatter[1])` 这一行。它从 `SKILL.md` 的开头提取 YAML，再交给解析器。

这里有两层检查：

- `frontmatter` 有值，表示正则匹配到了内容。
- `frontmatter[1]` 是匹配结果里的第一个捕获组，也就是要解析的 YAML。TypeScript 把它当作一次数组下标读取，认为结果可能是 `string`，也可能是 `undefined`。

原来的代码只检查了第一层，就把 `frontmatter[1]` 传给了要求字符串的 `parse()`，于是 TypeScript 报错。这个文件之前没被常规类型检查覆盖，所以临时把它加进去时才看到报错。 [报错位置](/home/by152/workspace/ena/agent-foundry/feature/init/packages/skills/src/workflow/plugin/vite-plugin-speckit-mount/mount-script.ts:51)

改两处。先让 `frontmatter` 直接保存捕获到的 YAML 字符串，再把挂载插件加进常规类型检查。

1. **在 `mount-script.ts` 里**，把现有正则调用的结尾从 `.exec(content)` 改成 `.exec(content)?.[1]`（保留源码里的参数）。然后判断捕获值是否存在，再调用解析器：

   ```ts

     ? null
   ```

   这样 TypeScript 能确认传给 `parse()` 的是字符串。没有捕获时得到 `null`，捕获到空字符串时仍交给解析器处理。 [挂载脚本](/home/by152/workspace/ena/agent-foundry/feature/init/packages/skills/src/workflow/plugin/vite-plugin-speckit-mount/mount-script.ts:43)
