172:- **FR-001** 要分别提供记录、提炼和分析三个独立 Skill。每份 Skill 有符合通用规范的独立目录、`SKILL.md` 和必要文档资源，定义自身职责、触发条件、输入和产物。提炼和分析由 AI 按各自的 Skill 指令直接使用宿主已有工具执行。当前记录阶段以现有 Skill 目录为输入，同一次本地安装将整份 `conversation-recording` 复制到项目 `.agents/skills/`，并在 `.codex/hooks.json` 登记该副本中的三个入口。Codex 分别触发对应用户消息、工具完成和回复完成的三个 Hook。每个 Hook 由独立脚本处理对应事件，互不调用。各脚本共用宿主事件读取、会话校验和文件存储能力。
173:- **FR-002** 项目级记录安装后，用户通过 Codex 原生流程对本次安装的记录 Hook 确认一次并启用记录。同一项目的 Hook 定义和 Codex 信任状态保持不变时，后续普通启动无需再次确认。用户在本仓库根目录或子目录按日常方式运行 `codex` 并发送消息，无需手改配置、点名记录 Skill 或另行启动记录。每个符合条件的交互轮次都自动进入记录流程，包括模型未选用记录 Skill 且零模型工具调用的轮次。用户发出的第一条正常对话消息触发 FR-003 建档，后续轮次沿同一会话续写。纳入记录的用户发言须在对应业务动作前保存并读回原文。无业务动作时，在开始发送最终回复前完成用户原话的保存和读回。正常最终回复发送结束后，在当轮自动保存实际发出的回复全文并读回，内容与实发文本逐字一致，无需用户再发消息。主记录可以独立写入，已发生的过程按 FR-004 和 FR-005 随本轮推进陆续写入。写入失败、恢复及不可控中断、Git 提交停写分别按 FR-006、FR-007、FR-008 处理。若采用 Hook，须在其通过首期会话记录验收后移除由其接替的旧记录逻辑。
174:- **FR-003** 记录流程在实际保存时根据项目规则和已核实的会话位置选择或复核资料根。首次选址依次考虑项目自定义规则、Agent 工具的实际项目内资料目录、根据项目情况自选的项目内记录目录。主记录、各组详情文件和会话附件均纳入项目 Git 管理，随项目变更提交，并遵守[详情文件与附件](#详情文件与附件)中的提交边界。Git 忽略规则不得覆盖新写入的记录或附件。每个会话按实际开启的本地日期建一份主记录 `records/<开启日>/<会话ID>.md`，连续交互和正常恢复跨日均沿合规的原文件续写。文件顶部保存会话 ID、实际开启时间和首次工作目录，并保留资料根、选址依据和来源归属。并行会话各自保存。此次开发变更完成时，移除旧索引版生成的记录产物，建档和续写统一采用本版规则。
175:- **FR-004** 首个里程碑保存原始对话和可核实的操作经过。主记录采用[主记录样式](#主记录样式)，由用户发起的每个宿主轮次对应一个紧凑文档块。每组通过随块保存的宿主轮次 ID 定位，并显示该组第一条用户消息的本地日期。发起、同轮补充和最终回复按实际顺序保留原文，多行、空行、列表和代码块能够还原。简短过程写 AI 实际做了什么。本组已有实际详情，且详情文件保存后可打开时，才显示独立的「查看经过」链接。提炼用户特点和分析协作规则属于后续里程碑。
176:- **FR-005** 当组内有可留存的进度原话、可见推理摘要、工具活动或附件时，按[详情文件与附件](#详情文件与附件)写入一份独立文件，以会话 ID 和宿主轮次 ID 对应到主记录的组。工具回调先保存文本、宿主稍后提供同一结果的附件时，在原结果块补齐原件和链接，该结果仍只记录一次。主会话中可取得的子代理派发与回传按实际活动留存，包括提炼和分析的派发。仅为记录本身保存、复制附件、核对断点及读回确认而产生的内部工具活动不纳入待记录事件，避免递归自记录。
