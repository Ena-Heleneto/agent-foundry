## 目标与边界

证明 Vite 为每次构建提供正确的 mode，配置回调和插件钩子可读取该值，并可在同一 Node 进程连续构建时区分各次输入。默认构建应观察到 `production`；显式构建应准确得到 `development`、`release`、`production`。

不使用自定义环境变量，不在 Node 模块直接读取 `import.meta.env.MODE`。本任务只建立 T007 所需的 Vite mode 传递证据，不实施集合过滤，不改工作流或直接调用 Vite 的脚本。

## 方法

1. 在现有 distribution 测试中使用 Vite Node API 和隔离临时目录建立观察构建，配置一个仅记录解析后 `mode` 的最小临时插件。
2. 在同一进程依次构建：不指定 mode、`development`、`release`、显式 `production`。记录每轮回调及插件观察到的 mode，不复用前一次配置状态。
3. 使用完整技能包 Vite 配置再跑适用的最小隔离构建，确认配置回调中的 mode 可交给配置阶段创建的插件；运行期插件可从对应 Vite 环境取得当前 mode。不得据此宣称集合筛选已经实现。
4. 对每项记录输入、预期、stdout/实际观察、退出码及临时目录副作用；清理临时构建输出，留下可复用的隔离测试骨架。

## 验收信号

- 默认 `vite build` / Node API `build()` 的解析 mode 为 `production`。
- 三个显式 mode 与输入逐字一致；连续构建的观察顺序与输入顺序相同，无前次值残留。
- 验证依赖现有 Vite，无新增依赖、网络、工作流或直接调用脚本修改。
- 通过只证明 Vite mode 可在所需配置/插件路径取得；集合过滤与消费者一致性仍由 T007/T008 验收。

## 执行顺序

1. 复核当前测试 harness 的隔离构建方式及 Vite 版本。
2. 添加 mode 观察夹具，运行默认和三个显式 mode 的同进程序列。
3. 检查构建返回值、记录证据并保存测试骨架；通过后再进入 T007。

# 改动符号 JSDoc 注释

## 核心规则

每次编辑 TypeScript、JavaScript、Vue 或相关前端代码时，凡是本次新增的声明，或本次修改了行为、签名、类型、初始值、业务含义的声明，都必须在声明正上方添加或保留准确的多行 JSDoc 注释。

需要覆盖的改动符号包括：

- 函数、方法、构造函数、赋值给标识符的回调函数、组合式函数、hook、事件处理函数和计算辅助函数。
- 变量、常量、ref、reactive 状态、类字段，以及新增或语义变化的解构别名。对象字面量属性、interface/type 属性、枚举成员等内部成员不单独挂注释，按下方执行流程第 5 条收拢到外层声明。
- 类型、接口、枚举、类型别名、类、模块、导出对象和 schema 定义。

不要为了满足规则去给无关的旧代码批量补注释，除非它们属于同一个被修改声明块且不补会造成风格或含义不一致。

## 执行流程

1. 编辑前，先识别这次可能会新增或修改的声明。
2. 编辑时，在每个改动声明的正上方放置多行 JSDoc 块，格式必须是：`/**` 开始，中间每行以 `*` 开头，` */` 结束。
3. JSDoc 块至少包含一句职责说明；函数、方法、回调、复杂类型或有约束的声明，应按需添加 `@param`、`@returns`、`@template`、`@property`、`@throws` 等标签。
4. 不要使用单行 `/** ... */`、普通 `//`、普通 `/* ... */`、Python docstring、Go 导出注释等格式替代 JSDoc。
5. **不在声明内部写注释**：对象字面量、interface/type 的属性、枚举成员、泛型参数等声明内部（如属性上方）不放 JSDoc；属性语义收拢到外层声明（接口、类型别名、常量、函数）的 JSDoc 块里统一描述。JSDoc 只挂在外层声明正上方。
6. 注释要简短、事实准确，说明符号的职责、含义或约束，不要写“这是新增/修改的函数”。
7. 完成编辑后检查 diff，确认每个改动声明上方都有准确的多行 JSDoc 注释。
8. 使用中文写注释

## 注释质量

优先描述意图、约束或业务含义。

推荐：

```ts
/**
 * 将承运商对账原始行转换为表格可渲染的数据。
 *
 * @returns 标准化后的对账行集合。
 */
const reconciliationRows = computed(() => normalizeRows(rawRows.value))

/**
 * 提交选中的订单发起仓库取消流程。
 *
 * @param orderIds 需要取消的订单 ID 列表。
 * @returns 取消流程提交完成后的 Promise。
 */
function submitWarehouseCancel(orderIds: string[]) {
  // ...
  return Promise.resolve()
}
```

避免：

```ts

function submitWarehouseCancel() {}

/** 新变量。 */
const value = 1
```

## 边界情况

- 如果匿名内联回调无法自然放置直接注释，且该回调有独立业务含义，优先提取为带多行 JSDoc 注释的命名常量。
- 如果声明已经有准确的多行 JSDoc 注释，只在本次改动导致注释过期时更新它。
- 即使项目平时不给简单局部变量写 JSDoc 注释，只要用户明确要求本次改动的变量要有注释，就按本技能执行。
- 不要用单行 JSDoc 或普通行注释凑数；格式不符合多行 JSDoc 时视为未完成。
- 对生成文件、压缩文件、lockfile、snapshot 或机器维护的产物，不主动添加手写 JSDoc 注释，除非用户明确要求修改这些文件并补注释。

## 验证清单

结束前检查最终 diff，并确认：

- 每个新增声明的正上方都有多行 JSDoc 注释。
- 每个修改了行为、签名、类型、初始值或业务含义的声明，都有或保留了准确的多行 JSDoc 注释。
- 注释简洁、有用，并符合附近代码的语言和风格。
- 改动声明的内部（对象字面量、interface/type 属性、枚举成员、泛型参数上方）没有新增 JSDoc 或行注释，属性语义已收拢到外层声明的 JSDoc 块。
- 没有对无关旧代码做大范围注释补充或格式扰动。

/**
 * 挂载材料所需的技能身份、源目录和集合声明。
 */
interface MountSkill {
  name: string
  source: string
  config: CollectionSkillOption

/**
 * 将文本作为单个 Shell 字面量引用，防止提示词中的引号和命令替换被执行。
 *
 * @param value 要嵌入的原始文本。
 * @returns Bash 单引号字面量。
 */
function quoteShell(value: string): string {
  return `'${value.replaceAll('\'', '\'\\\'\'')}'`
}

/**
 * 读取源技能描述并生成引用目标项目已安装技能的命令文件。
 *
 * @param skill 含 command 声明的技能，未声明时返回空值。
 * @returns 官方命令元数据、文件内容及目标项目内的技能路径。
 */
async function createCommand(skill: MountSkill) {
  if (skill.config.command === undefined)
    return
  /**
   * 命令名同时决定扩展 ID 和文件名，只接受官方规范形式。
   */
  const match = /^speckit\.([a-z0-9-]+)\.([a-z0-9-]+)$/u.exec(skill.config.command)
  if (!match)
    throw new Error(`非法命令名称：${skill.config.command}`)
  /**
   * 正文只在构建期读取，不把源机器路径带到运行项目。
   */
  const body = await readFile(join(skill.source, 'SKILL.md'), 'utf8')
  /**
   * 支持 LF 和 CRLF frontmatter，不将技能业务复制到命令正文。
   */
  const frontmatter = /^---\r?\n([\s\S]*?)\r?\n---(?:\r?\n|$)/u.exec(body)
  /**
   * 官方命令描述必须来自源元数据，缺失或空值直接拒绝。
   */
  const metadata = frontmatter ? parse(frontmatter[1]) as { description?: unknown } | null : null
  if (typeof metadata?.description !== 'string' || !metadata.description.trim())
    throw new Error(`技能 ${skill.name} 缺少有效 description`)
  /**
   * 当前支持的项目级 Codex 安装路径，运行前核对该引用实际存在。
   */
  const skillFile = `.agents/skills/${skill.name}/SKILL.md`
  return {
    extensionId: match[1],
    name: skill.config.command,
    file: `commands/${match[2]}.md`,
    description: metadata.description,
    skillFile,
    content: `---\n${stringify({ description: metadata.description })}---\n\n完整读取项目内的 ${skillFile}，遵循该技能及其所需附件处理本次请求。\n\n本入口只调用已安装技能一次，不复制另一套业务；若本次调用已执行该技能则沿用结果，源技能不得再次调用本入口。\n\n用户输入：$ARGUMENTS\n`,
  }
}
