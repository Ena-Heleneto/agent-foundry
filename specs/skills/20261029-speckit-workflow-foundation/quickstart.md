连续至少3轮不点名Skill，覆盖普通问答、讨论、纠正或确认、commentary及普通final。最后一轮发出普通最终回复后不再输入，独立核对它已自动落盘；控制组不可调用逐条read_thread/模型保存。记录源完成、接收、读回实际时点；原文覆盖/自动触发率100%，逐条模型保存次数0。五条旧探针及问答控件final_answer不抵扣普通final或末轮。

分别在隔离输入中给出明确偏好、持续目标、用户纠正、手动分析要求；核对主代理先snapshot确认原文已存，再实际派发分析子代理。另用普通过程对话、仅引用Agent建议或他人偏好作反例。记录实际识别结果、漏触发/误触发、子代理启动身份、消费的已存source_refs及产物，不能用手工指定正确类别或文件存在冒认自动触发。一次任务选择即使有分析也不能固化为永久特征。

分析期间继续完成正常任务，再输入明确纠正；原文继续自动保存，主代理立即按当前纠正行事，不等待新profile。至少1次主动查询可核对记录/分析/入口分别覆盖、缺口和实际延迟；不采用1分钟/5分钟超时门槛，记录真实耗时，不因无提示认定成功。

对分析执行注入可恢复的一次失败后成功、连续两次失败及不可恢复失败：同一真实trigger_ref绑定的一轮自动重试最多1次，连续失败停止本轮，新正常触发或用户新的手动要求才续接；成功覆盖不重复形成。原文仍记录，故障在当前会话下一次可见反馈说明。分析已存/入口失败的分支只恢复未完成发布，不再生成重复结论。

5. 额外实际尝试缺 plan 的有/无描述两支，均不得新建正式方案。使用同一目标依赖两个既有 Task、另有无关 Task 的材料作模式对照：独立 Increment 从指定 Task 切入时，可说明必要关联并调整同一目标内获授权的规划，保留各 Task 的目标/验收及状态，不能误限为只读单 Task；Tutor 缺 MVU 时只在指定 Task 内补齐，其他 Task 仅作依赖引用，范围不足须说明，不能因复用 Increment 而跨 Task 写入。两种模式都不得纳入无关 Task、实施业务或复制工程状态；测试部分保存失败时使用隔离项目可恢复的写入失败条件，禁止修改真实项目权限绕过限制。普通项目不创建 .specify。
6. 同一分析能力尚未交付时核对“规划已保存、分析未完成”的真实输出，不能调用另一分析冒充；交付后由 T064/T086 补齐描述依据的完整消费，T076 再收集真实用户规划/反馈。T072 负责实际工作区同版刷新，隔离入口测试不抵扣它。

每组证据应含来源版本/摘要、描述原文或无描述标识、项目输入、执行动作、实际输出/差异、原任务保护、结果和未测范围。对照必须可证伪；旧数据、模拟用户发言和 AI 示例不得填成真实用户验收。
