# 契约：通用业务节点实施顺序

日期：2026-11-09。来源：[规格 FR-087～091、SC-034～036](../spec.md)、[研究 R42～R44](../research.md#r42通用业务节点规则的独立交付2026-11-09)、[记录模型](../data-model.md)。本文件定义独立 Skill 及其消费者的目标行为，实际交付和限制见 [验收记录](../analysis/acceptance/tv-07-business-delivery.md)，不以契约本身充当通过证据。

## 交付与调用

技能名为 business-node-delivery，源码位于 packages/skills/src/skills/coding/business-node-delivery/SKILL.md，目录名与 frontmatter name 一致。通过目标 agent 的技能发现/加载能力单独调用；支持 `$技能名` 的环境可使用 `$business-node-delivery` 并附当前节点及规划/实施意图。输入使用自然语言，无必填参数表、特殊 DSL 或新增子命令。

该规则归 coding 分类，可独立安装，由宿主根据自身 description 和当前业务请求自然发现；也支持显式点名。不向 Spec Kit 模式正文添加本技能链接、显式调用或安装依赖。模式是否安装和是否存在正式 Task/MVU 均不是发现前提；模式可独立工作，缺本技能不增加其启动前置。不增加第五 modes、hooks、脚本、节点身份或第二份状态。

| 输入               | 读取和约束                                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| 业务目标与当前节点 | 要达成的局部结果、涉及接口/代码范围及观察方法；上下文唯一时续接，含糊时仅澄清影响当前推进的信息                      |
| 原任务与闭环       | 使用已有任务及业务关系；Spec Kit 中读有效 MVU/Task，非 Spec Kit 用其已有材料，不要求创建 .specify、mvu.md 或 Task ID |
| 实现与依赖证据     | 相关数据定义、后端、接口、页面、共享前置和已验证结果；实际读取，不把路径存在或用户熟悉当验证通过                     |
| 当前意图及授权     | 规划、讨论、检查或已有范围内实施；沿用目标项目有效规范、分工及授权，不靠本技能扩大范围                               |

输出落在原任务步骤或项目已有等价记录：当前节点/预期结果、适用步骤及顺序理由、复用/不适用依据、具体依赖、验证输入/预期/实际结果、未测范围、受影响下游及下一动作。相关信息可用简短说明与引用表达，不对每个微小动作复制八栏目，不另存一套工程进度。

缺少当前目标、必要依赖或有效授权时报告具体缺项及影响；仅停止依赖该信息的动作，允许已授权的只读核查和无关工作。不为能执行而臆造需求、验证结果或用户确认。

## 粒度与顺序

MVU 保留业务结果、关键节点关系和整体验收；一次推进可只选其中很小的业务节点或单个接口。节点必须能说明其对原目标的贡献及验证方法，但不必每次形成整个业务闭环。其工程步骤沿用原 Task，节点通过不代表整个 Task 或 MVU 通过。

默认在当前节点范围安排“数据库 → 后端业务 → 验证逻辑 → 前端页面”的适用部分：

1. 先明确节点结果、作用范围和验收信号，核对必要技术假设及真实前置。
2. 数据设计/实现已有时检查适用性并复用；无数据职责时说明不适用，不为了层次完整而新增存储。数据操作仍受项目授权约束。
3. 在有效数据与其他前置上实现当前范围的后端业务/接口；已有可用部分直接复用，不重做无关模块。
4. 按节点职责选择验证方式，满足本节点及必要前置的条件后才能推进依赖结果的步骤。
5. 正式页面按其实际依赖接入；若需要多个接口，逐个完成并验证后汇合，不强制每个接口制作页面。接入后仍验证该页面承担的业务交互，并按所属 MVU 的原业务信号验收。

存在有依据的顺序调整时，写明依赖、调整原因、当前能观察什么以及尚不能宣称什么；例如只读原型不能冒充真实接口业务已验收。共享结果引用同一实现和证据，不为展示顺序复制工程条目。允许先完成同一页面所需接口，不将此扩为跨业务批量实现所有后端后才反馈。

## 验证与失败

验证方式按职责与风险选择自动化测试、接口请求或临时测试页；不统一强制测试页或自动化测试。每个节点覆盖正常流程及适用的异常、权限边界，输入、预期结果、实际结果和证据应能被再次核对。必要技术前置和目标项目已有工程检查仍须满足。

规划阶段只写验证条件、方法和依赖，不填写未来通过结果；执行阶段根据实际返回判断。单有 lint/编译、关键词或页面能打开，不能代替节点业务验证。既有证据须核对当前实现、输入和覆盖范围，变化推翻旧结果时保留旧证据并记录复验原因。

失败、未执行或证据不足均不能当通过：记录实际问题、依赖该结果的步骤及恢复条件；依赖页面或业务逻辑停止，无关工作按自身条件继续。修复后复验通过才续接，不将“已修复代码”当复验结果。节点验证、工程 Task 完成、MVU 通过、学习掌握及真实用户反馈分别判断。

## 自然发现与加载后职责

| 上下文    | 自然发现后适用的职责边界                                                          |
| --------- | --------------------------------------------------------------------------------- |
| Increment | 已明确 MVU 结果、展开 Task 步骤时适用；只安排路径与验证条件，不因生成步骤进入实施 |
| Direct    | 核对用户当前方向/依赖及推进前适用；保留用户选择，必要调序说明依据，不绕过验证     |
| Tutor     | 细化原 Task 的工程步骤与用户实践时适用；用户主写、单 Task 边界、真实掌握判断保持  |
| Pair      | 讨论当前工程步骤及审查验证时适用；保留默认只读和局部授权，不扩大代写范围          |

宿主从已安装技能目录读取本技能 description，匹配业务规划、业务接口、页面接入及恢复开发意图后加载完整正文；用户无须报技能名或模式名。仅文案、格式、视觉或无业务实现路径的解释请求不匹配。未安装时不伪称已应用；显式请求本技能却缺来源时报告缺项，不自动安装或复制回退，也不因技能缺席冻结原模式。

发现匹配不等于可以实施：加载后仍须满足目标项目和当前模式的治理、材料、范围及授权。尚无正式任务的业务目标可匹配，但只做获准的规划或核查，不自动创建正式任务。Pair 旧治理迁移归原 T065，T093 的 Pair 实际职责核查仍依赖它；该局部条件不阻止独立触发识别。
