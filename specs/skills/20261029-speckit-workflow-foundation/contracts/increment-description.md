# 契约：Increment 的可选规划描述

日期：2026-11-10。需求：[FR-082～086](../spec.md)、[已确认输入](../requirements/prompts/2026-11-08-increment-planning-description.md)。本文件定义待实现行为，不新增输入解析服务或任务状态系统。

## 输入和来源

自然语言与显式 `$speckit-modes-increment [规划描述]` 共用同一正式入口，Spec通过明确路径或原唯一上下文定位；当前工作流暂限Spec Kit，task-increment仅作为维护/挂载来源。描述是自由文本，不要求字段顺序、特殊标记或固定技术层。去掉定位信息后的描述缺失/空白采用原分支；含义不明的内容不能默默当无描述。入口发现不改变无plan、有plan无tasks、有plan/tasks三类材料边界；不接受Task定位参数，已有Task只读作现状和职责关联。

当前明确输入限定意图；已确认 spec 与真实代码约束仍须核对。只在已有授权覆盖范围内保存普通细化。新业务范围、权限或验收变化先说明影响并确认，已明确授权不重复询问。描述中的业务顺序、验收衔接和工程步骤偏好分开理解，不互相替代。

## 输出职责

| 内容           | 落点和判定                                                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 用户原意与来源 | 复用项目已有需求/讨论位置并在本轮规划中引用，无约定时在现有方案当前范围段说明，不强建目录                                    |
| 项目事实       | 指向已有需求、代码、Task 或证据；仅发现路径不等于实际读过                                                                    |
| 补全与调整     | mvu 的相关短段或 plan 的理由说明，写出依据；重要歧义保留待确认                                                               |
| 最终闭环       | 同级 mvu.md，状态＋依据及四项说明，不以技术层作业务结果                                                                      |
| 任务与步骤     | tasks.md 原Task的简洁目标/必要边界/依赖/验收及唯一checkbox，详细方案开工前另存，先复用已存在工作再新增实际缺口，保留完成事实 |
| 本轮结果       | 区分规划保存、未同步项、分析刷新和下一步；禁止因生成材料进入实施                                                             |

## 操作顺序

先检查 plan 和Spec定位 → 读取本轮描述/无描述分支与现有材料 → 核对业务结果、遗漏、冲突和技术前置 → 仅对重要未知澄清 → 形成小 MVU、顺序与验收 → 复用或生成 Task 并落实正文顺序 → 按上游到下游保存并读回 → 显式调用同一分析技能。缺 plan 不代建正式方案；必要描述缺口无法确定时只停受影响范围，不伪造完整规划。

用户例子“权限验收后记账、再日程”作为该次业务方向；每个模块可按实际职责拆小。闭环内“表→service→接口→测试页面→页面”按适用性和现有实现展开；不要求重做已有层、不为纯后端闭环凑页面、不以测试页面能打开代替业务验收。小闭环验收和用户显式的阶段衔接均保留，AI 不擅自取消已有门禁。

通用业务节点规则通过自身 description 由宿主按业务规划请求发现，Increment 正文不链接或显式调用该技能。匹配并加载后，可在已有 MVU 中细化原 Task 的小节点或接口、按页面依赖汇合，并保留只规划和原材料门槛。具体行为见[通用节点契约](business-node-delivery.md)；TV-07 区分触发识别和加载后行为，旧 TV-06 证据不抵扣新验证。

## 冲突、重复与失败

描述遗漏且有依据时补齐并解释；缺依据标假设；与已确认目标/验收冲突时列差异和继续条件，不能通过直接改 Task 偷换需求。已有步骤顺序限制或其他执行者写入时保持受影响范围，其他可确定内容继续。

重复同一描述先比实际文件，无实质变化不重复加任务；新描述影响先前安排时保留原依据和调整理由；无描述沿原推荐但仍读取有效已保存规划，不把“无描述”解释为清空历史。保存部分失败要报已写/未写并恢复，未成功读取前不推进依赖更新；分析能力缺失按原规则单列，不能冒充全面完成。

## 验收与实现边界

具体矩阵见 [TV-06](../quickstart.md#tv-06可选规划描述)，T087/T088/T089 分别承担最小候选、生产来源和实际交付；这里只定义契约。旧 task-increment 已有保护、迁移与分析逻辑复用，不新增 after_increment 或全局状态。三模式补全/消费研发和测试暂停；当前准备与Implement按原Task的有效方案和授权实施，规划不取得实施授权。
