以下目录是默认职责布局，不是穷尽文件清单；新材料按用途和阅读需要灵活扩展并更新必要导航，不新增文件注册系统、不批量迁移其他Spec。需求实质变化由相关工作流skill先保存原始输入，再维护简洁摘要，整理稿不得覆盖原文；此职责后续纳入工作流宪章，不写项目级规范。

知识片段、报告及三模式专项研发/验收本期暂停，旧资料和事实保留。历史正式学习报告归personal-hub `apps/personal-hub/content/blog/` 的既有草稿体系，本表学习目录仅存过程。当前工作流工具暂限Spec Kit，不维护其他任务工具的等价产物布局；独立coding规则仍沿其适用项目记录，不受本表强制目录约束。当前 Implement 准备与 Increment 的自然发现不改变产物既有hook、明确请求或内部复用触发条件。

## 综合分析输入与输出

artifact-spec-analysis 的输入由调用方显式给出最新原始输入/确认、spec、plan、同级 mvu.md 的有效详情、tasks、既有索引和必要证据。新详情读取及兼容迁移遵循 [MVU 契约](mvu.md)；分析不另存一份活动详情。缺少材料时说明具体缺项及影响；冲突引用指出来源，不靠旧聊天补成事实，不把未验证假设写成结论。

输出首先逐功能独立成块，用功能名称和简洁完整文字说明做什么，必要逻辑自然融入，不强制固定栏目或总表；需要时链接有效依据。原业务分析、业务流程图、技术分析、技术流程图、MVU里程碑与流转图保留适用职责，缺项/暂停/未验明确，不以分析代替验收。内容多时分文档并更新 README 导航，逐类关联需求、闭环、Task 和实际代码或计划位置；Mermaid 每图一事、术语配通俗说明，不生成第二份工程状态或互相冲突的图示副本。diagrams.md 负责技术图导航，可以链接分类分析，避免重复维护同一流程。

## 双触发与刷新

1. 分析正式维护源为 packages/skills/src/workflow/artifact-spec-analysis/SKILL.md；唯一 hook 声明位于同集合 collection.config.json 的 skill.artifact-spec-analysis.hook.after_tasks，沿现有集合约定保存逐事件参数，不重复 command/description，不交付逐技能 speckit-hooks.json。技能正文/必要附件和集合声明分别核对同版来源；正式脚本对集合配置的读取与完整接线由后续原注册任务承接，隔离临时 hooks-only 登记不代替实际安装器适配。
2. Increment 完成规划同步、格式检查及读回后，显式加载同一 artifact-spec-analysis 并传同样的材料与目标；不增加 after_increment、后台事件或第二个生成器。
3. 刷新前读原索引和最新材料，更新本次分析范围，保留已确认历史来源；没有变化的内容不靠时间戳制造差异。重复刷新不得重复创建闭环或任务；计划和 tasks 未完成更新时明确当前限制，不能分析成“最新任务已验收”。
4. 失败报告实际已写/未写及恢复办法，分析文件保存失败只阻断依赖分析结果的后续动作，不伪称跨文件原子回滚。

## 仓库画像

本仓库画像由项目协作规范独立维护，工作流宪章不复制该规则。仓库级 `.specify/memory/user-shadow/` 为唯一画像位置：conversations 日期文件保存每轮对话与工具摘要，conclusions 日期文件提炼有效结论，profile.md 综合当前理解。沿用 Rnn/Enn 锚点和来源链；回复前保存已发生内容，下一轮可补上一轮真实回复，不能预写未来回复/工具结果或虚构原话、精确时间。

每轮有摘要；有新结论才更新 conclusions，影响整体理解才更新 profile，保留纠正来源及适用情境。实施思路讨论中主动核对有效认识，区分用户习惯、思路与单Task决定；MVU主要读取当前画像，不为每次规划强造结论。记录多而理解不足须分别核查提炼、汇总、读取、应用、情境与失效，明确已证实原因和未核实部分。真实后续机会轻量抽查实际提问/取舍/纠正是否生效，无机会如实未验，不逐轮报告或评分、不用文件读写当效果通过。新会话、中断或画像变化时读当前描述，持续协作复用，不每轮重读全部历史。此机制是 agent 遵循约定，不声称有独立监听和全会话自动捕获；未知历史说明覆盖限制。凭据和生产连接串不得写入摘要，对外技能不得夹带本仓库个人资料或硬编码路径。

## 历史辅助产物

根目录issue/PR及其他既有资料保持原范围，不批量搬迁或因技能退役删除产物。本Spec业务图及任务逻辑图按单图增量方式维护：diagrams/business-flow.md沿用旧图有效流程并更新过期规则，diagrams/logic-flow.md按当前有效任务重建完整依赖并保留平台并行/阶段门禁语义，不另留根目录或归档旧图。旧基线及验收哈希仍代表当时记录；Review合同只作退役来源，不恢复双确认，旧六技能挂载删除按[registration.md](registration.md)处理。

当前尚生效的旧artifact hook仍遵循自己的新旧候选冲突与一次性规则；本轮只处理本Spec文件，不修改公共hook。两类图的有效部分合入当前目标后，根旧候选不再存在；其他Spec仍按自身候选判断。旧冲突记录按发生时事实保留，不重写为当时已通过，图更新不作为新综合分析已生成。

TV-04 的实际输入、动作、失败与恢复结果计划保存到 `analysis/acceptance/cleanup-validation.md`；当前真实收尾继续写入 T080 已规划的 `analysis/acceptance/revision-summary.md`。TV-04 已有实际记录，本次只引用其原范围；revision-summary.md 仍待 T080 真实执行后保存，不由本次 Plan 创建假结果。一般项目使用原 Task 与已有验收记录布局，不强制引入这些具体文件。

记录已处置对象的位置、依据、结果及实际验证；待核实对象记录位置、保留原因和后续处理条件。无清理项也记录核查范围及理由。记录由原 Task 引用，不复制正式 checkbox；清理完成不触发自动结案，artifact-project-description 仍按真实总体结案条件生成或更新。
