## Increment 一次规划

明确Spec和可选描述，按无plan、有plan无tasks、有plan/tasks三类材料路径处理。结合需求、已有方案、同级mvu、代码和证据形成可观察小业务结果，解释范围、顺序、依赖、暂缓与技术前置；无描述不强迫补填，已有Task仅作职责关联，不接受Task定位参数。

先MVU再轻量Task；既有ID、验收、完成事实及证据保护，必要时同步正文顺序和共享前置，不为凑技术层重做已有成果。mvu保留四项短说明及有依据五状态，plan一处文件级链接。保存读回后显式复用同一综合分析，无after_increment；规划不取得实施授权。

本期分别核对规划、讨论认可、技术前置、工程结果、真实加载/行为、分发消费、阶段批准与最终结案。三暂停模式不生成或补测，也不记通过。自然语言发现不等于全文读取，hook登记不等于实际停止，既有完成任务不因换格式重开。

## Direct 一轮协作

**暂停参考**：本节及以下Tutor资料不参与当前研发、测试或结案。

读取用户当前想法与原 Task，讨论并独立核对依赖、范围及验收；允许不按 tasks 列表顺序推进。按实际分工实施/验证，把实际改动映射回原 Task 步骤、证据与进度，记录思路、调整理由、确认/待定及下一步。用户选择与必要前置冲突时解释影响并讨论路径，不为了跟随顺序跳过验证。范围内沿用有效授权，局部反馈不自动成为全局需求。

中断恢复核对原记录和实际代码，不重复实施或建立独立子任务。工程交付先核验内容、入口与独立材料分支；真实 Direct 行为由后续基础业务 Spec 承接，当前样本未创建不得报告通过。

## Tutor 一轮学习

从 mvu.md 沿用已有 MVU，兼容尚未迁移的原 plan 详情，或按单 Task 边界补齐；只了解当前步所需基础，解释概念和理由，提供提示及必要示例。用户编写主要代码，AI 按真实实现反馈、纠错和验证；局部代写以当次请求为界，完成后恢复原默认分工。AI 示例、自动测试或模拟发言不能作为用户掌握证据。

有价值的真实学习形成短片段：问题、关键解释、关联代码、理解或待巩固点；普通进度不强造知识。过程资料放 learning/<Task ID>/，由原 Task 引用。暂停、恢复或切模式续用原 Task；工程、学习和报告结果分别记录。

Task 结束后与用户基于片段共同整理学习报告。读 personal-hub 当前 schema 和既有文章，共同形成具体稿件与目标后保存到 `apps/personal-hub/content/blog/`，初始 `status: draft`；复用已有稿件，不恢复 Review 双确认，不自动发布，不用工程完成推导报告或学习完成。正式文章名在共同写作时确定，不提前选一篇 published 文章覆盖。
