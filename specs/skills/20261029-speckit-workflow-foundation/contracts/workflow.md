# 契约：任务定位、业务闭环与保存续接

更新：2026-11-10。本期为 Implement/Increment；三模式定义只作暂停参考。来源：[规格](../spec.md)、[模型](../data-model.md)、[计划](../plan.md)、[MVU契约](mvu.md)。当前工作流宪章已正式修订为7.0.0，工作流工具暂限Spec Kit；既有工程按证据覆盖范围复用，新入口发现及完整消费仍待对应任务核验，本契约不建立另一套治理。独立coding规则的普通项目使用不受此范围收敛影响。

## 上下文解析

1. 用户明确的项目/Spec 优先；否则采用当前唯一上下文或 .specify/feature.json。Task 以所属 Spec + 原 Task ID 定位，不能只凭多个 Spec 中都存在的 T001 猜归属。
2. 指针失效时说明原因并在现有材料检索；唯一匹配可说明依据后续接，多个候选只补问必要定位信息，不改指针掩盖问题、不创建替代任务。
3. 实施类请求由原生 Implement 和同一共同准备消费 spec、plan、mvu.md（尚未迁移时兼容原详情）、轻量 tasks、原 Task 方案、相关代码及项目规范和证据。缺正式 Task 或必要材料先报告；没有有效认可方案先讨论，不写业务代码。
4. Increment 的材料分支按下一节处理；它有 plan 无 tasks 时生成任务是明确职责，不等于实施准备能自动补建任务后直接实现。
5. 自然语言实施与显式 Implement 完整消费同一准备能力；自然语言规划与显式 Increment 消费同一规划入口。普通讨论不自动实施，三模式不参与本期进入/切换测试。缺失或过期能力报告修复路径，不旁路来源冒充加载；见[准备契约](implementation-preparation.md)和[注册契约](registration.md)。
6. 未初始化Spec Kit时报告当前不支持该工作流上下文，不新建.specify、不回退其他任务系统或转换任务身份。仅安装来源或显式no-mount可以保留来源安装事实，但不声称工作流已就绪。分发不携带Foundry个人画像或固定仓库路径。

## Increment 材料契约

可选描述不改变下列材料前置；有描述时按[描述契约](increment-description.md)先核对用户方向、项目事实、补全与重要冲突，再形成 MVU 和 Task。无描述保留原推荐；Increment不接受Task定位参数，已有Task仅作现状与职责关联。

| 输入                          | 结果                                                                                          | 写入边界                                                                  |
| ----------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 没有 plan，包括存在孤立 tasks | 提示先完成规划并列缺项                                                                        | 不凭孤立 tasks 假造已完成方案或启动实现                                   |
| 有 plan、没有 tasks           | 详情写入同级 mvu.md，plan 留文件级引用及总体推荐顺序，再生成符合项目格式的 tasks 并补职责关联 | 承接当次 tasks 生成职责；保留实际材料与来源，不生成独立子任务             |
| 有 plan/tasks                 | 核对实现/证据后调整闭环、任务顺序与依赖                                                       | 原 Task ID、已完成事实与证据保留；新工作使用未占用 ID，失效做法标替代关系 |

每条采用 [MVU 契约](mvu.md) 的四项短说明，必要业务意义、合适范围、顺序理由、技术前置及暂缓/调整条件在相关段落交代或引用。用户思路依据不足时先推荐并说明理由，不虚构画像。同步规划后显式复用 [综合分析契约](artifacts.md)，不引入 after_increment。

## Tutor 补齐契约

**暂停参考**：下文保留原定义，不作为本期研发、测试或结案要求。当前 Implement 以[准备契约](implementation-preparation.md)为准。

先读取 mvu.md；尚未迁移的 plan 详情按 MVU 契约兼容，已有 MVU 沿用并拓展原 Task；有 plan/Task 无 MVU 时复用 Increment 规则，只覆盖指定 Task 的既有目标、范围、验收，其他 Task 仅作为依赖引用。范围无法形成业务结果时说明局限与前置，不扩围、不以技术联通冒充业务完成。缺 plan 先提示规划。

Task 的八栏目与整体工程交付保留；细步骤在改动内容中内联目的、位置、具体做法、前置和可观察结果，再加必要基础、讲解、用户实践、反馈与掌握验证。不新建独立编号、目录或状态。

## 技术风险与推进

先主动扫描四类风险并核对适用证据；必要技术验证成为关联业务步骤前置。验证失败记录真实结果、阻止依赖下游并调整方案，无关工作不被无理由冻结；成功验证骨架继续增量填充，业务完成仍须满足业务验收。用户熟悉技术、偏好某方案或画像描述均不是技术证据。

做法与实际代码不符、目标/范围/验收变化时依项目治理记录偏差并确认；正常范围内的持续授权不逐步重复询问。发布、部署、数据库、外部变更仍须明确授权。

## 保存和恢复

读取当前文件与证据 → 完成当前范围动作/核对 → 先保存 mvu 详情再更新 plan 文件级引用，串行保存本次授权的 Task 或知识资料 → 检查链接和覆盖 → 格式检查及读回 → 更新有证据的结果和下一步。多文件失败不保证原子回滚，明确已写/未写、影响和恢复办法；成功读回前不推进依赖该记录的新步骤或标完成。

重复请求、切换模式或中断先读原 Task、plan/MVU 与实际文件，识别已完成动作，续做未完成部分；当前思路、分工、已有授权、待定和下一步可恢复，不依赖聊天记忆覆盖文件事实。学习结果不被工程通过覆盖，工程进度不复制到学习资料或分析索引。

## 历史兼容

原子任务记录只有实际存在才衔接，核对原要求与验收覆盖、链接和保存后，把仍有效未完成做法写回原 Task 并保留来源；历史完成事实不改写。本仓库两份目标 Spec 当前无独立子任务目录，不建立空目录或伪造迁移证据。

## 任务清单的末尾清理契约

本节映射FR-075～076；当前7.0.0 VII继续保留清理要求，原T081/T082/T054证据保留当时范围。原生任务生成、普通对话更新与Increment读取同一Spec Kit工作流治理，不在技能中复制规则或注入本仓库规范；其他任务工具的兼容暂不维护。

| 输入或触发                                    | 预期结果                                                                          | 保护边界                                                         |
| --------------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 生成/更新清单，无等价未完成收尾任务           | 扫描包括历史在内的 ID，创建轻量清理任务，详细方案开工前讨论，放在有效执行序列末尾 | 未实施任务保持未完成；只有已完成旧收尾时也不重开旧身份           |
| 已有等价未完成末尾收尾任务                    | 复用原 ID、原目标和验收，在原任务验收及其适用方案补清理对象、依据及检查           | 不重复新建；综合收尾原有其他结案条件和依赖继续有效               |
| 清理用途明确的局部代码/文档/注释等            | 按本次范围和依据只处置该对象，保存实际差异、验证和引用核查                        | 单次搜索无命中不能证明可删；有效同文件内容保留，不扩为全仓扫除   |
| 对象用途无法确认                              | 保留原内容，记录准确位置、原因及后续处理条件                                      | 其余清理与必要检查通过可完成清理部分，不自动完成整体 Task 或需求 |
| 核对后无须清理                                | 保存核查范围、保留依据与无需处置结论                                              | 零无故变动，不为产生清理成果而删除受保护资料                     |
| 保存/验证失败、引用受损或已确认应清理项未完成 | 报告已写/未写和影响，修复后重读续接                                               | 停止受影响的完成更新，不声称跨文件原子回滚，不冻结无关工作       |

执行顺序为治理同步 → TV-04 → 原实现与必要验证完成后的实际清理 → 原总体结案核对。TV-04 的成功材料保留复用；工作流验收遵循宪章 IV，实际代码改动按项目工程规范跑所属 workspace 的最低检查。正式映射为 [T081 治理](../tasks.md#t081) → [T082 TV-04](../tasks.md#t082)，T082 同时依赖 T052，并作为 T053/T054 与 T080 的显式前置；实际收尾复用 T080，原结案条件保留。本契约不维护工程状态，不改变已完成 T050～T052 的事实。
