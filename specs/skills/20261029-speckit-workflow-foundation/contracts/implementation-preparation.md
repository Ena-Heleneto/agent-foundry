# 契约：单 Task 实施准备与确认方案

日期：2026-11-10。来源：[当前规格](../spec.md)、[计划](../plan.md)、[研究 R51](../research.md#r51共同条件由宪章承接hook-提前进入准备)。这是设计契约；工作流治理已独立正式修订为7.0.0，生产skill、hook及真实行为仍待实施验证。

## 调用与前置

来源为 packages/skills/src/skills/workflow/implementation-preparation/，SKILL.md 与 speckit-hooks.json 同目录交付。自然语言明确要求实施/继续原 Task 可发现此能力，显式 Implement 的 before_implement 也完整消费同一正文；普通讨论、规划请求不自动启动实施。工作流暂限已初始化 Spec Kit 项目，不自动创建 .specify 或回退其他任务工具。

输入是明确项目、Spec、原 Task 或当前拟实施任务范围，以及有效需求、plan、同级 mvu、轻量 tasks、相关代码/规范、已有方案和证据。用户定位优先，唯一上下文可复用，多候选先只澄清定位；原 ID 必须连同所属 Spec 校验。外部技能只读目标项目既有治理与记录约定，不导入本仓库个人资料。

## 每个 Task 的开工条件

准备前实际读取所需材料，核对必要技术前置和有效授权。没有有效认可方案时只讨论，不写业务代码；用户可先给思路，AI 也可基于真实项目提议，经真实讨论认可后形成方案。文件自称已确认、AI 自评或模拟回复不构成用户认可。

每个实际进入实施的 Task 都必须有适用、成功保存且读回的认可方案。批量、连续及并行请求逐项适用；A 的确认不放行 B，方案同时覆盖多任务时仍须各原 Task 一份文件并说明真实确认范围，不虚构额外批准。现有适用确认和授权直接复用，正常续做不重新审批。

宪章承接此共同条件；hook 缺失、禁用、解析失败、条件跳过或调用失败不豁免。原生模板可能继续运行，因此必须在真实宿主证明宪章被消费、准备被完整加载、受影响实施停止；不能宣称 hook 是程序锁。缺宪章、skill、有效材料或已知过期时报告实际影响与修复路径，未修复不把生成/安装成功当有效开工。

## 单 Task 方案与清单

默认文件为所属 Spec 的 implementation/<Task ID>.md，由原 tasks 条目链接；tasks 独占工程 checkbox。方案让读者理解目标、核心逻辑/数据关系、理由、推进顺序与验收，并保留用户方向、项目核对、真实认可及重要调整依据。信息按真实需要展开，不强制八栏目、全字段、字数或每个微小动作一个记录。

新增文件或写法先查存量实现和项目规范，优先复用，说明必要职责及当前落点。普通路径/命名/内部写法可在已确认逻辑内调整并同步依据；影响逻辑、职责、范围或验收的实质变化，先停受影响部分重议。讨论认可、技术验证、工程完成、业务验收和阶段批准分别判断。

## 保存、恢复与失败

保存认可方案→格式检查→读回→更新原任务引用；过程中逐项核对覆盖与现有文件。失败报告已写/未写、影响及恢复条件，停止依赖该保存的实施或完成更新，不承诺跨文件原子回滚。修复后重读原 Task、方案、最终代码和已确认修复，只补未完成事项；撤回方案不能按旧诊断再次实施。

无新事实时重复请求不产生第二份方案、独立子任务身份、state.json 或工程进度。历史未完成材料确实存在才衔接；已完成身份、原验收与证据保留，不为换格式重开旧任务。

## 交付和验收

T103验证隔离最小候选；T104完善生产来源后，沿已核实的官方安装/注册路线刷新同一隔离目标至正式维护源。记录所选CLI版本、实际入口/配置、正文及附件完整清单与内容摘要，实际完整读取后重验正常、无方案和逐Task边界；T105在此正式维护源官方安装的入口上验方案认可、保存及恢复。候选通过、仓库源码读取或旧安装结果均不能抵扣；来源/附件变化须重核受影响结果。此MVP隔离刷新不依赖T067/T068全量注册或T072真实项目迁移，生成文件仍只由官方路线更新。

2026-11-11用户明确[暂跳过构建相关内容](../requirements/raw/2026-11-11-defer-build-validation.md)，当前以[原任务暂跳过范围](../tasks.md#当前构建相关内容暂跳过2026-11-11)为准：构建交付、dist同版及构建产物安装/消费回归保留为待补验，不能写成已通过；T104整体未勾选不阻塞T105消费其已有证据的非构建职责。正式维护源的官方安装、完整读取及真实行为仍须实际证明；构建恢复后在原Task刷新构建产物并补验，不把本次源码安装结论迁移为构建通过。

before_implement 配置无非空 condition、optional:false，调用此 skill；来源配置与必要附件同版，官方 hooks-only 生成且保留原生 Implement。不新增模式命令、项目级规范路由或手改生成副本。逐 Task 条件由工作流契约持续约束，不假设官方存在循环内回调。

[TV-10](../quickstart.md#tv-10共同准备逐-task-与异常停止)分别验证自然语言发现、全文读取、进入准备、实际停止/放行及恢复。无方案、损坏配置、条件跳过、执行失败、保存失败、A有方案/B无方案和缺必要宪章均须留实际证据；漏触发或缺方案仍实施判失败，返回设计。未测、缺宿主或缺真实确认如实记录，不模拟用户认可。
