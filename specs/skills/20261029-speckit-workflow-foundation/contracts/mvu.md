# 契约：独立的小闭环详情

日期：2026-11-10。依据：FR-006/007/009/061/064/070/074/080/081、SC-030；来源为 [spec](../spec.md)、[模型](../data-model.md)、[研究 R35～R38](../research.md#r35)。以下约定描述目标交付，不表示技能/模板/原生消费已经实施。

## 文件分工

| 材料           | 内容与读取约定                                                                     |
| -------------- | ---------------------------------------------------------------------------------- |
| spec.md        | 需求、范围和验收；不复制工程进度                                                   |
| plan.md        | 总体方案、技术依赖、推荐顺序及一处 mvu.md 文件级链接；不保留逐条闭环索引或锚点跳转 |
| mvu.md         | 与 plan 同级，详情唯一活动入口；稳定标题下展示有依据的状态摘要及四项详情           |
| tasks.md       | 原 Task 身份、目标/范围/验收、必要依赖及唯一工程完成状态；详细方案独立保存         |
| 分析/学习/证据 | 引用上述来源；分析可解释闭环关系，不保存另一份活动详情或工程状态                   |

当前沿用MVU-001～009稳定定位，并为单Task讨论后实施新增MVU-010；三模式闭环仅保留暂停历史。已有工程事实不重开，新增职责的正式ID由后续Tasks补齐。本期挂载/自然发现只验Increment与共同准备，T095～T100的未完成范围须按新方案调整，不沿旧四模式清单执行。当前工作流暂限Spec Kit；独立coding规则仍沿普通项目材料，不注入本仓库路径。

## 每条四项说明

每条稳定标题下先写一行 `**状态**：未开始。**依据**：……`，再写下方四项详情。依据来自本闭环具体职责的任务/步骤记录与实际闭环证据；状态取未开始、进行中、待验收、已通过、受阻。仅生成规划不代表开始；有实际实施且仍可推进时进行中；实现具备而缺闭环验证时待验收；已通过须有覆盖验收信号的实际证据；当前必要下一步无法继续时受阻，并说明障碍及恢复条件，局部受阻不掩盖其他可推进职责。

任务/步骤、验收结果或阻塞条件变化，以及中断恢复时，在授权范围内刷新状态与依据；只读分析只报告不一致。全部关联 Task 完成不能代替闭环验收，当前闭环通过也不能反向完成覆盖范围更大的 Task。共享任务仅其在本闭环内的职责可作依据。摘要不新增工程身份、checkbox、状态服务或完成比例；原证据不因状态变化被覆写。此补充来自用户状态选择（原仓库私有记录，未迁移），不修改已完成 Task 的历史验收。

| 项             | 最小可读内容                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------- |
| 闭环结果       | 当前 Spec 内这次做成什么、谁能观察到；可只覆盖原 Task 的局部职责                               |
| 节点与关键逻辑 | 必要步骤如何串起、节点各做什么、决定闭环成立的顺序或判断；范围/前置/暂缓理由在需要处简述或引用 |
| 关联 Task      | 真实已有 ID 及各自职责；同一共享 Task 可被多闭环引用，不复制条目或状态                         |
| 验收信号       | 可观察的操作/输入及成功或关键失败结果，能判断局部闭环成立；工程完成仍以 Task 原验收为准        |

每条几小段，以能读懂为准，不规定字数、全分支图或完整功能设计，不复制八栏目。图示可选；必要技术假设及信号可链接 plan/quickstart，不为填写内容扩大原范围。尚未生成任务时明确“职责关联待任务生成补齐”，生成后补入真实 ID/职责，不虚构 ID 或空链接。

## 读取与材料分支

1. 明确 Spec 优先，先读 spec/plan，再明确读取同级 mvu.md、tasks 和相关证据。文件发现清单未列 mvu 不代表它不存在，消费者须按同级明确读取。
2. 有 plan 尚无 mvu 时读取旧详情，按本次范围增量迁移；不能误报缺方案或重建已有闭环。只有 mvu、没有 plan 时仍提示先规划，不绕过原前置。
3. mvu 已存在则复用；plan 若只是文件级导航不再重新导入为详情。存在两份冲突活动详情时说明来源和影响，先解决相关范围，不凭时间戳覆盖；无关任务按自身条件推进。
4. Tutor 沿用已有详情，缺闭环仅在单 Task 原范围补齐；独立 Increment 才可说明同一结果下必要关联范围。原生任务生成和分析必须实际消费同一来源，治理/模板约定足不足以传入文件由 TV-05 验证，不把直接修改 .agents 副本当交付。

## 保存、迁移和恢复

先核对写前材料和原 Task/证据 → 保存必要历史来源 → 写入或更新 mvu 详情并格式/读回 → 将 plan 收敛为一处文件级链接并迁移旧入站引用并格式/读回 → 更新本次授权的 Task/分析引用并逐份核验。保护原 ID、目标、范围、验收、checkbox、历史证据和阶段批准；不为迁移重开旧任务。当前已有 plan.history.md 保留其历史用途；本次或其他项目的 Increment 不自动创建整份方案快照。plan 不保留逐条闭环标题/锚点跳转，授权范围内旧引用改指 mvu，不能修改的引用明确报告位置与影响。

多文件保存不是原子事务。任一失败报告已写/未写、引用是否一致及恢复入口，停止依赖该结果的动作；不改权限、替换保护文件或用旧 plan 重新覆盖已保存详情。恢复先读实际现场，只补未完成部分；重复更新无重复闭环、Task 或无意义重排。同一分析能力只在规划同步、格式和读回完成后刷新。

## 描述与小闭环（2026-11-09）

可选描述会影响本次闭环的业务顺序、验收衔接及内部步骤，但先按业务结果判断闭环，再生成 Task。步骤链不是 MVU 分类表；同一模块可有多个小闭环，复用已有实现并说明必要调整。原意/事实/补全/假设与保存边界按[描述契约](increment-description.md)，无描述仍沿旧流程。TV-06 先验证此新增语义，旧 TV-02/05 不自动抵扣。

## MVU 内的小节点与通用顺序规则（2026-11-09）

MVU 的业务验收范围可以大于一次实施范围。business-node-delivery 在既有闭环内按原 Task 选取小节点或接口，组织适用的数据、后端、逻辑验证与页面步骤；不为一次推进重新划分 MVU、不分配节点身份或工程状态。多个接口按同一页面的实际依赖分别验证后汇合，节点或接口通过不自动改变 MVU 的业务结论，也不反向完成整个 Task。

四项闭环详情的角色保持，具体节点顺序及证据归原 Task 步骤；必要依赖与对业务结果的贡献可在节点说明中简述或引用。规则接口与缺项处理见[通用节点契约](business-node-delivery.md)，其新行为由 TV-07 单独验证，既有 TV-06/05 结果不追溯扩大。非 Spec Kit 使用自己的目标和任务材料，不要求新建 MVU 文件。

## 本期轻量输入与实施边界

Increment不接受Task定位参数，Task只是现状和职责映射。规划生成轻量清单，不预先内联全部详细步骤；每个Task开工前由共同准备形成implementation/<Task ID>.md的适用认可方案。MVU四项短说明和五状态继续按自身业务证据更新，不从方案存在或任务勾选数推定通过。三模式的旧单Task分支与跨模式测试本期暂停。
