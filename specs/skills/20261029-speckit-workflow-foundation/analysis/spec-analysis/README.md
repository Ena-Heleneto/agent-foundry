## 开工前先共同形成实现思路

用户要求实施某个原 Task 时，先核对该 Task、当前需求、plan、同级 mvu、实际代码、项目约定及既有方案。已经有适用的真实认可就复用；没有时先讨论做成什么、关键逻辑和理由，形成并保存方案后再开工。进入另一个 Task 要重新核对，不能拿 A 的认可放行 B。普通工程安排可以按实际代码调整并留依据；改变逻辑、职责、范围或验收时，要回到讨论。

实现采用工作流宪章定义共同条件、implementation-preparation 承载准备、官方 before_implement 提前调用的分工。hook 缺失、禁用或失败仍不能豁免共同条件，但 hook 本身不是能拦截所有聊天的程序锁。[准备契约](../../contracts/implementation-preparation.md)说明实际停止和恢复边界；[T103 候选证据](../acceptance/tv-10-preparation.md)及[T104 正式来源证据](../acceptance/t104-preparation-delivery.md)分别证明其范围，不能互换。

这服务于[实施准备闭环](../../mvu.md#mvu-010)。[T104](../../tasks.md#t104)的构建交付、[T099](../../tasks.md#t099)的实际入口发现及[T107](../../tasks.md#t107)的真实使用反馈仍按原任务验证，不能从规则正文存在推断所有请求都已受约束。

## 轻量任务与一 Task 一份方案

规划时，任务只保存稳定身份、简洁目标、必要依赖和整体验收，便于用户审阅。真正开工前，详细思路放到 implementation/<原 Task ID>.md，由原任务引用。方案说明如何实现和认可覆盖什么，工程 checkbox 留在 tasks；方案保存、用户认可、工程完成和业务验收分别判断。

这种分工解决提前生成过多细节、未读代码就固定文件和写法的问题，不把八栏目要求搬进另一个文件。[T105 的正式来源消费](../acceptance/task-inline.md#t105-正式来源的轻量任务与方案消费)已验证非构建范围的模板传入、认可复用、保存恢复及调整边界；构建来源补验仍留[原 T105](../../tasks.md#t105)。旧已完成任务、历史讨论及撤回的做法继续保留，文件自称“已认可”不是真实认可证据。

## Increment 先规划小业务结果

用户用 Spec 和可选业务描述发起 Increment，不再用 Task 参数定位入口；描述里引用已有任务仍可帮助说明现状和依赖。AI 先结合实际实现、必要技术风险及已有理解，形成能观察和验收的小业务结果，再映射或调整 Task 正文。原身份、验收、完成事实和历史证据随原区块保留，推荐顺序变化不能重编号或重新规划已完成工作。

没有 plan 时停止规划写入；有 plan 无 tasks 时先形成闭环再生成清单；已有两者时复用已有内容，只补实际缺口。plan 留总体路线及一处 mvu 文件级链接，四项闭环说明在同级 mvu。没有新事实时保持文件稳定，规划保存成功也不自动实施业务。详细边界见[Increment 契约](../../contracts/increment-description.md)和[规划闭环](../../mvu.md#mvu-001)。

已有规划能力及可选描述工程事实继续复用；[T096 回归](../acceptance/tv-06-description.md#t096-新规则适配与真实来源回归)验证新规则的非构建职责。正式入口、完整迁移和[T076 真实反馈](../../tasks.md#t076)仍须实际消费与用户参与，不能由隔离演练替代。

## 需求变化能追溯原意

[T104/T096来源补充](../acceptance/request-boundary-source.md)已把Spec修订与规划/实施的边界写入两份技能。旧Increment的Spec-only请求不应被Plan前置挡住；两份源规则的独立判定与审查已留证，但新正文的正式安装、自然发现及文件行为未验，不能从源码包含这条规则推断已能自动选对流程。

用户进一步[确认](../../requirements/raw/2026-11-12-spec-revision-planning-boundary.md)，需求变化可能只需修改Spec；“调整需求”不能自动等同MVU规划。按[当前方案](../../plan.md#自然语言请求与变更影响判断)，先判断修订的是需求定义还是实施安排，确认后的需求改原Spec，再核对真实影响。读取MVU检查影响不等于必须写它；闭环未变就保持MVU，只有任务验收受影响时只衔接相关Task/方案。Spec修订与规划都变时分层同步，单独Spec修订不要求先有Plan/MVU，也不为此新建功能。

这使用户可以修正需求而不被迫重新规划整套工作。[T099](../../tasks.md#t099)仍负责真实发现/定位/行为核对，新增的区分、缺规划材料场景和不应变化材料保护沿原验收验证；本轮只更新方案和验证安排，没有交付或证明新的自动路由，也未恢复发布/挂载职责。

需求改变时，保留可见原始输入、来源和实际日期，再用简洁摘要解释问题、方向、本次变化及确认或待定，沿链接进入当前正式要求。整理稿与 AI 建议另存，不能覆盖原话或成为用户已确认的要求。普通进度、重复续做不构成新需求，不重复制造原文文件。

资料按职责放入 requirements、implementation、analysis 等既有目录，允许按实际用途扩展；不预列所有未来文件，也不建立文件注册或第二状态系统。[资料契约](../../contracts/artifacts.md)维护分工，[T106 实际证据](../acceptance/requirements-trace.md)说明当前准备与 Increment 对来源的消费及保存恢复。范围改变影响到哪些功能，应顺着原文、当前 spec、关联闭环与原任务核对；分析只说明影响，不自行批准需求变化。

## 对话落盘让普通项目也能回查原文

主 AI 使用独立 conversation-recording Skill，每轮保存当前可见用户与已发出助手发言，读回后才交给下游。普通项目可以只启用这一项，沿自己的资料根建档；缺宿主 ID 时明确本地定位，工具原始数据及不可见指令排除。同轮补缺与跨轮同文本分别处理，上一轮真实 final 在下一轮仍可见时补存，末轮缺口如实可查。清理旧资料后只记录新对话，明确暂停才持续停用。

暂停/恢复的最小依据由 Skill 保存在资料根同级的控制说明，新会话先读取再判断能否记录；重新复制和清理对话根均保护它。已知暂停不因保存失败或控制缺失被解释为恢复，恢复后不补暂停期。具体位置和故障边界沿[资料模型](../../data-model.md#暂停与恢复依据)，[T115](../../tasks.md#t115) 需以真实新会话验证持久化，当前只补齐设计。

当前 packages/skills/src/profile/conversation-recording/SKILL.md 已由 [T119 第一步](../acceptance/profile-four-skills-host.md) 建立最小候选：真实 CLI 自然入口、启用后普通追问及修复后的显式入口有全文读取和主 AI 保存读回证据，先前显式入口误记自动 Skill 正文的失败保留。旧 shadow-profile、单项集合声明和真实工作区副本保持；当前只证明限定样本的独立落盘，三轮摘要及完整交接尚未运行。[T115](../../tasks.md#t115) 的完整能力和 [T119](../../tasks.md#t119) 后续步骤仍待原任务；旧直接保存演练及 T114 不抵扣新范围。

## 对话摘要由独立子代理保存

本轮新增原文成功读回且摘要已启用后，主 AI 派发子代理实际加载 conversation-summary，读取交付范围并亲自保存摘要，主 AI 再核对文件、来源和覆盖。这让用户在完整原文之外获得可读的意图、决定及可见结果导航。来源为已确认文件与稳定锚点，摘要不能补造未读回内容，也不负责形成个人结论。

[T120](../../tasks.md#t120) 完善拟建的 packages/skills/src/profile/conversation-summary/SKILL.md。它在 T115 后可与 [T121](../../tasks.md#t121) 的画像来源完善并行，运行期共享文件仍须遵守 T117 验证的提交规则。摘要失败保留原文和缺口，恢复按来源补缺；分析可以在摘要仍进行或实际失败时独立启动。真实子代理加载、保存和结果回传须按 [TV-14](../../quickstart.md#tv-14完整对话惰性分析与共同发布)实测，主 AI 复制返回文本不抵扣子代理实际保存。

T120 的独立验收使用单独用例根，每个目标文件仅一个写入者，不等待 T117。摘要和分析可在不同文件上实际重叠，共享覆盖只由一个执行者汇总；同文件多写入者争用统一留 T117。此处区分真实摘要交接与共享提交验收，不反向增加任务依赖。

## 对话分析直接消费已读回原文

新的明确偏好、持续目标、用户纠正或手动要求触发 conversation-analysis，普通对话先积累。分析子代理直接使用已读回原文，区分明确表达、业务决定、观察与 Agent 建议，结论注明情境、确定程度及更正链。摘要是可选导航，不能成为启动前置。当前明确纠正立即影响协作，主 AI 可继续使用最近有效入口。

[T116](../../tasks.md#t116) 完善拟建的 packages/skills/src/profile/conversation-analysis/SKILL.md；它引用原 Task 的分析职责，不重复新建分析任务。每个真实或明确本地触发来源最多一次自动重试，派发前预留并读回，中断或重复入口不重置，结果不明保留缺口。结论已存而入口失败只补入口；按需查询分别说明原文、摘要、分析和画像覆盖。其真实独立启动及自动交接先由 T119 候选验证，T116 沿同一来源完善，不以规则文字代替运行事实。

## 影子画像按有效认识更新精简入口

## 多会话提交保护更正与遗忘

多个执行者更新同一资料时，最终来源/代次与文件基线校验、写入和读回须在同根短时约束内完成。模型在外准备增量，旧基线重新读取合并，明确更正优先，未知冲突留双方来源，不影响可合并内容。当前 Plan 选用 Linux flock 候选，本机文件实验仅证明其局部操作；[T117](../../tasks.md#t117) 必须先用真实双会话证伪，再完善四个 Skill 的共享保存规则。

明确遗忘先标记来源失效，再清理原文及摘要、结论、入口和派生引用；在途摘要、分析、重试和恢复发布前再核对，失效结果拒写。重建资料根换新代次，覆盖说明只保留必要非正文信息。T117 要分别验两类迟到结果和清理中断；不能约束在途写入就报告未完成，Git 历史另议。本次任务生成不执行真实遗忘，也不宣称多文件事务。

整根移走/删除重建与在途写入需要组合验证：旧根和锁的身份不能被同路径的新对象替代，旧执行者不得自动建根续写。T117 另验最后校验后、实际写入前发生根替换的交错，须证明旧提交被拒或旧写入者已结束后才开放新根共享写入。新锁、新代次和取消请求均不能单独证明通过。T118 在最终来源复验，同级暂停控制不随对话根清理；本次仅据[修复记录](../issues/2026-11-18-profile-context-reconciliation.md)补齐上下文和验收，没有运行该组合。
