# T101：当前范围与保护基线的核查做法

日期：2026-11-10。对应[原任务](../tasks.md#t101)，结果保存到[保护基线](../analysis/acceptance/implementation-preparation-baseline.md)。

上轮已说明本任务先核对实际 CLI 版本、来源与入口、已有修改和可复用证据；用户随后回复“开始吧”。本轮据此开展独立资料核查，并沿用户确认跳过检查清单中已被 Node 入口替代的历史平台入口要求，保留其未勾选标记。这项授权覆盖基线调查与记录，不构成 T103 候选实现方案或真实宿主行为验收的认可。

先实际读取当前 Spec、Plan、同级 MVU、原 Task、准备与注册契约、相关注册脚本和官方登记；以用户指定 Spec 为准。共享 feature.json 当前指向分发功能，因此使用明确目录和不持久化参数核查当前功能，避免改动另一项工作的上下文。

CLI 同时记录 PATH 的实际版本和当前脚本选择的版本。环境变量未设置时，选择脚本默认的1.2.6，直接核验已有缓存中的官方可执行文件及元数据；本地缓存路径仅作为调查定位，不进入分发契约。只运行版本查询，不触发安装或注册。

将维护源、工作区复制副本、官方扩展内来源和生成入口分开清点；比较源与来源副本的完整文件集合及摘要，生成入口保留官方渲染差异，不要求其整文件等于维护源。单独记录旧入口、缺失的新能力、三暂停模式及已有证据的适用范围，不以存在文件推定能力可用。

写入前保存用户已有修改、暂存区摘要、受保护文件摘要、所有正式 Task 行及完成块。复用历史基线的静态证据方式，在本 Task 的证据中附一份采集快照；它不参与安装、进度计算或后续执行判断。完成时只允许 T101 的 checkbox、方案/证据链接和当前计数发生对应变化，其他 Task、历史原文、清单、治理、生产来源和实际挂载保持。

验收采用资料核对：实际版本输出、源与入口清点、全部占用编号、旧证据存在性、文件及暂存保护、引用检查、Markdown ESLint 和读回。没有生产代码变更，本任务不运行代码测试或构建，不以资料核查替代 TV-10/11/12 或阶段验收。后续从 T102 的已生效治理复核继续；发现新业务逻辑或需改安装来源时回到对应 Task 的方案讨论。
