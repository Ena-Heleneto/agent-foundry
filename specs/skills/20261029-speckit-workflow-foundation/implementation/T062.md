## 现状与本轮做法

Increment 已要求规划保存、格式检查和读回后显式调用 artifact-spec-analysis，但当前维护源尚无该技能。T102 治理、T105/T096 的非构建消费及 T106 需求追溯已有实际证据，本轮复用，不重复修改这些能力。候选使用单一 SKILL.md；after_tasks 和 Increment 都加载它，不增加另一个生成器或 after_increment。

先在独占临时项目核对无候选的实际行为，另以新上下文短样本观察默认分析会遗漏什么，再编写最小候选并验证。输出以 analysis/spec-analysis/README.md 为入口，按主要功能独立短段讲清作用和必要逻辑；业务、业务图、技术、技术图、MVU 里程碑和流转图按适用性覆盖、引用或解释缺项。图与说明引用有效材料，不另存活动 MVU 定义或工程状态，不将计划当实现验收。

采用现有官方 skills 1.7.4 本地安装隔离候选，核对完整文件集合和摘要；沿已核实的 Specify 1.2.6 临时 hooks-only 路线只登记 after_tasks，复用未改写的官方原生 tasks 入口。宿主实际执行该入口的后置 hook，再用安装的当前 Increment 调整同一项目规划并显式复用同一候选刷新；留存实际读取工具输出、调用来源、文件差异和原材料保护。真实历史输入只引用已保存来源；构造任务、代码哨兵及测试指令明确为夹具，不当作新的用户需求或业务认可。

分发线已将 hook 声明移到集合配置，本轮不修改集合配置或真实挂载，不恢复已移除的生产 hook 文件。候选与临时 extension.yml 只在隔离目录和验收夹具保留；正式来源及当前配置落点留给 T063 按实际契约核对。构建按原授权继续暂跳过，不以旧 dist 抵扣。

## 顺序、观察信号与保护

1. 保存本方案、格式检查并读回，在原 T062 引用；快照本轮涉及材料和原任务身份，保留并行分发修改。
2. 准备小型等价项目，覆盖两个当前功能及一个暂停方向，具有原文/摘要、spec、plan、同级 mvu、任务与必要证据。用无指导新上下文样本及无候选入口观察实际缺口，保留失败和环境问题。
3. 根据实际缺口写最小候选，做不少于五次独立短样本，人工核对输出形状、来源与未验边界；短答不代替文件行为。
4. 通过官方隔离安装、登记和完整摘要核对后，实际运行原生 tasks 后置创建与 Increment 调整后的同源刷新。两回合均须实际完整读取同一候选、读取同级 mvu，生成可理解功能说明及适用六类分析，引用有效、暂停/缺项/未验明确，原任务身份/已完成证据/业务哨兵和治理受保护。Increment 仅按测试指令授权范围调整规划，不实施业务。
5. 重复刷新核对无重复 Task/MVU、无新增状态副本或无意义时间戳差异；若最小行为失败，仅停止相关下游，沿本 Task 留证并调整候选。T064 的完整故障恢复不在本 Task 冒称通过。
6. 运行目标包 lint、check-types、既有 Python 测试及候选格式/frontmatter/本地链接核查，独立只读审查候选与真实证据。将原始输入、工具事件、实际文件及结果保存到 analysis/acceptance/fixtures/t062/，说明每个未执行范围。按原验收回填 T062，不自动开始 T063。

真实宿主沿当前默认模型、workspace-write，每回合最多 240 秒；环境失败、超时或部分写入分别留证，不能计为通过。若需要恢复，仅沿真实 session 和已保存文件补缺，不自动全套重跑。包 build、构建来源消费、完整注册迁移、正式 modes 入口、真实工作区挂载及用户业务验收均不由本候选验证抵扣。不发布、部署、写数据库或提交 Git。

本 Task 验证新分析契约与双入口实际消费，命中技术前置 C3/C4，沿原 T062 承接，不新增重复门禁任务。候选通过后保留原骨架供 T063 增量交付；失败回本方案调整，不把文字存在或宿主自称成功当通过。
