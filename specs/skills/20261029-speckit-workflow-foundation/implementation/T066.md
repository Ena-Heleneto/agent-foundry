## 迁移逻辑

先完整读取本次来源、配置、附件及目标项目的实际登记、扩展 manifest、受影响生成目录；核对已登记生成正文与同版官方生成结果。额外附件、用户改写、链接、路径越界、未知扩展内文件或归属不清的孤立目录，均列出实际路径并停止受影响迁移，不覆盖、不自动清理。缺任何本次必需正文、配置或附件，在首次变更性官方调用前停止。

测试旧环境使用官方离线初始化及官方 add 建立三/四/五入口登记和六旧 hooks。四项、五项沿已保存历史集合；三项明确标为迁移测试集合，记录其精确名称，不伪装历史安装事实。配置故障或孤立残留另标为人工测试输入，不靠手改 registry 或 YAML 完成正向迁移。

预检通过后，按明确清单对已登记的六退役扩展逐项官方 remove，保留历史产物；无登记对象不得报告已移除。随后按当前集合配置逐项官方强制重装准备、分析、结案 hooks，最后以同一 modes 身份强制更新为仅 Increment。每项实际退出码决定是否进入依赖阶段；失败报告已完成与未运行，不承诺多步骤回滚。若官方 force 无法完整清理，保留失败现场，再核实官方 remove/add 路线；不手删生成目录凑通过。

第二次执行从实际磁盘登记恢复，已退役且确实不存在的对象不重复假报删除；仍按来源刷新所选 hooks 和 Increment。比较实际入口集合、配置语义及完整正文/附件，不能仅凭命令成功或目录名判断。准备保持 before_implement、optional:false、condition:null；分析仅 after_tasks；结案保持当前 after_converge，不增加 after_increment 或额外模式命令。

## 本轮实施安排与已观察问题

测试夹具与候选分别放在 `registration-fixture.mjs` 和 `registration-migration.mjs`，避免用候选本身计算全部期望。前者使用官方 init/add 建立旧环境，各反例复制其独占模板；后者复用来源核验并执行只读预检和官方迁移。新增夹具文件属于已认可逻辑内的工程分工，不增加生产能力或任务身份。

归属核验使用验证方从官方生成结果取得的一次性内存基线，逐次成功后仅更新当前测试上下文；不是落盘安装状态或可直接交付的生产归属服务。T067/T068 必须结合真实项目可审阅的官方来源与登记实现预检，不能将测试夹具的已知基线泛化成未知环境自动可信。中途失败恢复用同一测试上下文核对实际磁盘，未声称进程崩溃或任意环境自动恢复。

初次官方构造旧 hook 时发现集合事件选项没有官方必需的 command 字段，真实 CLI 拒绝。候选和夹具现按所选技能身份补 command，其他选项取集合；无自有 YAML 合并。实际来源变换与官方失败日志保留，不能把首次夹具失败记为迁移通过。

旧 hooks 测试的原路径配置缺失已在写前基线复现，显式启用官方工具后其三个历史场景均停在同一夹具缺项；未修改其原断言或生产脚本。本项新增场景单独报告，不称完整旧测试文件全绿。当前已实际运行的整包 lint 仍报 `collections.ts` 第 11 行两项既有错误；check-types 与 12 项 Python 测试退出 0，最终结果仍需结合后续代码和审查核对。
