# T067：Bash 正式注册接入

日期：2026-11-12。对应[原 T067](../tasks.md#t067)、[注册契约](../contracts/registration.md)、[T066 骨架与验收](../analysis/acceptance/registration-validation.md)和 MVU-004。工程状态只在原任务清单维护。

## 本轮来源与范围

用户在得知 T066 已完成隔离退役验证、真实挂载未改，下一步将流程接入正式脚本后回复「继续吧」。本轮沿 T067 核查并形成具体方案；此前 T066 的「可以」不扩成对本 Task 新工程选择的认可。下述新增工具尚待确认，没有下载、安装或修改生产脚本。

随后向用户展示本方案及新增只读 yq 的具体原因，说明其会改变“不新增依赖”的原约束，用户实际回复「同意」。本次认可覆盖 T067 方案及 yq 的准备与验证；仅此处增加只读运行工具，Node 只调度、无自有 Python/JS 安装核心、官方修改受管配置等边界继续有效。继续当前指定分支，不创建工作树或提交并行改动。

目标是使 Bash 正式模块能只注册 Increment，按本次选择安装准备、分析、结案 hooks，并通过官方 CLI 退役六旧 hooks，保护未知内容和历史，准确传递失败及未运行阶段。调用方仍只有既有公开入口，内部模块保持 Bash，不生成命令模板、包根扩展声明、自有安装核心或配置合并器。

本项不实施 PowerShell、源码清退、完整编排、真实工作区/全局迁移或分发产品。T068、T069、T070、T072 等沿原任务承接；构建、dist 和构建消费继续暂跳过，源与隔离正式消费仍须验证。

## 已核对事实与待确认选择

现行 Bash 命令脚本仍要求 Tutor/Pair/Direct/Increment 四份来源，hooks 脚本仍要求七项逐技能配置。正式事件配置已转入 `src/workflow/collection.config.json`；不能沿旧路径补回配置，也不能直接调用 T066 的测试 JS helper 作为生产运行核心。

现有安装/挂载 Bash 模块已经使用 jq 1.8.1，提供 `FOUNDRY_JQ` 与校验官方二进制摘要的准备方式；本机 jq 实测也是 1.8.1。该现有能力可读取集合和 registry 的 JSON，但不能解析现有 `.specify/extensions.yml` 及技能/扩展 YAML 元数据。

已实际只读调用固定 Specify 1.2.6：`extension list --json`、`extension info --json` 和 `artifact list --json` 提供官方结构化查询；在 T066 保存的孤立 hook 项目中，配置仍有 artifact-issue-description，但 artifact inventory 不返回该项。因此不能将官方 inventory 没有旧项当作有效旧调用已经消失。帮助中的 `event run` 是实际执行入口，不将其用作无副作用的配置读取。

建议新增 mikefarah/yq 作为只读 YAML 解析器，将读取结果输出为 JSON，再复用 jq 核验。官方资料说明它提供无需其他运行依赖的独立二进制及 JSON 输出：[项目](https://github.com/mikefarah/yq)、[输出格式](https://mikefarah.gitbook.io/yq/usage/output-format)。仅解析，不使用 inplace、merge 或写回目标配置；所有受管配置更改仍由 Specify 完成。版本、平台资产与可信校验值须在获准后固定并实测，不能默认 latest 或只相信 PATH 中同名程序；工具准备失败发生在任何目标变更前。

这会增加一个运行工具，超出[总体方案](../plan.md)“Node ≥22.20.0 只调度，不新增依赖”的现有约束，需要用户明确同意后才实施。新增 Bash 运行 Node/Python 核心与已确认边界冲突；自行用正则解析 YAML 会漏掉合法语法，均不采用。仅依赖官方 inventory 已由实际孤立样本证明覆盖不足，也不降格 T066 的保护要求。若用户不希望新增 yq，本项保留待讨论，先重新选择满足原保护目标的读取方式，不静默安装或削弱验收。

## 拟接入逻辑

命令模块保留 `--project`、`--skills-dir`、`--cli` 和 FOUNDRY_SPECIFY_VERSION/default 1.2.6，来源根由调用方明确指向 Increment 的非发现根；只核验 task-increment，不要求或补装三暂停模式。正文及必要附件完整准备，description 取真实来源；扩展身份仍为 modes，声明仅 speckit.modes.increment，必要附件原字节桥接，实际渲染交官方完成。

hooks 模块保留项目和已安装来源根参数，增加明确集合配置输入 `--collection-config`，不从源码仓库隐式寻找配置。缺该输入时报告调用方尚未提供，不尝试恢复旧逐技能配置。增加可重复 `--skill` 指定本次三种允许的 hooks 子集；没有该参数时使用明确的当前三项默认集合，而不是扫描旧残留推断选择。缺未选技能不阻塞；退役对象仍按明确六 ID 核查，任何越出已确认目标的对象先保护报告。

完整读取本次来源、配置和必要附件，核验路径链、链接、缺项、附件冲突及元数据。命中缺项或不可读，在首次变更性官方调用前停止。只读核对当前登记、有效 hooks 配置、扩展 manifest 与生成目录；孤立目录/调用、额外附件、未知声明或用户改写均列路径并停止受影响链。

T066 的一次性内存基线不能成为生产前置。正式核验应依据实际旧登记及可审阅的声明/来源，在自有临时项目由同版官方工具重现相关生成结果，再比较目标正文和精确文件集合；只准备 manifest 声明的来源与必要附件，不能把整个未知目录原样复制后自称已证明归属。无法证明的内容保持原样并报告；不记录持久指纹、不实现第二套渲染器。缺源零调用和未知保护分别记录目标变更调用，临时验证调用不得混称真实目标已经迁移。

全部受影响对象预检通过后，hooks 模块仅对正式登记存在的六旧扩展逐项官方 remove，再对本次选中 hooks 逐项官方 add --force；不安装六旧技能或增加模式命令。命令模块最后以同 ID modes 强制刷新仅 Increment。整体来源→hooks→命令顺序由后续 T070 编排，本 Task 不提前改其代码。

每次执行使用全新自有临时输入，成功或失败都只清理自身临时目录。官方失败保留退出及实际完成/未运行范围，停止依赖阶段；不承诺回滚。重复执行核对真实磁盘与当前来源，已退役无登记不假报再次删除；坏配置或未知孤立调用不会因目录不存在被当作清理完成。来源合法减少附件后再次刷新不得残留旧文件。

## 获认可后的实施与当前验证

上文待确认表述保留方案形成时事实。已按用户「同意」准备 yq 4.54.3，官方 release 资产摘要与下载文件 SHA-256 均为 `129534601871538efe0ba4c5e62a34fb1d5f469bcb975c4fddeb467d82974973`；jq 1.8.1 复用既有官方摘要。工具只放独占临时目录，实际 YAML 别名读取和非法输入拒绝已验证，不安装到系统或写入目标项目。一次 API 二进制下载超时单列，未使用其部分文件；正式下载与官方 checksums/asset digest 一致。

两个 Bash 模块复用 register-commands.sh 中的 Bash 原子函数，register-hooks.sh source 后只调用 hooks 分支；不新增运行核心文件。测试新增 registration-bash-fixture.mjs，包装器仅记录并转发真实 Specify 调用；生产不引用测试 helper 或 T066 内存 baseline。公共 README/PowerShell/完整编排仍按原任务串行承接，本项没有修改它们。

当前 Bash 只读核验已安装的旧声明和必要文件，在自有临时项目调用同版官方生成模式以核对目标目录；零目标变更与临时官方重现调用分别留证。缺配置/正文/附件、未知目录、用户改写、YAML 别名中的孤立 hook、错误工具摘要均保留实际停止证据。只有当前 sources、元数据和所选集合输入齐备才进入目标变更。

实际补测依次发现并先复现：来源减少后留下的空 references 目录会阻断后续重复；递归检查整个发现根会误挡无关技能链接；预检 init 的进程失败被笼统转换为 1；首次安装时悬空发现根因 -d 为假绕过检查，官方返回成功但未生成入口。相应修复仅清理自有暂存空目录、缩小目录检查范围、保留实际退出码、在存在性判断前无条件检查目标路径链；真实项目和未知内容不为修复而清理。

工具和 Bash 当前实现范围明确为 Linux x86_64；其他平台在实际实现/验证前拒绝，不把 PowerShell 缺运行时或 macOS 未执行算通过。编码附件引用等无法核验形式保守拒绝并报告；没有承诺任意来源、所有版本或进程崩溃恢复。构建、dist、真实挂载继续保持原未验边界。

独立审查发现三项 Important，已补实际旧正式结构与保护反例并修复：旧 hooks 来源中的 speckit-hooks.json 仅在与旧 manifest.hooks 语义一致时认领；附件从 SKILL.md 的实际链接开始求可达闭包，不允许附件自引用或不可达环证明归属；旧模式按其实际有/无顶层 references 的布局重现，不为旧输入无条件补新桥接。真实旧模式样本同时包含附件内相对引用，未恢复 Tutor 能力研发。新增四项回归均通过，坏旧配置前后均拒绝；首轮红灯中旧模式先暴露原引用检查遗漏相对附件，不把它伪记成每个缺陷各自独立报错。定向复审与最终源码回归结果沿验收材料续记。
