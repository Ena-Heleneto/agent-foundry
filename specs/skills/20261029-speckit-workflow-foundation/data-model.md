## 2026-11-18 四个独立 Skill 的资料模型

以[三项澄清](spec.md#session-2026-11-18)为准。复用项目唯一资料根，当前仓库沿 `.specify/memory/user-shadow/`，无既有位置的普通项目用 `docs/user-shadow/`。下表为最小信息和验证规则，文件路径采用目标项目已有等价布局。原文与摘要仍在同一资料层，分析和精简入口各自留存。

| 实体与维护者 | 最小信息 | 关系与验证 |
| --- | --- | --- |
| 原文 `conversations/raw/YYYY-MM-DD.md#Mnn`，对话落盘 | 完整正文、角色、顺序、可知日期、真实宿主消息身份或明确本地会话及轮次 | 文件加不复用锚点标识来源。按同一来源补缺。不同轮即使正文相同也独立保留 |
| 已读回范围，对话落盘 | 资料根、可核验来源、项目相对路径与锚点、实际读回相符的范围、身份和保存缺口 | 写入未确认时只保留已读回部分给下游。后续执行者重新核对仍可访问的同一范围 |
| 摘要 `conversations/YYYY-MM-DD.md#Rnn`，对话摘要子代理 | 原文锚点、摘要覆盖、意图、决定及理由、可见结果与缺口 | 一个摘要可引用多条已读回原文。摘要从真实已存内容派生，恢复时按来源和旧覆盖补缺 |
| 分析结论 `conclusions/YYYY-MM-DD.md#Enn`，对话分析 | 已读回的触发来源、使用的原文、认识、情境、性质、确定程度、更正关系 | 直接引用原文，已有摘要可附为导航。区分明确表达、情境决定、观察及 Agent 建议 |
| 精简入口 `profile.md`，影子画像 | 当前有效认识、覆盖、情境、有效更正、必要待核实事项、结论引用 | 只综合有来源的有效认识，正文最多 2000 字，按正文 Unicode 字符计入换行和 Markdown，少量覆盖元信息除外。首次理解不足时可显式建入口，自动刷新按有效变化触发 |
| 覆盖说明 `conclusions/coverage.md`，按需复用 | 原文、摘要、分析与入口的实际覆盖，触发及派发可核验事实、未合入范围、资料代次和最小失效信息 | 支持查询、恢复及多会话核对。未知原有格式保留。说明不复制原文、被遗忘正文或额外保存私人身份 |
| 记录控制说明，位置见下节，对话落盘 | 项目相对资料根、明确暂停/恢复的适用范围、可核验来源或明确本地定位、可知日期及当前有效决定 | 仅保存恢复启停所需的最小事实，不复制发言正文、摘要、认识或被遗忘内容；不是工程状态、项目代理配置或第二份画像 |

原文的状态依次为已接收、已写待核对、已读回相符。保存或读回失败时保留确认部分及缺口。摘要与分析分别从已读回范围开始，各自核对已执行、已保存及可读回事实。分析结论已读回且会改变画像时，进入影子画像自动更新。进展及缺口均以实际资料为据。

当前尚未发出的 final 未形成原文。下一轮仍可见时按实际时点补存上一轮真实 final。无后续调用或已不可见则说明缺档。旧 JSONL、旧摘要和未知覆盖格式仍按真实来源使用。正文围栏须保留已有换行、空白及 Markdown。

### 暂停与恢复依据

对话落盘 Skill 在资料根同级使用 `<根目录名>.recording-control.md` 保存最小控制事实；已有等价持久位置时复用并明确定位。例如普通项目的 `docs/user-shadow/` 对应 `docs/user-shadow.recording-control.md`。路径由目标项目资料布局推导，不写入通用技能的机器绝对路径。该说明留在目标项目，不分发，也不由 Spec Kit、AGENTS 或 CLAUDE 调度。

收到明确暂停时先遵守当下停止要求，再保存并读回暂停的范围及来源；暂停期间只维护必要控制事实，不收集新的对话原文、摘要或认识。明确恢复时先更新并读回控制决定，再从恢复请求及后续新发言开始记录，不补暂停期。控制保存失败时，已知暂停继续有效，实际持久化缺口必须说明，不能把内存决定当作跨重启保存成功。

新会话及复制/重启后的首次执行，先按项目资料布局读取控制说明，再判断是否写原文。对话资料清理、整根移走或删除不处置同级控制说明，也不隐式解除暂停；新建资料根沿用有效控制决定。首次无任何暂停依据可按启用范围建档；已知控制文件丢失、不可读或决定冲突时，不能解释为恢复，先核对项目内仍可核验的来源，无法确认只暂停受影响记录并说明恢复条件，正常协作继续。控制信息本身的明确删除/遗忘请求须说明会影响的恢复依据，不从被删除正文重建它。

### 分析轮次、重试计数与中断恢复

用已读回的真实触发来源或明确本地定位绑定一轮。同一轮的首次派发、实际宿主身份或未知情况，以及至多一次自动重试的预留与结果，写入既有覆盖说明。恢复时先核对实际派发和已存范围。确认预留后尚未派发时续接同一次预留，已派发时核对已有结果，状态不明时保留缺口。新正常触发或新手动要求独立计数，仍先核对实际分析覆盖。只有新认识才新增结论，普通过程可积累供后续分析。不可恢复的分析失败停止本轮自动重试。结论已保存而入口更新失败时，恢复只补入口更新，并重新核对结论是否有效。

### 共享提交与失效

共享写入的预期基线包括目标文件版本、资料代次、当前有效来源及已读回的新纠正。模型在短时互斥外准备增量。最终检查、写入及读回由同一根固定的短时提交约束保护。Linux 候选使用该根的空文件 `.shadow-write.lock` 协调，只在共享写入需要时使用。基线变化时重新读取及合并。无冲突内容合入，明确更正优先，无法判断时保留双方来源与未合入范围。

同路径资料根重建不等于同一根或同一锁。发布范围须同时核对交接时的资料根/锁身份、资料代次和仍有效来源；旧根消失或身份改变时，在途摘要、分析、重试及恢复不得自行创建原根、锁或覆盖说明后续写，也不得跟随移走的旧根回填。普通提交的 `.shadow-write.lock` 实验不证明根替换期间互斥连续：替换方案须证明旧写入者受同一约束拒收，或先确认其已终止再开放新根共享写入。无法证明时保留组合场景未完成，不能以重新获取同名新锁判通过。

明确遗忘时，先标记受影响的范围失效或更新不复用的资料代次。随后清除原文、摘要、结论、精简入口中的相关内容及派生引用。覆盖说明只存恢复和拒收所需的非正文信息。重建资料根采用新代次，旧范围及失效的锚点不可复作依据。已消费旧来源的在途工作仍需通过发布前校验，遇混合来源时可从仍有效部分重算。多文件清理中断时按已标记范围续做，逐文件核对。Git 历史另行处理。

旧的事件、版本和锁字段设计见[历史摘录](history/retired-shadow-runtime-2026-11-18/model.before.md)。下方 11 月 14 日摘要前置关系按发生时的范围追溯。

依据[规格澄清](spec.md#session-2026-11-14)和[专项契约](contracts/shadow-profile.md)，统一行为改由独立技能承载，项目约定仅提供接入和布局，当前先源码复制使用。本节是 Markdown 信息关系，不新增 JSON 协议、数据库或记录程序；其他工作流与 Task 模型保持。

| 资料或关系   | 必要信息                                                           | 身份与校验约束                                                                                                |
| ------------ | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 项目资料根   | 本地位置、当前仅本人、Git 暂行方案及覆盖限制                       | 每项目一个有效根；已有布局优先；当前项目沿 .specify/memory/user-shadow，普通项目无约定时推荐 docs/user-shadow |
| 轮次摘要 Rnn | 真实会话/轮次来源、已发生表达/工具目的与结果、决定/理由/纠正、缺档 | 文件路径＋稳定锚点；宿主 ID 仅在真实可见时记录，否则显式标为本地定位，不以相同文本判重                        |
| 有效结论 Enn | 认识、情境、明确表达或暂定观察、确定程度、限制、摘要来源及纠正关系 | 文件路径＋稳定锚点；至少关联一条真实摘要，不由 Agent 示例或单 Task 决定推断永久特征                           |
| profile.md   | 当前有效认识、协作建议、结论来源、理解不足及必要待核实范围         | 综合有效结论，首次无结论可只说明理解不足，无新整体认识不改写                                                  |
| 更正链       | 纠正摘要→被纠正结论→新理解及适用范围→当前画像                      | 保留旧原文和来源，锚点不重用，清楚说明何处不再或仅部分适用                                                    |
| 保存缺口     | 已写/未写、原因、影响、恢复位置及仍可核实来源                      | 在真实答复及可写的已有摘要内说明，不另建状态文件；不可见部分保持缺档，不承诺永久自动补齐                      |

一个项目包含多轮摘要，一个结论可引用多轮摘要，一个摘要也可支持不同有情境的认识，当前画像只综合有效认识。本期只有研发使用者本人，引用他人的话须标明归属，不能形成他人画像或本人特征；多使用者留待后续版本。

首次按真实需要建立 conversations 日期文件及 profile 入口，出现有效结论时再建 conclusions，不强造空结论。现有日期文件/Rnn/Enn 继续使用；不同会话可用可核实或明确标为本地的会话后缀区分摘要，不批量改名旧资料。写前重读、延续本文件未占用锚点；同轮重入只补新增事实，跨轮相同文本保持不同来源，不新增注册表。

正常顺序为摘要→必要结论→必要画像→检查读回→最终答复；真正最终答复在后续仍可见时补记。保存失败保留已成功部分，继续正常答复并提示缺档，恢复从磁盘及可核实来源补缺，不从画像倒推未知原话。这一例外不改变工程材料失败阻断其依赖步骤的原规则。

同一资料根串行写入；恢复先重读并局部合并，不以旧内存整份覆盖其他会话新来源。矛盾情境可并存，无法判断时保留来源及待核实范围，暂缓受影响汇总，不按后写时间定胜负；无锁方案不承诺任意并发事务。三类资料暂纳入 Git，后续可调整，不自动提交或公开，也不放进技能来源和未来分发物。

## 稳定引用

## 业务节点的最小记录

节点做法记录在原Task方案，结果引用既有证据或目标项目已有等价位置；下表只说明需要表达的信息，不是新表单、字段协议或每个微小动作的固定八栏目。

| 信息               | 内容与约束                                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------------- |
| 业务归属与当前范围 | 所服务的业务目标、已有 MVU（若存在）、原 Task/步骤和当前节点；单接口可以是合法范围，非 Spec Kit 不强制新建身份 |
| 预期结果           | 当前节点怎样算可用及观察方法；同时保留 Task/MVU 尚需满足的整体验收，不能混同                                   |
| 适用步骤与依据     | 当前数据、后端、逻辑验证和页面的适用部分；已有成果的来源和适用证据、不适用原因或必要调序依据                   |
| 依赖与页面汇合     | 当前步骤需要哪些结果、谁依赖本节点；共享数据实现只引用一份，页面列明所需接口而不复制工程状态                   |
| 节点验证           | 实际输入/动作、适合职责与风险的方法、正常及适用异常/权限的预期和实际结果、证据位置及未测范围                   |
| 续接与限制         | 失败或未执行阻止的具体下游、仍可继续的无关步骤、修复和复验条件；事实变化后按原记录核对，不新建状态枚举         |

关系为：已有业务目标可包含多个节点，节点通过原Task对应方案内步骤关联实现与证据；一个页面可依赖多个节点，某个共享结果也可被多个节点引用。既有 MVU 的状态仅按其全部业务信号核对，不按节点数量或接口测试成功数自动汇总。节点本身无独立唯一键，只使用原任务定位及必要代码/语义位置。

继续条件必须来自适用证据：输入与预期明确、实际结果满足当前节点条件、必要前置已具备；只完成编译或关键词检查不能代验业务逻辑。未执行、真实失败及证据不足分别如实描述，不能当作通过。验证失效后仅重核受影响链，不覆盖旧证据或冻结无关工作；这些是原步骤的事实更新，不是新的状态机。

本主线新增通用规则交付的闭环详情位于 mvu.md，正式 Task 已回填 T090～T094 及原 T065 前置职责；节点本身仍无独立工程身份/状态。没有 .specify 的项目复用其现有任务、证据和授权布局，不导入 Foundry 固定路径或仓库画像。

## 清理对象与记录约束

对象可以是整个文件，也可以是同一文件中的代码段、文档段落、注释或失效代码。定位必须足以重新核对目标：文件使用项目相对路径，局部对象附符号名、标题或片段上下文；行号只作辅助，不用易变行号作为唯一身份。多个对象可共享路径，不据此整文件删除。

按当前用途及调用/引用、历史、适用测试形成处置依据；正式交付、有效治理、历史任务事实、验收证据、复用骨架及有效引用受保护。用途无法确认则保留，位置、保留原因和后续处理条件均必填；这些是证据字段，不是新的生命周期状态系统。

处置后串行保存核查结果、运行必要验证并读回；存在已确认应处理但未处理项、引用受损或验证失败时，不记录清理完成。待核实内容保留不单独阻断清理完成，无须清理时保存核查范围与理由。重复调用重读原 Task、实际对象和证据，只补未完成动作；条件改变时重新核对，不抹除先前保留依据。T080 同时承担总体结案，清理部分完成不会自动改变其正式 checkbox。

## 闭环、步骤与证据关系

业务结果的验收信号定义在 mvu.md；plan 保留总体方案和文件级引用，具体工程验收仍在原 Task；技术风险验证是实现它的前置步骤。四类风险命中、可复用证据、验证输入、失败影响和骨架保留写入闭环及关联 Task。验证失败只阻止依赖该结果的步骤，未受影响的工作可继续；通过技术验证不自动完成业务闭环。

工程 Task 完成由其原目标/范围/验收和真实证据判断，正式 checkbox 不按对话状态自动切换。“待用户实现”“待反馈”“保存失败”等是当前步骤说明，不建立另一套工程状态枚举。学习资料只说明掌握和待巩固，不复刻工程 checkbox。

MVU 状态摘要使用未开始、进行中、待验收、已通过、受阻，展示在每条标题下并附 Task/步骤或闭环证据依据；实现具备但缺业务验证时待验收，已通过须有实际闭环证据，受阻注明恢复条件。状态随相关事实变化和恢复读取重新核对；只读分析只报告不一致。共享 Task 的其他职责及未完成的大任务不能替代本闭环判断，摘要不反向更新 Task checkbox，也不新增状态文件或服务。

## 方案有效性与确认来源

有效方案包含与当前Task目标、逻辑、职责和验收一致的内容，可追溯真实用户认可，且已成功保存/格式检查/读回。认可可来自实际历史或当次真实回复，不能由AI自评、文件自称或脚本扮演提供。已有适用内容复用；普通工程调整同步依据即可，实质改变回到讨论。这里描述继续条件，不增加确认ID、状态枚举、指纹、锁或全局审批服务。

缺方案、失效认可或保存失败时，只停止受影响的业务实施和完成更新，允许读取、讨论及修复；前置重新满足后核对实际文件续接，不重做已完成事实。正式工程完成仍只在原Task按全部验收判断。
