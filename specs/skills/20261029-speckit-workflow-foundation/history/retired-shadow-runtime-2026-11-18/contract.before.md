# 契约：影子画像的项目接入、完整记录与独立分析

日期：2026-11-16。依据：[当前Spec与5项确认](../spec.md#session-2026-11-16)、[研究R65～R70](../research.md#2026-11-16-五项澄清后的研究结论)及[记录模型](../data-model.md#2026-11-16-完整原文与独立分析模型)。这是Phase 1设计，不是已运行接口；11月14日旧摘要验收只沿其实际范围复用，原始证据不改。

2026-11-18按[用户最终纠正](../requirements/raw/2026-11-18-independent-shadow-skill.md)更新入口归属：影子画像独立Skill运作，Spec Kit和项目Agent规则不管理其启停、路由或调度；下方接口与主代理/子代理分工是技能执行职责，不是新增Agent管理服务。旧AGENTS试用按历史事实保留，不能抵扣新的独立接入验收。

## 来源与近期使用入口

正文沿用 `packages/skills/src/profile/shadow-profile/SKILL.md`；计划增加同源 `scripts/shadow_runtime.py` 与 `references/host-contract.md` 两份必要附件。前者处理本地记录和保存，后者声明支持的源结构/宿主生命周期接入要求；本次未创建它们，不把现有正文当成已包含采集器或调度器。

原 `scripts/dev/actions/link-skills/link-skills.sh` 精确复制profile分类中的Skill及附件，生成目标项目 `.agents/skills/shadow-profile/`，副本不手改。根 `pnpm skills:link`仍读取紧急版，不能据其成功称本新增附件已复制。暂不接管主线构建/安装、紧急版集合或宿主配置，不发布新的Spec Kit事件/模式/命令。

## 独立Skill接入

技能可直接调用或由宿主技能发现机制使用，不依赖Spec Kit初始化/Task/扩展/hook，不向AGENTS、CLAUDE等项目代理文件增加画像启停或必调用路由。资料位置可沿目标项目已有布局，该位置不构成外部管理入口。Skill发现/实际调用、记录进程启动和语义分析触发分别留证，任何一项存在不证明其他项；宿主自然发现未证实则说明未覆盖，不以项目级强制规则补造成功。用户暂停、清空或只归档时按该次要求保持范围，不因已安装就重新建档。

正式记录适配输入必须包括可信项目根/资料根、真实thread身份、唯一源定位、源结构/实际宿主版本及可用的新消息事件路径。只能定位该thread并核对session_meta/cwd；不搜索其他会话内容，不把机器绝对路径/凭据写进通用附件。CLI版本不冒认桌面或服务端版本。按[11月17日纠正](../requirements/discussions/2026-11-17-record-on-dialogue.md)，不再将可证实结束信号设为统一开工前置；先验证新消息到达即记录的正常链。已有inotify只证明文件变化，SessionEnd/界面切换/每轮回复结束不混为一谈。

主代理只在会话接入/恢复时启动一次受管记录进程，不逐条模型保存。新可见消息到达即尽快处理；CLI停止就结束记录，不以退出为触发、不等待写入/分析收尾、不安排关闭后补录。主动退出中断的未完成部分不计已存，也不保证退出前完整落盘。异常停止保留实际覆盖/缺口，正常协作继续。

## 项目资料与使用者

每项目一个有效资料根，沿既有治理；当前项目为 `.specify/memory/user-shadow/`，普通项目无约定时可用 `docs/user-shadow/`，不强制初始化Spec Kit。旧 `conversations/YYYY-MM-DD.md#Rnn`保留真实摘要；新原文放 `conversations/raw/<thread>.jsonl`，分析沿 `conclusions/YYYY-MM-DD.md#Enn`，处理及遗忘非内容事实放 `conclusions/coverage.md`，默认入口仍为 `profile.md`。不建立跨仓库画像或全局身份注册。 尚无认识时先保存真实原文并建立说明理解不足的精简入口，不强造结论；仅有旧摘要时明确其缺口，不冒认完整来源。

当前只有使用者本人，多会话不等于多人支持；他人发言注明归属，不混入本人特征。三层内容暂可纳入项目Git，后续可调整；没有自动add/commit/push/公开。个人资料不进入Skill正文、附件、通用候选夹具或分发物，测试仅用明确标记的合成信息。

## 运行附件的输入、输出与失败边界

以下是同源Python附件的内部操作契约，不是新增面向用户的工作流命令。字段详见模型；JSON只作为可校验操作载荷及JSONL原文编码，不建工程状态服务。

| 操作     | 输入及前置                                                                                        | 输出及失败信号                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| capture  | 经核验的project_root/memory_root/thread_id/source、source_profile及新消息事件路径；支持范围已验证 | 仅同会话可见消息白名单，逐条原文及保存读回事实；unsupported_source、identity_mismatch、source_gap、save_failed均保留实际缺口   |
| snapshot | 真实trigger_ref/kind、已保存source_refs、当前入口与遗忘约束                                       | source_refs/字节校验、base_profile_digest、forget_generation及更正依据；未保存/被拒收来源不交给分析                            |
| commit   | 分析子代理产生的增量认识/来源/覆盖、snapshot依据、实际尝试事实                                    | 依次保存结论、覆盖、入口并读回；stale_input需锁外重算，invalidated_by_forget丢弃，partial_save仅说明已成功部分，不虚报整链成功 |
| forget   | 用户明确遗忘范围及真实请求来源、关联的项目内原文/分析/入口引用                                    | 先无正文失效依据、再删三层、最后读回报告；delete_incomplete不能宣称完成，不自动处理Git历史                                     |
| inspect  | 当前资料根、确切请求范围                                                                          | 接收/保存/分析/入口的分别事实、覆盖/缺口、实际时点/延迟及最近有效入口；不因无故障提示就推断成功                                |

旧计划中的lifecycle_handle不再是capture的统一必填输入，SessionEnd及强杀矩阵不作为额外前置。记录属于主代理/CLI运行范围；不为记录新建脱离CLI的常驻采集服务，不以任意父PID、全局Codex进程或空闲定时器冒认确切主会话。具体实现若引入独立存活问题须修实现，不能据此重新要求用户提供退出通道。当前日志候选仍须证明真实来源/事件与可靠保存，旧实验不冒认当前接入成功。

## 单轮内容和身份

范围内原文包含用户及Agent已出现的可见文本、必要过程说明、普通实际最终回复；工具调用参数/原始返回、隐式思维、系统/开发者提示排除。Agent可见说明中的执行结果仍属于对话。控件只保存真实可见回答，不能把问题封装/元数据当用户原话；非文本只引用和必要说明，引用不可达或原件未保存如实说明。

事件以真实thread/turn/item三元组为身份，保留线程内顺序与实际完成/接收/保存时点；身份缺失不按文本合并，不伪造ID。旧本地Rnn仍可按其有限身份回查，不冒认真实宿主三元组。新原文JSON解码后text保持原字，不预写未来回复、不用下一轮补记冒认即时记录。

共同保存流程为校验→锁内读遗忘拒收依据→append原文→flush/fsync→读回→确认已保存。只有成功后才能计入持久去重/交付分析；重启由实际原文重建集合。部分行、解析错误、轮转/截断和溢出必须标缺口，不能累计skip后称完整；源变化只在同会话运行期间核验真实身份和位置，不盲目重附着其他日志或关闭后补录。

## 结论、纠正与当前画像

主代理识别新的明确偏好/持续目标/用户纠正或手动要求后，先snapshot确认原文已存，再通过实际宿主协作工具派发分析子代理。只传项目根/已存范围/触发依据及有效约束，不逐条转发完整历史，不让采集脚本代调当前聊天工具。普通过程、Agent建议及他人表达不自动当本人长期特征。已有分析在处理时再来新消息，原文继续保存；新增触发依据必须保留，下次快照覆盖，不能静默吞掉。

子代理锁外读取已存原文，输出增量认识、情境、表达性质、确定程度、更正关系和覆盖，支持历史重新提炼；无新认识可只更新覆盖。 普通更正保留旧原文和旧认识，说明被何条更正及不再适用范围；只有明确遗忘才按删除协议清除。主代理正常协作不等待分析，当前纠正立即应用，使用最近有效入口；分析尽快异步、无固定时限，进展和实际延迟按需查询。

发布进入同根固定文件锁的短临界区，先核对遗忘代际、实际来源、当前profile及快照后新增的用户表达/纠正。仅入口变化时重新合并无冲突增量；新增相关纠正、来源变化或关系不明时释放锁，重算受影响认识，不在锁内等待模型。明确更正依真实来源及适用情境优先；未知矛盾保留双方依据并标待核实，不按完成/写入时间取胜，不阻断其他独立内容。

结论先保存，已分析事实随后保存，入口最后更新并读回；发布事实只对应实际成功范围。入口正文最多2000字，详细依据引用读取，移出已结束进度和重复/失效信息；长期偏好不按固定天数失效。不因入口超额截断原文或删除详细分析。单文件os.replace不构成多文件事务，任何部分成功都要可恢复。

## 同根协调与遗忘后的失效

原文追加、分析提交、入口发布、遗忘及恢复全部经过同一固定 `.shadow-write.lock` 的fcntl.flock协议；锁文件不随每次操作删建，不保存工程状态或私人正文。此为Linux本地候选，全部writer遵守和实际文件系统语义须验证，模型分析不持锁。按FR-033，此锁只协调画像资料的运行期数据，不用于工程任务批准、阻断或完成状态，也不新增工程事务/回执系统。外部直接修改不能冒认受协调保护；发现内容/版本漂移先重读、保留现场和缺口。

遗忘在锁内先写并读回coverage中的递增forget_generation和无正文source_refs拒收，再清除项目内相关原文、分析/更正链、入口及临时派生片段，处理引用和实际未完成范围；核对完成后才报告成功。失效凭据不能复述被遗忘内容，Git历史另议。其保存失败就不能宣称遗忘完成。

所有capture重投、commit、重试和恢复写入前均核对代际和拒收来源；旧代际候选不得先落盘再清理，必须丢弃，从删除后有效来源重新开始。删除中断仍保持拒收，后续优先续完清除，不能用旧备份恢复相关内容。reader在每次使用缓存或磁盘入口前轻量核对代际/未完成删除；受影响旧入口不得继续当有效依据，正常协作可不依赖画像继续。这里只保证项目文件与入口消费协议，不声称清除宿主原生日志、Git历史或模型不可控内部状态。

## 分析额度与派发中断

本轮额度绑定已存真实trigger_ref；合并触发时沿启动时固定的来源集合，消费范围/快照调整不改变额度。首次派发及自动重试均须先在同根短锁内保存coverage预留并读回，再调用宿主协作工具；首次retry_count=0，自动重试的预留将其单向置1，同一轮不回退。预留是已发生的调度事实，不是子代理启动或分析完成的回执；取得宿主返回后才保存真实子代理句柄/尝试结果。记录模型的[计数与恢复](../data-model.md#分析轮次重试计数与中断恢复)为唯一详细定义，不新增工程身份或状态服务。

派发前后中断均先核对持久额度和宿主依据，不按新进程/新句柄重新计数。尝试结果不明且无法取得真实宿主依据时保留缺口，不盲目补派发或回收已占额度；已预留的重试即使未证实启动也不再自动追加。来源过期需重新派发分析的重算也占原轮次剩余额度，无额度则待新触发，遗忘失效丢弃旧代际；不能以重新snapshot或恢复为理由循环重跑。新的正常触发或用户新的手动要求才建立下一轮，先核对有效未完成覆盖；重复原事件、重启或Agent自行重新执行不是新触发。

## 故障、恢复与效果

每轮按真实触发绑定的可恢复分析失败自动重试最多1次；仍失败停止本次分析，保存已完成覆盖和缺口，待下一次已确认正常触发或用户手动要求时基于已存原文续接。不可恢复失败不重复尝试。分析成功但发布部分失败，恢复只补未完成发布，不重复结论；stale_input/遗忘失效不能被当成无条件重试旧载荷的理由，不循环消耗。

正常进展按需查询；已检测故障由执行Agent在当前会话下一次可见反馈说明已写/未写、已分析/未分析、缺口、可用入口及恢复办法，正常答复和原授权协作继续。不另开外部通知或关闭后运行；未接入/漏调用仍由验收观察者依真实轨迹判断，不要求未加载唯一入口的Agent自诊断。

读取成功、实际触发、可靠保存、分析正确、入口可用及真实应用分别判断。没有真实应用机会明确未验，不将合成测试输入流入真实本人画像。验证沿[TV-14](../quickstart.md#tv-14完整对话惰性分析与共同发布)，最终来源还须重新精确复制和真实读取，不能用旧TV-13摘要通过抵扣新范围。
