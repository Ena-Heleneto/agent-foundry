### 中型验证：自动记录、真实触发与恢复

连续至少3轮不点名Skill，覆盖普通问答、讨论、纠正或确认、commentary及普通final。最后一轮发出普通最终回复后不再输入且保持CLI运行，独立核对它已自动落盘；控制组不可调用逐条read_thread/模型保存。记录源完成、接收、读回实际时点；正常运行且未被主动退出中断的样本原文覆盖/自动触发率100%，逐条模型保存次数0。五条旧探针及问答控件final_answer不抵扣普通final或末轮。

分别在隔离输入中给出明确偏好、持续目标、用户纠正、手动分析要求；核对主代理先snapshot确认原文已存，再实际派发分析子代理。另用普通过程对话、仅引用Agent建议或他人偏好作反例。记录实际识别结果、漏触发/误触发、子代理启动身份、消费的已存source_refs及产物，不能用手工指定正确类别或文件存在冒认自动触发。一次任务选择即使有分析也不能固化为永久特征。

分析期间继续完成正常任务，再输入明确纠正；原文继续自动保存，主代理立即按当前纠正行事，不等待新profile。至少1次主动查询可核对记录/分析/入口分别覆盖、缺口和实际延迟；不采用1分钟/5分钟超时门槛，记录真实耗时，不因无提示认定成功。

对分析执行注入可恢复的一次失败后成功、连续两次失败及不可恢复失败：同一真实trigger_ref绑定的一轮自动重试最多1次，连续失败停止本轮，新正常触发或用户新的手动要求才续接；成功覆盖不重复形成。原文仍记录，故障在当前会话下一次可见反馈说明。分析已存/入口失败的分支只恢复未完成发布，不再生成重复结论。

补充以下中断交错，逐项对照coverage读回内容、真实宿主派发调用及返回句柄，不以静态字段值代替实际次数：

| 中断或恢复输入                                         | 必须观察的结果                                                                                      |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| 首次派发预留已读回，调用前或调用后但句柄尚未保存时中断 | 不把预留冒认启动/完成；先核对宿主依据，可确定的已启动尝试继续观察，无法确定则保留缺口，不盲目补派发 |
| 已确认首次失败，重试额度写为1后、实际派发前中断        | 同一触发恢复仍为1，预留不回收；结果无法证实时等待新触发/新手动要求，不自动补发                      |
| 重试已启动后中断，再重复原事件、重建子代理或更新快照   | 沿原轮次及实际句柄恢复；retry_count不清零，原轮次实际启动最多首次加1次重试，无第三次自动派发        |
| 原轮次停止后出现真实新正常触发或新手动要求             | 新来源建立下一轮，只分析有效未完成覆盖；重启/原事件重投不得冒充新触发，已成功结果不重复生成         |

以上交错及保存失败均须核对预留已成功读回才允许派发；保存失败不得凭内存额度继续。详细语义沿[分析模型](data-model.md#分析轮次重试计数与中断恢复)，本指南是待执行场景，不代表宿主已具备尝试查询/恢复能力。

resume/compact及重复入口核对一会话不重复记录，已存原文的分析续接单独标明。主动quit/停止即结束记录，不等待最后一次写入，不在退出后补录；退出中断的尾行或未完成事件不计成功，只报告可核验的实际覆盖。普通final的保存用例在CLI继续运行时进行，主动退出另按上述边界判断，不重复增加SessionEnd或强杀专项前置；旧生命周期探针原文与发生时结果保持。
