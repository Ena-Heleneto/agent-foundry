# 影子画像追加完整对话需求前的条款摘录

日期：2026-11-16。来源：本次修改前的 `spec.md`；以下仅摘录受影响的旧条款，保持正文原文，不是完整规格快照，也不是对话原文。

这些条款保存当时的摘要记录与答复前保存要求；当前有效要求见[现行规格](../spec.md)。旧验收仍仅证明原发生范围，不证明新增能力已交付。

## 旧条款原文

### 用户故事 9 - 维护当前仓库的影子描述（优先级：P1）

**优先级原因**：可追溯理解用于修正规划和协作，避免重复误判用户意图。

用户希望 AI 从可追溯摘要与结论理解当前仓库的协作方式，保留理由与纠正，避免反复重读全部对话或把一次选择泛化为永久特征。

**独立测试**：以实际可见交互检查过程摘要、有效结论与当前描述的引用链，并覆盖一次纠正及恢复读取；明确无独立后台监听能力。

**验收场景**：

1. **给定** 一轮实际对话与工具操作，**当** 回复前留档，**则** conversations 摘要只记录已发生表达、目的、关键结果、影响和必要日志依据；不提前编造回复、工具结果、原话或精确时间。
2. **给定** 新结论、普通进度或纠正，**当** 维护，**则** 新结论关联来源及情境，区分明确表达和暂定观察；影响整体理解才更新 profile，保留被推翻方案与更正关系，重复进度不强造画像结论。
3. **给定** 新会话、中断恢复或画像变化，**当** 协作开始，**则** 读取当前描述并按需查依据；持续协作复用已加载描述，不每轮重读全部历史。不完整历史说明覆盖范围，资料只服务当前仓库。
4. **给定** 仓库画像及对话留档需要维护，**当** 确认规则落点，**则** 按 2026-11-14 追加要求，由独立“影子画像”技能承载统一行为，项目约定负责本地布局与必调用接入，工作流宪章不复制画像规则；既有真实内容和引用链保持，不能因职责迁移重写历史。

5. **给定** 实施讨论形成关于用户习惯/思路/判断方式的有效认识，**当** 维护画像，**则** 按既有约定核对来源和适用范围，复用或修订结论并更新有影响的当前理解；单Task建模或阶段选择不直接泛化。
6. **给定** 后续出现可应用的真实机会或重复纠正，**当** 回顾画像效果，**则** 核对相关行为及实际断点，按轻量试用方式调整；没有机会、未验证或机制未实现时不报告通过。

### 用户故事 14 - 每轮记录对话并持续生成影子画像（优先级：P0，最高）

**优先级原因**：当前缺少每轮留档与画像生成的持续入口，仅消费已有画像无法解决首次建档及后续对话丢失问题。

当前研发阶段只有用户本人，在启用技能的项目中自然对话，不必重复提醒记录；AI 保存真实摘要，提炼有依据的认识，维护能在后续协作中使用并被纠正的本人画像。多使用者支持留待后续版本迭代，本期不提供多人画像管理。

**独立测试**：在声明支持的真实宿主中，不显式点名技能，连续开展普通问答、需求讨论和用户纠正，再新建或恢复会话；核对每轮实际调用、摘要保存、来源链、画像更新和恢复应用。失败与恢复分别留证，不以静态识别或文件存在判定通过。

**验收场景**：

1. **给定** 项目已启用该技能，**当** 用户进行任意一轮对话，**则** 每轮必须调用，保存条件正常时在最终回复前保存本轮已实际发生的表达及必要工具摘要；简短确认、普通问答和无正式 Task 的讨论同样覆盖，不要求显式点名。记录保存失败时按场景 6 继续答复并提示缺档。
2. **给定** 项目尚无画像资料，**当** 首轮调用，**则** 从当前可见内容建立项目内记录和当前画像入口，明确覆盖范围及尚无依据的部分，不读取或复制其他项目的私人画像补齐内容。
3. **给定** 本轮形成有依据的新认识或对已有认识的纠正，**当** 提炼与汇总，**则** 关联原摘要、适用情境及确定程度，更新有效结论和受影响的当前画像，保留被纠正内容的来源；不把单次业务决定永久泛化。
4. **给定** 本轮只有进度或没有新增认识，**当** 留档，**则** 保存本轮摘要，复用有效结论与画像，不为满足必触发而强造新结论或重复改写画像。
5. **给定** 新会话、中断恢复或画像更新，**当** 继续协作，**则** 读取当前有效画像，必要时追溯结论和对话依据；后续提问与取舍可核对实际应用，不以读取成功代替效果验证。
6. **给定** 调用接入缺失、技能不可读或保存失败，**当** 检查本轮记录，**则** 验收观察者（负责验证的人工或独立 Agent）根据接入文件、实际加载/工具轨迹及保存结果判定未接入或漏调用，并在验收记录中报告未生效范围；不要求未加载唯一入口的业务 Agent 自行诊断缺失，也不将其沉默算作通过。接入已加载后，技能不可读或保存失败由执行 Agent 在正常答复中提示具体故障、缺档及恢复条件；保存失败不阻断原授权协作，恢复只补仍可核实的已发生内容，不重复建档、不覆盖用户内容、不编造不可见历史。
7. **给定** 当前仅维护用户本人的画像，**当** 对话引用其他参与者的表达，**则** 只保留必要上下文及来源，不将他人表达归纳为用户本人的习惯或偏好，也不据此创建其他人的画像；多使用者支持不计作本期已交付能力。

#### 仓库内影子描述

- **FR-065**: 画像资料按项目隔离；当前仓库沿用 .specify/memory/user-shadow/ 的资料职责，conversations 保存每轮对话与工具操作摘要，conclusions 保存有效结论，profile.md 保存当前自然语言描述与协作建议。2026-11-14 新增独立技能的统一行为与必调用接入要求，不迁入原仓库私人资料，不建设跨仓库同步、全局画像或后台监听服务；通用技能不硬编码本仓库个人资料路径。
- **FR-066**: 保存条件正常时，每轮回复前保存已实际发生表达与工具操作的目的、关键结果、影响、理由、纠正、必要上下文或日志引用；保存失败按 FR-117 继续答复、提示缺档及恢复后补记；后续可补记上一轮真实回复摘要，不逐字抄全部内容、不提前虚构回复/结果、原话或精确时间；不可见历史明确覆盖范围。
- **FR-067**: 有新结论才更新 conclusions 并关联对话来源及情境，区分用户明确表达与暂定观察；影响整体理解时更新 profile。保留被推翻方案及纠正，用新记录关联旧依据，不把单次工程选择泛化为永久特征，不强造重复进度结论。
- **FR-068**: 新会话、中断恢复或画像变化时读取当前描述，持续协作复用已加载版本并按需检索依据，避免每轮读取全部历史。按 2026-11-14 追加要求，统一记录与画像行为由独立技能维护，项目约定负责本地布局与必调用接入，不重复复制完整技能正文，不写入工作流宪章或宪章提示词；文件创建仅证明保存，实际调用、执行范围与限制须留证。

#### 独立影子画像技能与每轮必调用

- **FR-111**: 新建独立“影子画像”Skill，来源位于 `packages/skills/src/profile/shadow-profile/` 英文目录；统一承载对话摘要、有效结论、当前画像和恢复读取行为，不新增 Spec Kit 模式，不要求用户先创建正式 Task 或初始化 Spec Kit。当前研发阶段只有用户本人，本期只维护其本人画像；其他参与者的表达仅作必要上下文，不混入本人的习惯或偏好。多使用者支持留待后续版本迭代，不作为本期前置，也不将此阶段范围视为永久限制。
- **FR-112**: 在启用项目中每轮对话必须调用该技能，普通问答、需求讨论、实施协作、简短确认和用户纠正均适用，不依赖显式点名或本轮是否产生新认识。交付必须提供可验证的必调用接入与实际宿主调用证据；自然发现描述、安装成功或规范文字不能替代每轮实际调用的验收，未覆盖宿主如实说明。
- **FR-113**: 保存条件正常时，每轮最终回复前保存当前可见、已经发生的对话及必要工具摘要，关联该轮来源，记录关键意图、决定、理由、结果和纠正；保存失败时按 FR-117 继续正常答复、提示缺档并在恢复后补记。不保存隐式思维过程，不预写未来回复或工具结果，不虚构原话、精确时间及不可见历史。重复调用识别已有本轮记录，仅补缺失的已发生内容。
- **FR-114**: 没有已有资料时，从当前项目的可见对话开始建档并建立当前画像入口；明确资料覆盖与尚待形成理解的部分。已有资料优先复用，遵循项目本地布局，非 Spec Kit 项目不因建档被强制初始化 .specify；不从其他项目复制私人画像、会话、凭据或机器配置。对话摘要、结论和当前画像默认纳入项目 Git 版本管理，不默认忽略；明确标注这是暂行方案，后续可另行确认调整。实际提交、推送和公开沿项目授权，不因留档自动执行。
- **FR-115**: 有新认识才提炼结论，影响整体理解才更新画像，保留摘要→结论→当前画像的来源链、适用情境、确定程度及纠正关系。区分明确表达、暂定观察和单次业务决定；无新认识仍保存每轮摘要，不强造个人特征、重复结论或画像变化。
- **FR-116**: 新会话、中断恢复或画像变化时读取当前有效画像，按需追溯依据，并在真实适用机会核对提问、取舍或纠正是否反映有效认识；画像不能替代项目事实、用户授权或验证证据，文件存在与读取成功不等于实际应用有效。
- **FR-117**: 验收观察者（负责验证的人工或独立 Agent）依据接入文件、真实加载/工具轨迹与保存结果，判定接入缺失或漏调用并在验收记录中报告未生效范围、影响及恢复条件；不要求未加载唯一入口的业务 Agent 自行发现该入口缺失，其沉默不算通过。接入已加载后的技能不可读或保存失败，由执行 Agent 在正常答复中报告具体故障、已写/未写范围及恢复办法，不宣称成功。保存失败不阻断本轮答复和原授权协作；恢复先读取实际资料，只补仍可核实的已发生内容，保护原内容及引用，不可见内容保留缺档、不补造。验收观察者是验证职责，不新增后台监听、运行期检测器或 hooks。私人资料与通用技能源码、分发产物分离，不写入凭据，也不因记录行为扩大发布或外部操作授权。

## 旧边界与成功标准原文

- 当前上下文不可见的历史不得补造；摘要只覆盖已发生内容，真实最终回复可在下一轮补记。接入不具备宿主保证或实际调用证据时，必须报告覆盖限制，不能凭必触发文案宣称全会话自动捕获。
- **SC-023**: 画像至少覆盖 2 轮真实摘要、1 次有效结论更正及一次恢复读取；摘要→结论→当前描述引用可追溯率 100%，未来结果、虚构原话、单次选择永久泛化或仓库画像对外夹带次数为 0。
- **SC-048**: 在声明支持的真实宿主且保存条件正常时，连续至少 3 轮不点名技能的对话覆盖普通问答、需求讨论和纠正或简短确认，每轮实际调用及已发生内容摘要的覆盖率均为 100%；无画像首次建档场景实际通过，未执行场景不得计入通过。保存失败及恢复另按 SC-050 验收，不混作正常保存通过。
- **SC-049**: 覆盖至少 1 条有效认识、1 次用户纠正及 1 次新会话或中断恢复，摘要→结论→当前画像的适用来源可追溯率为 100%；无新增认识的一轮不产生虚假新结论，纠正后的真实适用机会单独核查应用效果，无机会如实未验。本期只验收用户本人画像；他人表达混入本人特征、擅自为他人建档的次数为 0，多使用者支持明确留待后续版本。按暂行 Git 方案核对三类资料可被版本管理且未被默认忽略，并明确保留暂行标注；未经授权自动提交、推送或公开的次数为 0。
- **SC-050**: 实际验证至少 1 次重复调用和 1 次保存失败后的恢复：故障轮仍正常答复并明确提示缺档范围，恢复后仅补记仍可核实的已发生内容；重复摘要、覆盖原纠正依据、虚构未来结果、跨项目复制私人资料及把失败记作成功的次数均为 0。缺接入或漏调用由验收观察者据实际轨迹和文件结果明确判定未生效；已加载接入后的技能不可读，由执行 Agent 在正常答复中提示。两类场景分开留证，不将未加载入口时业务 Agent 没有自诊断提示当成接入正常，也不以文案或静态检查替代行为证据。
