## 需求提示词

背景与目标：

当前影子画像主要保存对话摘要，记录不够完整。未来随着分析能力完善，流程可能更加复杂，因此需要将可靠记录、分析提炼和 Agent 消费分开，避免复杂分析阻塞主代理处理用户任务。

### 一、已经确认的需求

1. 建立三层产物：
   - 完整对话副本：作为可核查、可反复提炼的原始依据。
   - 分析产物：保存从对话中提炼的认识、依据、适用情境和纠正关系。
   - Agent 精简文档：作为 Agent 默认读取的入口，帮助其快速理解用户及当前协作背景。

2. 完整对话副本：
   - 保存用户与 Agent 的可见发言原文，包括必要的过程说明和最终回复，保留角色、顺序及来源关系。
   - 不包含工具调用参数和原始返回；Agent 在可见发言中说明的执行结果仍属于对话。
   - 不收录隐式思维、系统或开发者提示，不编造不可见历史。
   - 历史原文保留，支持后续结合新对话重新分析；不能以分析产物覆盖原文。
   - 已有摘要不能冒认为完整原文，历史缺口应明确标注。

3. 分析与提炼：
   - 先可靠保存对话，再开展分析。
   - 支持增量分析，以及按需回查早期对话、跨轮次重新提炼。
   - 分析可以产生独立材料，结论应关联真实对话来源。
   - 区分用户明确表达、Agent 建议、暂定观察和已确认决定。
   - 处理纠正、变化及不同情境下的差异，避免将一次任务要求固化为长期偏好。
   - 没有新认识时，不强行产生结论或更新画像。

4. Agent 精简文档：
   - 保存当前有效、对持续协作有帮助的信息，例如相关背景、持续目标、已确认的沟通和工作偏好、必要项目背景、有效纠正及待核实事项。
   - 控制篇幅，避免随历史无限增长；详细分析与原始对话通过引用按需访问。
   - 标明分析覆盖范围，使 Agent 能识别尚未处理的新对话。
   - 支持后续更新和纠正；用户当前明确要求、项目正式规则及实际证据优先。
   - 项目事实与个人偏好应能区分，避免把全部项目进度堆入个人画像。

5. 主代理与处理流程：
   - 主代理承担轻量触发、必要信息交付和结果消费。
   - 复杂分析及精简文档更新允许异步推进，主代理不必等待分析全部完成。
   - 主代理可使用最近完成的有效版本，用户当前明确纠正应立即应用。
   - 子代理可以作为执行方式，但不预先限定为每轮新建子代理，也不将常驻服务、队列或数据库写成既定方案。
   - 真实触发、答复后续跑及中断恢复能力必须经过宿主验证，不能仅凭技能文字承诺后台可靠运行。

### 二、需要补充澄清的边界

请识别并集中列出以下待定事项，不将建议默认值写成用户已经确认：

- 如何取得真实完整对话，尤其是最终回复，以及用户不再发送下一轮时的最后一轮保存。
- 可靠接收、保存成功、分析完成分别如何界定；记录环节允许的等待时间和分析更新时效。
- 中断、失败、重复触发后的续接、去重和缺档提示。
- 多个会话同时记录、分析和更新同一项目精简文档时的协调规则。
- 用户要求“忘记”时，对原文、分析产物及精简文档分别如何处理。
- 精简文档的篇幅预算、信息筛选与过期规则，以及附件等非文本内容的记录范围。

### 三、规格一致性与验收

- 明确衔接现有“摘要记录”“包含工具摘要”“答复前串行保存和分析”等表述，避免新旧要求并存冲突。
- 保留现有历史、来源链接及原验收事实，不将新能力写成已经交付。
- 补充可验证场景：原文完整性及角色顺序、最终回复收录、缺档标记、历史重新提炼、纠正传播、无新认识、重复触发、并发更新、中断恢复，以及分析积压时主代理继续正常工作。
- 分别验证记录成功、分析正确、精简文档可用和 Agent 实际应用效果，不能仅凭文件存在判定通过。
