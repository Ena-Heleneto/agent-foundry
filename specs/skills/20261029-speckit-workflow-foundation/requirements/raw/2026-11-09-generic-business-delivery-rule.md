# 追加需求：通用业务实施顺序规则

日期：2026-11-09。归属：[工作流基座](../../spec.md)。**优先级：本 Spec 后续新增工作中的最高优先级。状态：已登记，尚未细化和实施。**

## 用户明确表达

用户希望把“数据库 → 后端业务 → 验证逻辑 → 前端页面”整理成可通用的规则，不依赖 Spec Kit。随后明确要求追加到本 Spec，“不实施不走spec流程，但是最高优先级”。

因此本轮只保存追加意图、讨论背景和优先顺序。后续恢复本 Spec 时先处理这项需求，其他待办及既有任务身份、完成事实和必要前置继续保留；最高优先级表示工作排期，不把记录当成规则已生效或实施授权。

## 已讨论的建议，供后续确认

上一轮 AI 建议围绕一个小的可观察业务结果推进，顺序可表达为：

```text
明确业务结果与验收 → 数据设计 → 后端业务与接口 → 验证业务逻辑 → 正式前端页面
```

建议内容包括：每个小业务结果内逐步打通；数据设计说明模型、归属、权限与必要约束；已有实现和证据直接复用；验证按业务选择单元测试、接口请求、集成测试或临时测试页；覆盖适用的失败路径；正式页面接入后仍验证真实交互；不适用步骤和必要顺序调整说明依据。

这些属于上一轮讨论建议，尚未逐项确认，不作为当前项目强制规则。通用规则应能用于普通对话和其他任务工具，不要求项目具备 .specify、mvu.md、Task ID 或 Spec Kit hooks。具体交付形式尚未选择，不预先认定必须新增某个 Skill 或修改项目治理。

## 保留的讨论问题
