## 目标与职责

curl 引导脚本负责取得同版运行材料、校验并启动安装器，使使用者可以通过一次调用选择技能并完成适用安装和挂载。

建议分为两层：

| 部分                         | 职责                                                           |
| ---------------------------- | -------------------------------------------------------------- |
| `vite-plugin-curl.plugin.ts` | 构建时交付引导脚本、安装器和必要材料，不在构建时运行安装或挂载 |
| 生成的 `install.sh`          | 使用者执行时下载同版安装器，校验后启动已有 Node 入口           |

技能选择、正文和附件下载、内容校验、安全提交、归属收据及适用挂载继续沿用现有安装模块，避免在引导脚本中重复维护业务实现。唯一安装入口保持 `node script/index.mjs [参数]`；Node 按平台调度内部模块。主线仅保留 curl 安装方式，安装后自动执行适用挂载，保留 `--no-mount`。

现有安装模块仍有能力缺口；复用入口不表示全选、分类、跨平台或完整挂载已经实现。本文只讨论 Bash 引导方式，不据此增加或承诺其他平台支持。

## 使用方式与执行顺序

以下为命令形态示意，地址和文件名尚未确定，不是已公开可用的安装命令：

```bash
curl -fsSL 'https://<固定发布来源>/install.sh' |
  bash -s -- --agent codex --skill vue-reactivity
```

引导脚本建议依次执行：

1. 检查 Node、curl 及校验过程需要的工具；Node 下限沿用现有入口约定的 22.20.0。
2. 确定本次固定版本、固定发布提交的 HTTPS 下载来源，引导脚本、清单和运行材料必须同版。
3. 建立本次独立临时运行目录，下载清单及必要安装器材料。
4. 校验下载文件的路径、大小和摘要；缺件、下载失败或校验失败时停止，不启动未核验材料。
5. 保持使用者当前项目目录不变，调用临时目录中的 Node 入口，并用参数数组语义保留用户参数。
6. 保留安装器的退出码，清理本次可证明属于自身的临时文件。

启动动作示意如下；变量来源、参数冲突处理及下载校验尚需在实施前确定，此片段不是完整脚本：

```bash
node "$runtime_dir/script/index.mjs" \
  --source "$release_source" \
  --version "$version" \
  "$@"
```

安装器随后根据本次选择安装技能，按已有保护规则处理目标内容，再执行适用 hooks 和 Increment 挂载。引导脚本不切换到临时目录运行安装器，以免改变项目级安装目标；运行依赖放在独立工具目录，不修改消费项目的依赖配置。

下载应沿现有 [安装契约](../../contracts/install.md#内容获取及保护) 保持 HTTPS、重定向、超时、路径和摘要检查。上面的短命令仅展示调用形态，不替代完整下载保护。该契约尚含旧主线官方安装入口内容，当前主线范围以 [主线 curl 范围修订](../../requirements/raw/2026-11-12-main-curl-only.md) 为准。

## 产物结构建议

本次讨论提出以下结构，供继续确定插件落点；不将建议路径视为已经生效的发布契约：

```text
dist/curl/
├── install.sh          # 引导下载、校验并启动安装器
├── release.json        # 版本及文件清单
├── script/             # 现有安装器及必要运行模块
└── skill/              # 当前技能复制插件的输出位置
```

当前技能插件输出为 `dist/curl/skill/<集合>/<技能>`，旧安装器及清单使用 `skills/<分类>/<技能>`。两端路径必须统一后才能实际消费；不能仅新增 `install.sh` 就宣布安装链接通。
