- **FR-070**：提供简易版本管理，覆盖维护当前源版本、构建时派生产物版本标记、技能发布成功后登记版本与下载链接三个动作。源版本、构建结果及已发布记录须可区分；仅构建或上传失败不能登记为发布成功，同一已发布版本不能被不同内容或地址静默改写。版本管理本身不扩大上传、部署或发布授权，不要求在本轮引入工具、脚本、CI 或自动发版实现。

- 当前单次构建交付全部已有内容；尚未实现的安装器与发布材料不生成占位文件，也不作为当前构建前置。构建成功不代表完整安装、发布或线上 MCP 适配完成，详见 [构建契约](contracts/distribution.md)。

## 用户场景与测试（必填）

### 用户故事 1 - 外部用户按需获取完整技能（优先级：P1）

没有本工作区开发环境的用户，可以从公开来源通过主线curl下载入口安装整包、一个分类、一个或多个技能，并直接阅读技能正文及其引用材料。

**优先级原因**：准确交付可用内容是所有后续能力的基础，用户不应为了一个技能安装整套工作区。

**独立测试**：在外部干净目录使用指定发布版本，分别完成四种范围的安装，核对所选技能、必要附件和未选内容；不依赖隐匿或挂载功能。

**验收场景**：

1. **给定** 一个已发布且通过核验的统一包及其版本，**当** 用户分别选择整包、分类、单技能、多技能，**则** 安装结果恰好是所选公开技能集合，每个技能的正文与必要附属文件完整可读，引用不依赖本工作区绝对路径。
2. **给定** 某个分类的来源目录，**当** 用户按已核验包内的技能声明和正式范围核对可安装名称，**则** 仅展示该分类可安装技能，不产生安装文件，不混入工作区挂载副本。
3. **给定** 已安装某分类，**当** 用户增装另一单技能，**则** 已有其他技能不被修改或删除，不出现未选择的新技能。
4. **给定** 无效技能名、空分类或不满足依赖的选择，**当** 用户安装，**则** 得到明确诊断；不得静默改为整包安装或擅自补装其他技能。
5. **给定** 首版公开内容仅含 coding、frontend、workflow，**当** 用户列出或安装整包，**则** 结果不含 eval 评估样本；显式选择 eval 分类或其技能时报告未公开或不可用，且不安装其他内容。
6. **给定** 两次调用之间官方 latest 已更新，**当** 再次预检，**则** 重新查询实际版本；每次报告与同次校验的Agent元数据发布包版本一致，不依赖本地 Agent 声明文件。
7. **给定** 在线元数据、发布包完整性或规则布局校验失败，**当** 主线curl执行写入前检查，**则** 明确失败且目标零写入，不回退旧表，也不提供官方skills安装建议。

### 用户故事 2 - 用下载脚本安装并获得可核查结果（优先级：P1）

用户通过主线curl下载并执行自有安装器选择技能范围，取得同固定发布版本的完整内容；失败时能知道哪些内容已经安装、哪些需要重试。

**优先级原因**：这是当前主线唯一安装入口，提供所选技能安装、可选隐匿及自动挂载。

**独立测试**：在受支持环境通过主线curl安装固定版本和所选范围，将正文及附件与已核验统一包/候选逐项对照；另外验证冲突、重复安装和中断后的结果说明。

**验收场景**：

1. **给定** 明确的版本和合法选择，**当** 使用 curl 获取并执行安装器，**则** 安装内容与所选固定版本的已核验统一包及候选一致，结果列出实际技能、版本、目标位置及各阶段状态。
2. **给定** 未提供选择参数或混用互斥选择，**当** 执行安装器，**则** 在写入前报错并给出正确用法，不使用隐含的全量安装。
3. **给定** 相同版本、相同内容已经安装，**当** 再次执行，**则** 识别为已满足而不产生重复文件；该技能可以作为本次已核验成功集合参与后续步骤。
4. **给定** 同名未知技能、用户修改、另一版本或已跟踪的目标文件，**当** 执行安装器，**则** 保留原内容、报告冲突和处理建议，不自动覆盖、删除或取消跟踪。
5. **给定** 下载或写入中断，**当** 执行结束，**则** 列出完整成功、失败及未执行项，不把残缺目录视为已安装；重试先核对现场，保留已确认完整内容及用户修改。
6. **给定** Linux、macOS 或 Windows 上具备文档列出的 Node 和平台前置工具，**当** 经已验证的install入口及同版内部平台模块执行，**则** 通过T019已核验的首次获取和平台接线选择Bash或PowerShell内部实现，相同版本及选择范围得到一致内容，安装、隐匿及适用挂载的结果分别可核查；任一平台未实际验证时必须标为未验证。
7. **给定** 目标 agent 支持项目级和全局安装，**当** 用户分别使用默认范围与显式全局选项，**则** 技能分别安装到对应项目级与用户级位置，不相互覆盖；若目标 agent 不支持全局安装，请求在写入前被拒绝。

8. **给定** 用户已取得核验通过的同版本Node公共挂载入口及内部平台模块，**当** 执行 `node script/index.mjs [参数]`，**则** 无需指定子命令或平台脚本，保留消费项目目录、参数原始值、输出和退出码；取消时停止正在执行的子进程及已验证平台的后代，不将未支持参数或未接通挂载报告为成功。

9. **给定** 技能与 curl 同次发布统一版本且用户选择一个历史技能版本，**当** 通过公开 curl 入口安装，**则** 使用最新已发布的 `install.sh` 获取所选历史技能内容，技能和辅助脚本都来自该历史版本的已核验统一包，实际入口与所选包的版本及来源分别可核查；不因选择旧技能切换到旧入口，也不因入口更新混用其他版本运行材料。

### 用户故事 3 - 挂载所选钩子与 Increment（优先级：P1）

需要工作流集成的用户，可以把本次安装的适用技能接入目标项目已有的 Spec Kit 阶段钩子和指令。钩子指阶段前后运行的动作；指令指用户主动调用的入口。

**优先级原因**：用户不仅要读到技能，还要按明确的入口分工使用既有工作流集成能力。

**独立测试**：准备相同的已安装技能集合和可用目标项目，验证主线curl安装后的自动挂载及显式关闭结果；不需要启用隐匿。

**验收场景**：

1. **给定** curl 本次成功集合包含来源分类为 workflow 的技能，**当** 未关闭挂载，**则** 调用公共入口检查环境，先处理适用钩子，再在钩子成功或不适用时注册适用指令。
2. **给定** 关闭挂载，或本次只安装其他分类但历史上已安装 workflow，**当** 安装完成，**则** 跳过挂载入口，不因历史技能触发处理。
3. **给定** 用户执行主线curl安装，**当** 安装完成，**则** 按本次workflow选择和--no-mount进入或跳过挂载，不要求另行执行官方skills安装或该路线的显式第二步；技能安装与挂载结果分别报告。
4. **给定** 主线安装流程传递版本、所选技能、目标agent、实际安装位置与目标项目，**当** 公共入口执行，**则** 取得同版本公共材料并核验实际文件，只处理本次已核验成功且有对应映射的技能；不能以命令退出成功或扫描到历史内容代替核验。
5. **给定** 本次只选 task-increment 且正文、附件、版本和目标环境满足条件，**当** 请求挂载，**则** 注册 Increment，不要求三个暂停模式来源或补装其他技能；bug-report 等无映射技能报告不适用。
6. **给定** 目标不是 Spec Kit 项目，**当** 请求挂载，**则** 报告不适用并跳过，保留技能安装结果，不初始化项目或改写宪章。
7. **给定** 目标是 Spec Kit 项目但缺少必需工具、集成、所选来源或兼容条件，**当** 检查环境，**则** 报告具体失败及修复条件，不进入依赖阶段；缺少三个暂停模式不属于失败条件。
8. **给定** 钩子失败或指令注册失败，**当** 执行结束，**则** 分别报告技能安装与挂载结果；钩子失败不得继续注册指令，指令失败保留已经成功的步骤并提供可重复执行的续接方式。
9. **给定** Increment 已挂载且旧项目曾有三个暂停入口，**当** 执行受管更新并连续重试，**则** 每次通过官方能力按同版来源刷新当前入口，实际确认暂停入口已处理且不复活；未知文件、用户维护内容和无关扩展保留。
10. **给定** 所选 agent 属于本次在线解析版本 skills 的支持清单，**当** 使用 curl 安装，**则** 按对应 agent 的安装位置约定交付技能；若目标 Spec Kit 项目中的该 agent 集成不在本次 skills 清单与所选 Specify 版本的适用交集内，则明确报告挂载不受支持，保留技能安装结果，不自行创建原生工具不支持的集成。
11. **给定** 已全局安装 workflow 技能且挂载开启，**当** 用户提供明确项目，**则** 仅对该项目挂载；未提供项目时报告“技能安装成功、挂载失败：缺少目标项目”，提供补传项目重试说明，不修改当前目录或用户主目录的项目配置。

12. **给定** 本次选择主线实施准备 skill，**当** 经主线curl安装入口及适用挂载步骤消费，**则** 正文、附件与 before_implement 声明同版完整，官方注册结果和实际可加载证据可核查；不新增 Implement 包装指令，不发起业务实现。
13. **给定** 所选实施准备正文、附件或 hook 声明缺失或不同版，**当** 进行挂载前核验，**则** 在首次Specify扩展安装前明确失败，报告已完成与未执行阶段；不以历史安装替代本次来源核验。
14. **给定** 主线Bash、PowerShell、唯一公共入口或工作区集成实际参与挂载，**当** 核查相同版本及选择的消费结果，**则** 均采用当前映射，三个暂停入口不再生成或重装，未执行平台和调用路径如实报告。

### 用户故事 4 - 可选地隐藏本次安装带来的本地文件（优先级：P2）

用户希望安装技能后不让本地新增文件出现在普通未跟踪列表中，可以在 curl 安装时显式启用隐匿；技能仍保存在 agent 能读取的位置。

**优先级原因**：隐匿是可选便利功能，不能阻止不使用该功能的用户正常安装。

**独立测试**：在普通仓库、无 Git 的目录及父仓库的子目录分别安装；核对实际排除来源、未跟踪列表和原有规则。

**验收场景**：

1. **给定** 未传 `--hidden`，**当** 安装成功，**则** 安装器不新增本地排除规则。
2. **给定** 当前目录是普通仓库根目录，**当** 使用 `--hidden` 安装一个分类或单技能，**则** 仅为本次成功内容对应的实际路径追加精确本地排除规则，保留原规则并去重；所选文件不再出现在普通未跟踪列表，未选内容不被新规则隐藏。
3. **给定** 项目级安装的当前目录没有 `.git`，包括位于其他仓库内部的子目录，**当** 使用 `--hidden`，**则** 明确提示“跳过隐匿处理”并继续安装，不修改父仓库排除配置、不初始化 Git、不改成全局安装。
4. **给定** 排除文件不可写，或写入的规则没有实际生效，**当** 安装已完成，**则** 保留已安装内容并报告“安装成功、隐匿失败”，给出重试条件，不误报全部成功。
5. **给定** 挂载需要修改已有共享配置，**当** 启用隐匿，**则** 说明这些共享配置的改动仍可见，不为隐藏本包条目而忽略整个文件；无法全部隐藏时明确报告覆盖限制。
6. **给定** 构建已将交付技能的相对路径和安装根占位符写入隐匿脚本，**当** 当前 agent 使用 `.agents/skills` 且本次仅安装其中部分技能，**则** 替换前缀后，先检查当前项目 Git 目录，再只将本次成功技能的精确路径写入本地排除文件；不残留占位符、不写入构建目录、不隐藏未安装技能或整个 `.agents/skills`。

7. **给定** 统一包及所选技能已核验且用户开启 `--hidden`，**当** 同包hidden模块缺件、协议不兼容或执行失败，**则** 保留成功安装并报告“安装成功、隐匿失败”及重试条件，不执行未核验或未知协议脚本；统一包自身下载或核验失败时不得安装技能。技能仅部分成功时如实报告逐项失败，不把安装阶段改成成功。

### 用户故事 5 - 维护者交付可追溯版本（优先级：P1）

维护者可以准备一个来源清楚、范围明确、内容完整的发布版本，供主线curl入口及同版公共挂载材料消费，并区分本地验证和真实远端验证。

**优先级原因**：稳定、可追溯的公共内容是外部安装的交付前提。

**独立测试**：在不执行远端发布的情况下检查发布范围、候选文件核验记录、版本对应、完整文件与安装文档；获授权发布后再补真实外部安装证据。

**验收场景**：

1. **给定** 一组获准公开的技能，**当** 维护者准备版本，**则** 发布物覆盖这些技能的完整目录、必要公共材料和版本信息，不混入工作区副本、未公开内容或敏感配置。
2. **给定** 同一个发布版本，**当** 用户通过主线curl入口选择安装范围，**则** 可以追溯到相同技能源；公共挂载材料与技能版本对应。
3. **给定** 远端发布尚未授权，**当** 完成本地产物验证，**则** 报告明确区分本地已验证与远端未验证，不把占位下载地址写成已可用命令。
4. **给定** 新交付能力完成，**当** 检查已有消费方式，**则** MCP 清单分发、工作区技能挂载和原生扩展入口仍然可用。
5. **给定** 功能已在当前仓库实现且用户尚未创建公开仓库，**当** 维护者准备迁移交付，**则** 明确列出用户直接迁移所需的技能、MCP 源材料及配套工程文件、新仓库的依赖与配置调整、待替换的公开来源地址和待补的远端验证；不要求生成迁移工程包。用户建仓并完成源码迁移及配置后，再按 US7 另获授权执行首次正式发布，外部安装不依赖原 monorepo 的未交付文件。
6. **给定** 紧急版在当前工作区的 `packages/skills-distribution-urgent/` 已完成范围内全部本地验证，**当** 本地阶段结束，**则** 汇总真实结果和迁移说明后，在既有授权及真实前置满足时继续，不因阶段结束或逐Task方案保存要求再次暂停确认；搬移、建仓、推送或发布仍需对应明确授权。说明后续将该目录与 `packages/skills/`、`specs/skills/`、`apps/mcp/` 一同迁往采用ISC的新开源仓库。迁后独立检查与公开来源消费继续列为后续验收，不以尚无远端否定本地阶段结果，也不把本地结果当最终发布通过。

7. **给定** 主线与紧急版并行且用户仅问“接下来应该做什么”或查询本功能进度，**当** AI回答（包括新会话或中断后恢复），**则** 无需用户提醒，先核对本Spec、plan/tasks/mvu及必要现场证据，分别说明两条线的当前事实及依据、下一步、分工与适用阻塞；紧急目标目录未创建或旧副本有局部成功时，同样保留两条线，不把旧证据当新位置通过。
8. **给定** 用户正在主线手写，紧急版出现失败或真实依赖阻塞，**当** AI规划或恢复实施，**则** 保留主线的原计划及用户手写分工，只停止依赖失败结果或缺必要输入/授权的部分，紧急版不设中间固定停点；不要求主线等待紧急版或紧急版等待主线重写，也不接管用户代码。
9. **给定** 用户明确仅处理其中一条线或其中一条缺少必要材料，**当** AI回答下一步或续接，**则** 可聚焦指定工作，但简述另一条保持的安排；缺材料的一条明确待核对和继续条件，不静默遗漏、误报完成或自行判定暂停，也不因完成发现检查而自动取得实施授权。
10. **给定** 紧急版已有实施授权且下一Task或阶段属于已确认范围，**当** 当前项完成并满足真实前置，**则** AI读取必要材料、保存适用方案与证据后连续推进，不因逐Task方案或阶段切换重复索取认可/继续指令；缺输入、依赖失败或外部操作缺对应授权时只限制受影响部分，继续可独立完成的准备与验证。

### 用户故事 6 - 在真实分发需求中规划并验证闭环（优先级：P1）

用户在主线移交后，以本 Spec 的业务目标或需求描述使用 Increment 规划最小可推进、可验收的闭环；已有 Task 用于关联职责与证据，不再要求 Task 定位参数。Tutor 的历史场景保留为暂停记录，移出当前执行及结案条件。

**优先级原因**：以实际需求和反馈检验闭环规划，保护既有任务事实；不以安装成功代替行为验证。

**独立测试**：选择真实分发业务目标，保存 Increment 规划、用户反馈、调整与恢复证据；不等待全平台或公开发布，不删除真实 plan/tasks 制造分支。Tutor 学习与共同报告不在本期测试内。

**验收场景**：

1. **给定** 主线已移交且本 Spec 有 plan/tasks，**当** 按本 Spec 或业务描述调用 Increment，**则** AI 解释业务结果、观察办法、划分顺序、依赖、暂缓项及影响范围，依据真实反馈调整，保留 Task ID、已完成事实和证据，刷新同一综合分析。
2. **给定** 验证有 plan 无 tasks 或缺少 plan 的路径，**当** 准备材料，**则** 使用独立验证材料，不删除本 Spec 真实文件；无 plan 提示先规划，有 plan 才生成任务。
3. **历史场景（暂停，移出本期验收）**：**给定** 指定 Task 已有 MVU，或有 plan/Task 但没有 MVU，**当** 进入 Tutor，**则** 分别沿用或仅补齐指定 Task 的闭环；其他 Task 只作依赖引用，范围不足时说明限制，不扩围或虚报业务完成。
4. **历史场景（暂停，移出本期验收）**：**给定** 用户按 Tutor 编写主要代码并提出问题，**当** AI 提示、检查或按请求局部代写，**则** 以实际实践反馈判断学习结果，局部代写后恢复原分工，不用 AI 示例、模拟发言或自动测试代替掌握证据。
5. **给定** 一个技术假设验证失败或记录写入中断，**当** 准备继续，**则** 受影响步骤停止、保留证据并修复或调整路线，无关工作不被无理由冻结；重试续接原 Task，不重复创建闭环或任务。
6. **历史场景（暂停，移出本期验收）**：**给定** Task 结束且存在知识片段，**当** 用户与 AI 共同整理报告，**则** 读取 personal-hub 实际文章格式，复用既有稿件并保存草稿；工程、学习和报告各自判断完成，不自动发布或恢复 Review 双确认。
7. **给定** 本 Spec 已有任务且 Increment 生成或修订 MVU，**当** 核查规划结果，**则** 按主线 FR-079 检查任务正文与闭环、真实依赖及导航一致，任务身份、原验收和完成事实保留；重复调用稳定。有依据的局部保留应可定位且说明继续条件，不将仅有推荐列表或局部受限记为全量重排完成。
8. **给定** 使用同版 Increment 规划或迁移闭环，**当** 核对文件产物，**则** 按主线 FR-080 检查唯一文件级链接、同级详情实际读取及旧引用保护，plan 无逐条 MVU 索引或 Task 范围列表，没有自动新增的整份方案快照；现有技术方案、任务及历史证据保留。
9. **给定** 规划生成、实际职责推进、闭环验收或阻塞条件变化，**当** 核对 MVU 状态及恢复，**则** 按主线 FR-081 记录五状态之一和依据，原四项详情保留；缺业务证据不能因任务全勾选标已通过，局部通过不能反向完成大 Task。独立材料覆盖五种状态及条件变化，旧证据保留、无新事实重复稳定，不用材料准备伪造真实用户行为。

### 用户故事 7 - 维护者通过流水线检查并发布技能版本（优先级：P1）

维护者希望将构建、流水线和技能发布部署作为同一交付链推进：技能及其构建依赖发生变更时，自动获得可追溯的检查结果和候选产物；确认具体版本后，由流水线发布同一份已验证文件，让外部使用者取得稳定、完整的安装来源。本版本完成后技能项目迁到独立公开仓库，后续开发和流水线在该仓库独立运行。

**优先级原因**：本次优先推进构建、流水线与技能发布部署的共同交付，从构建重做阶段同步验证整条交付链，减少手工拷贝和核对遗漏，让上线结果与已检查版本保持一致。任务按这条链的真实依赖重排，其他工作及原验收继续保留。

**独立测试**：当前版本在隔离执行环境中，从指定源码提交生成候选并验证；分别模拟未授权、检查失败、版本冲突、目标不可用、中断和并发重试，记录直接迁移所需文件和配置调整，独立运行在迁后真实仓库检查。迁移到独立公开仓库、真实目标就绪且获得发布授权后，在新仓库执行首次正式发布，核对远端全部公开文件，再从该来源验证主线curl入口；本地交付、隔离验证、远端发布成功、远端校验和独立使用者验收分别留证。

**验收场景**：

1. **给定** 影响技能、脚本或其构建依赖的变更，**当** 提交变更供审查或合入约定分支，**则** 自动执行适用工程检查并提供关联源码提交的结果；普通检查及外部贡献触发不得写公开仓库或取得发布凭据。
2. **给定** 检查通过且完整获准集合已就绪，**当** 准备候选，**则** 可在干净环境重建并核对同源两次构建的公开文件一致，候选包含安装所需技能、附件、脚本、根VERSION、说明和许可证，能搬离monorepo使用；检查记录留在流水线证据中，不以随包逐文件JSON为前置。
3. **给定** 已有候选但维护者未触发发布，或必需检查失败、未执行，**当** 检查流程结束，**则** 只报告检查与候选结果，不产生新的公开版本，也不把未验平台记为通过。
4. **给定** 有权维护者明确触发发布并指定源码提交、版本和已配置目标，**当** 流水线执行发布，**则** 重新核对授权范围及候选身份，将通过检查的同一份公开文件原样发布，报告源码提交及R2固定对象的HTTPS地址。
5. **给定** 包内VERSION或整包摘要与指定版本记录不匹配、目标未配置、发布凭据不可用或候选已失效，**当** 发布前置核验，**则** 发布失败且说明原因，已有公开版本保持可用，不将凭据写入日志或交付物。
6. **给定** 相同版本被重试或并发发布，**当** 比较候选与已公开内容，**则** 完全一致时可复用同一结果，不产生重复版本；内容不同则拒绝覆盖。中断留下的不完整材料不得作为完整可消费版本对外报告。
7. **给定** 发布步骤结束，**当** 进行远端核验，**则** 核对所选记录对应的固定统一包、同版入口及全部获准文件，并分别核查可变下载版本表和最新入口，并在隔离目标验证主线curl入口；若远端核验失败，报告已经发生的发布与尚未通过的验证，保留此前完整版本及重试条件。
8. **给定** 新版本出现问题，**当** 维护者决定使用先前完整版本，**则** 能找到其固定来源并重新验证安装；已公开版本不被改写或删除，已有用户安装仍遵循冲突保护，不强制降级覆盖。
9. **给定** 用户已直接将 skill、MCP 等源码及必要工程文件迁到独立公开仓库，并在新仓库完成依赖与配置调整，**当** 维护者在没有 Foundry 工作区的环境修改源码并运行流水线，**则** 仅凭新仓库自身的源码、配置、脚本和已声明依赖即可完成检查、构建和授权发布，无需 Foundry 提供工程导出或配置投影工具；供技能安装的发布根不因其他源码或测试材料迁入而扩大选择范围。
10. **给定** 技能项目尚未迁移，**当** 当前版本完成流水线隔离验证，**则** 保存验证结果、直接迁移的文件范围和迁后调整说明，不以生成工程包或项目索引作为交付前置；Foundry 不提前向真实公开目标发布，首次正式发布保留到迁移后的独立公开仓库，不能以模拟目标或本地候选抵扣远端验收。

### 边界情况

- 尚无独立 mvu 的原方案按主线兼容读取；只有 mvu 仍不能绕过缺 plan 的前置。状态依据缺失时明确待核实，不把隔离材料或旧完成任务当作当前闭环已通过；分发本轮撤回的身份和旧验收证据继续保护。
- 所选技能重复、名称与目录名不同、分类为空或包含未公开技能：按已核验统一包中技能声明的名称解析，重复名称去重；不扩大范围。
- 一个多技能请求只有部分技能完整安装：仅完整且通过核验的成功集合可进入隐匿和挂载；整体状态必须标为部分失败。
- 统一包和所选技能已通过核验，仅同包hidden模块缺件、接口不兼容或运行失败：保留成功安装，隐匿独立报告失败及重试条件；统一包自身失败时零安装，不保留已撤销的单独helper下载容错。
- 发布内容缺少引用材料、包含重名技能或依赖未选技能：在交付检查或安装核验时报告具体缺项，不让残缺内容参与挂载。
- 紧急版官方skills入口面对已有内容的行为不能靠本包改造；安装文档必须要求先核对冲突，不使用无条件覆盖选项，并在受控环境验证保护步骤。
- 技能安装目录属于不同来源、版本不同或安装后被用户编辑：首版默认拒绝自动替换；升级和迁移需用户先处理冲突再重试。
- `.git` 是文件的 worktree 或 submodule：与无 `.git` 区分。首版保守默认继续安装、明确跳过不受支持的隐匿，不猜测排除位置；扩展支持须在澄清时确认并验证共享排除的影响。
- 排除规则遇到空格、特殊字符、已有反向规则：按实际排除效果判断成功，不能只因追加文本成功就宣布隐藏成功。
- 下载材料或安装路径无法与所选版本对应、公共入口材料缺失：挂载失败并保留安装事实，不回退执行另一版本脚本。
- 同版本重试与中断后的部分结果：技能重验成功事实；所选适用 hooks 与 Increment 每次按来源经官方能力刷新，三个暂停入口不复活，不承诺跨文件原子回滚，不删除未知内容。
- 全局安装启用隐匿：项目外的技能文件报告隐匿不适用，不通过扩大排除范围隐藏；有显式项目时仅处理其内符合规则的本次文件。明确项目无 `.git` 时仍跳过，不向父目录查找。

- 旧安装含 Review/Guide/Explore 或被删除六技能时，仅按主线明确受管清单与官方能力迁移；未知文件、用户自维护内容与无关扩展保护，不能整目录 prune 或手改 registry。
- 实施准备 hook 登记或可加载不等于讨论门禁有效；本 Spec 不声称安装阶段已经执行实施前讨论。新入口可调用不等于行为通过；Linux 结果不推定 Windows/macOS、真实公开源或最低运行时通过。
- 三个暂停模式的来源可能仍在历史安装目录中：不得据此补装、重装或继续宣传为本期可用入口；是否交付及可发现按主线正式范围核对。其历史学习资料保留，不作为工程状态或本期必测项。
- 流水线遇到开发候选、缺许可证/附件、必需检查未执行或声明支持范围缺证据时，可以保留具体诊断，不能输出可发布结论或借自动化降低原验收要求。
- 来源提交、候选版本或公开目标在检查后发生变化时，原授权与检查不得套用到新内容；候选失效或超出授权范围须重新准备和确认，不临时重建另一份内容后直接上线。
- 同版本并发、发布中断或远端校验失败时，已有完整版本及固定地址保持可用；缺少公开仓库或凭据只阻止实际发布，不阻止无需凭据的本地检查与候选准备。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须向无 monorepo 环境的外部使用者交付完整技能目录及必要附件；交付范围须明确技能名称、来源分类、版本和必需文件，由流水线检查及其记录证明，不强制随包交付逐文件JSON清单。
- **FR-002**：本版本先在当前 Foundry 仓库实现并验证技能发布、安装及挂载能力；版本完成后由用户直接将 skill、MCP 等源码及必要的构建配置、脚本、测试、流水线和依赖声明迁到独立公开仓库，后续开发、构建和发布在新仓库进行。依赖与配置由新仓库维护，不依赖 Foundry 工作区，不提供自动工程导出、配置投影或项目迁移索引。源码迁移与安装发布物的文件集合分别限定范围，公开安装仍只交付获准内容且无需登录；主线发布文件由 Cloudflare R2 承载，源码仓库和文件下载根分别追溯，实际地址及映射后续确定。MCP 源码迁移不自动纳入其线上发布。本次规格更新不创建远端仓库、桶或执行迁移发布，也不要求当前 Foundry 仓库公开；紧急版来源约定不变。
- **FR-003**：首版正式技能发布与公开安装只包含coding、frontend、workflow三个分类及其必要附件，排除eval分类和评估样本。eval源码及样本允许随packages/skills迁入新的开源仓库，保留其维护、评估和测试复现用途；源码公开不等于纳入技能发布或承诺可安装。正式安装文档、预检和支持入口以获准技能发布物为安装来源，不把开源源码仓库根目录作为整包安装来源；针对正式来源的技能列出与选择均不得包含eval，显式请求eval分类或其技能时报告不属于可安装范围，不扩大安装集合。eval在当前仓库中的既有用途和消费方式保留。
- **FR-004**：主线只交付curl方式的自有安装流程，不再将官方npx skills add作为本期主线入口，也不要求双安装入口对比。install.sh的主流程为检查环境、取得依赖与统一包、整包完整性及根VERSION核验；结合本次选择完成正式安装、适用挂载、清理和结果报告。具体复用模块在实现方案中明确，不把额外安装器包或逐文件清单作为前置。安装结果必须与已核验同版统一包及候选中所选技能的完整正文和必要附件一致，不得用聚合文本代替完整目录。紧急版官方安装加显式挂载按FR-066单独验收。
- **FR-005**：主线curl入口必须支持整包、单分类、单技能、多技能四种粒度；选择技能与目标agent相互独立，不以安装全部后删除实现选择安装。紧急版仍按其既定范围执行。
- **FR-006**：主线不再提供官方skills命令构造、URL分类建议及官方--list等入口能力；可安装名称与范围由已核验统一包中的获准技能声明及正式发布范围确定，curl选择沿FR-007执行，必须排除eval及未获准内容，不能因取消官方入口放宽名称、依赖或完整性校验。
- **FR-007**：curl 安装器的外部选择约定为三者择一：`--all`、`--category <分类名>`、`--skill <名称...>`；`--skill` 可重复提供，合并后去重。缺少选择、混用选择方式、空值、未知名称或空分类必须明确报错，静态可确定的错误须在写入前发现，不退回全量安装。
- **FR-008**：技能间存在必须同时安装的依赖时，必须在选择检查中列出缺项并要求用户补充选择；不得静默补装。全部必要技能内部附件必须随该技能交付，不作为额外技能选择。hook配置的来源及同版公共材料按FR-020/049/055/064核验，不再将已删除的逐技能speckit-hooks.json作为固定附件前置。

- **挂载目标及结果**：具体项目、环境适用性、钩子与指令的独立结果和续接条件。
- **本地排除项**：本次内容的精确路径、实际排除来源及生效结果；与共享配置或既有跟踪状态区分。
