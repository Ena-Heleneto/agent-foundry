# 安装与公共入口契约

## 主线现行安装入口

使用者从公开 `curl/install.sh` 选择版本。入口核验选定的统一包、根 `VERSION` 及适用技能，按本次成功集合至多调用一次同包 `engine/install.sh`。引擎处理显式隐匿及适用挂载，`--no-mount` 关闭挂载。部分复制失败只处理本次已有成功项的隐匿，并返回原复制错误。主线正式包的入口和引擎路径沿当前 curl 契约，旧 `script/` 路径及 Node 调度对应各自历史验证。Windows 首次取得入口及从 PowerShell 到同版引擎的接线由 T019 实证。[curl 交付契约](curl-delivery.md#2026-11-23-公开入口与测试取件) · [挂载契约](mount.md#主线现行挂载入口)

## 2026-11-18 已核验脚本定位增量

主线统一包内安装入口和可选隐匿脚本目标为 `script/install.sh`、`script/hidden-install.sh`，本地构建对应 `dist/script/`。入口及调用方在整包可信后按该目标定位同版脚本，缺件按既有安装/hidden独立失败规则报告；不静默回退 `curl/` 旧路径、其他版本或未核验来源。远端最新入口及固定入口URL保持现有 curl 对象设计，不能由本地目录推导远端迁移。

本轮已从骨架继续迁移 hidden 构建逻辑；按用户后续纠正，安装入口读取及原字节交付由 curl 插件负责，输出仍在统一 script 目录，见[T077](../implementation/T077.md)；安装入口的实际消费、hidden调用及完整协议尚未接通，不由本地构建推定已可运行整个安装流程。根VERSION、轻量映射、来源标记及用户内容保护保持，下方历史命令不作为新消费链已接通的证据。

## 2026-11-16 当前主线适配

最新install.sh按一次固定的release.json记录下载一个统一包；新正式入口要求bytes/SHA-256，安全解包后核对根VERSION、映射和所选技能，才逐项安装。字段/参数与顺序见[curl契约](curl-delivery.md)，不另下helper，不要求随包文件JSON。数组记录与紧急旧schema1不可混用。

统一包下载/核验失败时零技能提交、零辅助执行；包已通过且技能完整时，后置hidden缺件/接口/执行失败独立报告并保留安装，取消旧“另一个包下载失败”的前提。选择/依赖、用户同名修改、tracked保护、同文件系统暂存及成功集合保持原目标。入口实际字节身份与所选技能版本分别记录，不能用latest查询证明已执行入口。

当前源码仍为占位地址、MD5、未固定node-jq和基础全量项目复制，hidden只解析，无根VERSION/成员安全/完整选择与报告；这些是待适配事实，不是本轮验证通过。固定临时依赖/缓存、在线Agent元数据和原Node/PowerShell/global目标保持，尚未支持参数在目标写入前明确拒绝，script/old不自动搬回。紧急版官方安装及显式第二步不变。

## 当前 curl 参数与临时依赖（2026-11-14）

依据[后续讨论](../requirements/discussions/2026-11-14-install-shell-flow.md#当前脚本参数版本表及依赖准备)，主线 curl 采用 `bash install.sh [version]`，首个参数省略时为 `latest`。当前获取的 `release.json` 是包含 `version`、`url` 的 JSON 数组，最新记录在首条，latest 取首条，明确版本必须唯一匹配；字段无效、空表、未知/重复的指定版本、非 HTTPS 或含空白控制字符的 URL 均失败，不回退其他版本。

curl/node/npm/uv 的基础检查之后，在用户目录下创建本次独占临时子目录并登记 EXIT 清理；npm 以非全局模式安装固定版本 jq 封装包到本次 deps，缓存放本次 npm-cache，通过完整路径调用，不修改全局 PATH 或目标项目。当前源码固定为 node-jq@6.3.1，不代表未来包版本永久不变；更换依赖版本仍须重新核验实际行为。

当前版本表只负责查地址，不替代包含文件大小和摘要的单版清单；旧单版清单也叫 release.json，两者名称和路径后续必须明确区分，不能套用同一 schema。latest 解析后，后续内容和挂载仍按选中具体版本固定，保留内容保护及完整性要求。

当前源脚本已完成临时依赖、版本表下载和 URL 解析，源脚本原样复制到 dist/curl/install.sh；固定源地址仍为占位，技能下载、文件核验、正式安装及挂载未接入。下方旧 Node 模块及参数契约保留其已有能力，尚未接通新 curl 位置参数；其中“版本必填、无 latest 默认”不再适用于当前 curl，不据该差异声称旧模块已经改造完成。本轮只同步文档，不改代码、规划或任务状态。

## 当前主线流程澄清（2026-11-14）

依据[用户原始输入](../requirements/raw/2026-11-14-install-shell-flow.md)和[讨论整理](../requirements/discussions/2026-11-14-install-shell-flow.md)，使用者执行 `install.sh` 时按“检查环境 → 下载依赖或者文件 → 完整性校验”理解主流程。结合既有选择和挂载要求，核验通过后安装本次所选内容、处理适用的隐匿及挂载，再清理和报告；不能用构建插件执行过程代替运行流程。

维护独立的 `install.source.sh`，构建原样交付到 `dist/curl/install.sh`；技能输出为平级的 `dist/skill/<集合>/<技能>/`。主线发布文件使用 Cloudflare R2，固定发布版本及源码追溯保持；实际 HTTPS 下载根和路径映射待确定。下文将主线来源限定为 GitHub raw URL 的模板不再作为主线现行地址要求；紧急版两步及其来源要求保持，旧官方主线入口仍按 2026-11-12 修订退出本期。

**版本需求补充**：按 [FR-068～070](../spec.md#当前追加需求本地产物版本r2-版本表与简易版本管理2026-11-14)，本地 skill/curl 只保存当前构建并各自标记版本；curl 交付已发布技能版本到 R2 固定地址的版本表。参数与表字段按上方最新约定，未知版本失败；后续取得对应内容及单版清单，版本标记与清单、内容版本一致，表不能代替文件完整性校验。持久来源、发布记录生成、技能内容及单版清单的实际映射仍待接通。

下载对象及完整运行材料须按当前流程确定，`installer.tar.gz` 和先交付 `dist/curl/script/` 是 Agent 提议而非用户确认。如何复用既有 Node 入口及平台模块尚未完成新方案讨论；既有 Node 入口与 `>=22.20.0` 检查未被本轮取消，但该版本尚未被证明为安装器技术最低版本，降低要求前须同步并验证。

下载阶段在使用者的用户目录下准备临时父目录，每次运行创建独占子目录；已有父目录可以使用，但不接管或清理旧残留。准备 npm 临时依赖后下载版本链接表 release.json，解析具体版本地址；后续再取得该版本的正文、附件和单版文件清单，并执行完整性校验。R2 必须事先提供真实表和获准内容的 HTTPS 访问；无需另写下载后端，当前本地产物不等于已经发布。

既有先暂存、校验后逐技能提交和用户文件保护继续有效。用户目录下的下载暂存与正式技能提交的暂存职责分开；后者仍满足与目标同文件系统约束，不能假定用户目录与安装目标之间可原子移动。失败只清理本次拥有的材料，不执行未核验的下载代码，不承诺跨阶段原子回滚；具体父目录名、清单路径适配及下载根仍待实现确定。

本节更新运行流程及已选交付方式，尚未确定的文件全集、清单和版本/路径适配不得按旧说明直接宣称可用；本轮不修改安装源码、任务状态或执行发布。

**本次构建重做的兼容边界（2026-11-10）**：保留两入口及平台运行实现，以新构建产物验证其实际消费。Release 继续 schemaVersion=1、既有字段与投影语义；内部构建类型不泄漏到安装参数。旧安装通过只描述当时实际范围，完整安装及多平台未完成项继续保留。构建、候选及返回值见 [build-pipeline.md](build-pipeline.md)，本轮不修改安装源码。

## 本包命令（既有 Node 接口，尚未对接当前 curl 参数）

发布根交付 script/index.mjs，使用者只运行 `node script/index.mjs [参数]`，不提供 install/mount/hooks/commands 子命令或另一组公开平台入口。Node ≥22.20.0 按操作系统调度对应内部安装模块；安装流程逐步接入核验、所选 hooks 和 Increment 模块。平台文件与同版必要材料一起交付，外部不需 monorepo、pnpm 或第三方 Node 运行依赖。当前已验证安装能力及未接通步骤必须在帮助中说明，不以统一入口存在冒认完整分发已交付。

| 参数                                          | 约定                                                               |
| --------------------------------------------- | ------------------------------------------------------------------ |
| --version <SemVer>                            | 自有技能发布版本必填，精确匹配 release.json；无 latest 默认        |
| --source <HTTPS 根 URL>                       | 指向公开仓库固定完整提交，不接受滚动分支；与 source-dir 二选一     |
| --source-dir <绝对目录>                       | 本地导出产物验证；与 source 互斥，不宣称远端已通过                 |
| --all / --category <name> / --skill <name...> | 必须三选一，skill 可重复、合并去重；不隐含全量                     |
| --agent <id>                                  | 必填且每次一个；取本次在线解析版本的支持清单，不自动选择全部 agent |
| --global                                      | 默认关闭；不支持该 scope 的 agent 在写入前拒绝                     |
| --project <绝对路径>                          | 全局挂载项目；项目级安装始终 cwd，传入时必须等于 cwd               |
| --hidden                                      | 仅 install，默认关闭；不传给官方 CLI                               |
| --no-mount                                    | 仅 install，关闭后续挂载；不含 workflow 时自然跳过                 |
| --check --official                            | install 的只读官方预检模式；不写目标、不执行 npx                   |
| --installed-root <绝对路径>                   | 仅内部核验模块使用；公开入口按 agent/scope 推导，不要求用户填写    |
| --report <绝对路径>                           | 可选报告文件，存在则拒绝覆盖；stdout 始终有结构化报告              |

version必填，且source与source-dir必须且只能提供一个；这三项检查也适用于--check --official。缺version、两种来源均缺失或同时提供、版本不匹配，均按参数或静态前提错误退出2且目标零写入。无选择、混用、空值、未知名、eval、空分类、缺依赖、版本和路径静态错误在目标写入前失败。没有项目的全局 workflow 安装本身可以成功，默认挂载随后报缺项目；不能把它提早变成安装失败。只读检查不会创建锁、收据或暂存下载文件（远端清单可读取到内存）。

## 内容获取及保护

引导脚本与清单均取固定提交；脚本检查所需平台工具、下载对应 script 运行材料并核验摘要，再按各平台入口已验证的前置条件启动；不得恢复嵌套 package.json 作为未经确认的前置设计。拒绝非 HTTPS 来源、不完整下载、重定向至非 HTTPS、越界路径与校验不符；网络超时、权限失败给出具体步骤。每个工具仅执行同 catalogDigest 材料，不回退另一版本。

curl 将所选文件写入同文件系统暂存目录，全部摘要通过后逐技能提交。根锁避免两个本包进程同时修改，失效锁不自动删除；目标为空才新建，归属收据及实际内容完全匹配才复用。未知目录、用户编辑、不同版本、Git 已跟踪文件均拒绝，保留其他技能。跟踪冲突检查可只读发现所属仓库；只有隐匿禁止向上查找/写入父仓库。保留完整成功项，清理仅限本进程可证明拥有的暂存内容。

## 官方入口的第一步

用户先对同版本同选择运行只读预检。通过后自行运行原生命令；预检输出准确 URL、agent、scope、选择及目标，已满足则建议跳过。发布README分别给出Bash/PowerShell的RELEASE_SOURCE赋值、未赋值即停止及固定提交HTTPS URL校验步骤，取得发布者提供的真实来源后才能运行；具体值与展开后的实测命令记在发布根外的来源说明。官方命令模板如下，仅示意，不是可直接运行的公开地址：

两入口共享仓库与完整发布 SHA，URL 形式分别定义：本包 `--source` 和 RELEASE_SOURCE 使用 `https://raw.githubusercontent.com/<owner>/<repo>/<发布SHA>` 作为文件下载根；官方目录安装使用 `https://github.com/<owner>/<repo>/tree/<同一发布SHA>/skills`，分类或单技能在其后追加对应目录。原始文件下载根不能直接交给官方目录安装。远端预检须将已核验的 raw 来源转换为同仓库同 SHA 的 tree 目录 URL，不能转换的来源明确拒绝提供建议；本地 source-dir 继续使用真实目录。此映射及远端实测仍待实施，不以本次源码调查宣称通过，详见 [流水线来源契约](pipeline.md)。

```text
npx skills@<本次预检解析版本> add <固定提交的skills目录treeURL> --skill <本次已核验名称列表> --agent <id> --copy
npx skills@<本次预检解析版本> add <固定提交的skills/frontend目录URL> --skill <本次已核验名称列表> --agent <id> --copy
npx skills@<本次预检解析版本> add <固定提交的单技能目录URL> --skill <声明name> --agent <id> --copy
npx skills@<本次预检解析版本> add <固定提交的skills目录treeURL> --skill <name1> <name2> --agent <id> --copy
npx skills@<本次预检解析版本> add <固定提交的分类目录URL> --list
```

全局安装额外传官方 `--global`。不使用官方 `--all` 代替技能全选，不传 hidden/no-mount 等本包参数。拒绝额外推荐技能的安装提示，避免超出选择。只读预检无法锁住上游进程，执行窗口禁止并发编辑；未使用预检的裸命令不在本包冲突保护承诺内。原生 symlink/default 等行为仍归上游，第二步按实际路径校验。

官方列出/建议命令中的公开名称应与本次获准清单一致；三个暂停模式不作为本期可用入口宣传，六退役技能不留有效映射。来源复制、公开文件选择和实际挂载分别核验；不借模式暂停改变其他技能的安装语义。

## 显式第二步与返回

官方安装后的第二步仍调用同一个 Node 入口，提供同版来源、完整选择、agent、scope 和适用项目；安装根由内部推导并交给核验模块，用户不指定 mount 操作或 installed-root。内部逐项核对实际文件全集及 agent 投影，再处理本次已核验 workflow 映射；这项官方安装事实复用与编排仍由后续任务接通，不因已有同名目录而绕过冲突保护。历史文件可作为本次显式选择的核验对象，但不得自行扩大集合。命令挂载仅需本次显式选择并完整核验 task-increment，不要求三个暂停模式；无选择为不适用，自身缺项失败，不补装其他技能。准备 skill/hook 仅按所选范围同版核验与接入；bug-report 无命令映射。公共运行材料单独获取，不假定单技能会带整个安装器。

curl 复用同一个 mount 实现，传递本次成功集合和版本证据；公共入口仍重验，不能信任内部调用参数。安装/隐匿/hooks/commands 独立报告，结构见 [数据模型](../data-model.md)。退出码 0 表示没有请求步骤失败，2 表示参数或静态前提失败，1 表示运行失败或部分成功；细节由 reasonCode 区分，不能用单个退出码代表所有技能成功。

实际接通前仍按当前脚本明确 unsupported/failed，不把统一 Node 入口当作自动挂载已实现。两入口都须按挂载契约先处理未知受管内容，禁止在官方更新前丢失用户附件；加载验证不发起业务实现。

隐匿先处理成功技能路径，挂载后再处理新增独占路径；两次合并成 hidden 阶段报告。隐匿失败不阻止适用挂载，hooks 失败必须阻止 commands。重试仍使用唯一 Node 入口及同版参数，由内部逐项重验并复用成功事实。

技能安装中的“已满足复用”不适用于命令挂载：条件齐备后每次调用既有脚本，以官方 --force 重装仅含 Increment 的 modes。模式受管内容由来源刷新，其他技能与无关配置保留。详细名称与独立脚本参数见 [挂载契约](mount.md)。

## 2026-11-04 手动与自动入口

官方 skills 方式保持两步：npx skills 只安装所选技能；用户取得同版运行材料后手动执行唯一 Node 入口，自动选择平台模块并核验实际安装事实，再处理适用挂载。该编排尚待后续任务接通；技能目录内的 package.json 不会被 skills 自动安装，单技能安装也不会自动取得发布根的 script。

curl 方式自动取得并验证运行材料、准备自身依赖、安装所选技能，然后按既有选择执行挂载；不要求用户另行运行挂载脚本，--no-mount 保留。两方式复用同一套依赖准备与挂载逻辑；依赖放在工具独立运行目录，不修改目标项目的 package.json 或 node_modules。依赖准备失败时停止后续步骤并报告具体原因。--check --official 仍只读，运行依赖须事先就绪，缺失时报告准备步骤，不在只读预检中下载或安装。

## Agent 在线来源

安装或官方预检每次在线解析 skills 的 npm latest，使用同一发布包的 Agent 路径规则；不固定版本、提交或数量；来源直接定义于 script/install-skills/read-agents.mjs，不维护 packages/skills/distribution、agents.json 或替代声明。官方建议中 skills@后面的实际版本来自该次解析，用户按报告原样执行；后续调用重新获取。上述原生命令仅为模板，实际 all/category 建议显式列出所选名称，避免星号扩大到未检查的内容。预检不启动 npx，不写缓存、锁、收据或暂存；网络/完整性/布局失败退出2且目标零写入，不回退旧表。本地 source-dir 也必须在线查询 Agent 规则；不存在离线静态表回退。元数据、官方 HTTPS 包地址、SHA-512 integrity、包内版本及规则布局均须通过校验，读取器不执行 CLI 入口或安装代码。所需 Node、tar 和平台工具须提前具备。自有技能的 version 与不可变发布来源不受此 Agent 数据策略影响。
