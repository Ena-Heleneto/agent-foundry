## 按需取得完整公开技能

既有任务[T094](../../tasks.md#t094)承接SourceVersions与已核验发布记录，避免把旧完成T010重新打开。统一源版本沿package.json，根VERSION由已有版本插件派生，dist外单份releases/releases.json记录和下载表沿当前模型；[T069](../../tasks.md#t069)派生构建材料，[T017](../../tasks.md#t017)固定一次调用的索引及关联。辅助脚本注入的路径也是生成输入，字节变化就必须递增整体发布版本，不可覆写旧关联。数组release.json负责发现，整包bytes/SHA、根VERSION及formatVersion=1核验负责固定统一包消费；逐文件证据在流水线包外。主线统一格式与紧急旧schema1显式分开，不恢复随包release-manifest.json。

原MVU-005/002把版本材料交给实际消费验证：清理dist仍保留历史记录；用新入口消费两版技能时分别取得其固定统一包及同包hidden；仅构建、上传或核验失败不能登记成功。这些是设计与任务，不是实际发布结果。跨版本技术前置在[T016](../../tasks.md#t016)与T094中证伪，正式登记仅在[T056](../../tasks.md#t056)/[T062](../../tasks.md#t062)对应实际核验成功之后。字段和固定对象边界统一阅读当前契约，不再维护另一份schema。

## 安全下载安装与失败续接

使用者得到的不只是命令退出码，还要知道哪些技能真正完整安装、哪些失败或未执行。下载、依赖和包核验在本次私有临时目录中进行；正式提交的暂存须与目标同文件系统。未知同名、不同版本、用户修改或已跟踪目标拒绝覆盖，部分成功不能把残缺目录记为已安装。

当前install.source.sh已有基础版本表/MD5、tar及项目级复制，固定下载根仍是占位，node-jq未固定，没有新辅助协议或完整阶段报告；此事实不能被旧Node入口证据覆盖。[T016](../../tasks.md#t016)先验证HTTPS/摘要/接口及恶意成员反例，[T017](../../tasks.md#t017)接获取核验，[T018](../../tasks.md#t018)处理逐技能提交与成功集合，[T019](../../tasks.md#t019)保留选择/平台目标，[T020](../../tasks.md#t020)报告实际阶段，[T021](../../tasks.md#t021)留真实消费和恢复证据。T070在实际安装之后复核，不再让T012反向等待消费者。

统一包下载、长度/SHA、成员安全或根VERSION失败时零技能提交、零辅助执行。只有包已可信且所选技能完整时，同包hidden模块缺件/协议/执行失败才保留安装，报告“安装成功、隐匿失败”、overall=partial且非零；技能部分成功仍保留逐项失败，不能改报安装成功。原MVU-002的局部里程碑是完整可用技能及可操作重试说明；原三平台/动态agent/global、最低运行时和真实R2分别需要证据，局部Linux结果不能替它们通过。操作与样本矩阵见[验证指南](../../quickstart.md)，依赖转接见[流转图](flows.md)。

首次安装由最新install.sh启动；后置Node公共入口承担原挂载与平台调度，不能据旧入口证据宣称首次下载已经三平台可用。T019在原方案核对Windows首次获取和内部平台接线，未执行路径继续列未验。T069的TSV与获准目录双向对应，不执行包内TS；T018在暂存时写入最小.foundry-source来源标记，清理后新进程重试同时核对来源标记与可信包正文附件全集，缺标记、不同版/来源、额外用户文件保持冲突。新数据、标记及反例已落到原任务，不代表源码已有实现。

## 同包辅助脚本与可选精确隐匿

维护者能检查技能与脚本目录，流水线再将获准内容归档为一个包；使用者只有显式hidden时才调用同包隐匿模块。发布前缺必需脚本不能放行，运行时未核验或未知协议代码绝不执行；隐匿失败保留成功安装，不将整个agent根或共享文件隐藏。

本轮Tasks生成时，hidden模板仍位于curl插件目录，已有逐行Bash生成、占位符、本地Git及排除基础逻辑；用户明确授权将其原字节移至 `build/plugins/vite-plugin-script/hidden-install.template.ts`，技能扫描与hidden脚本生成由该插件负责。用户后续明确安装入口构建留在 curl：该插件读取 `vite-plugin-curl/install.source.sh`，原字节交付 `dist/script/install.sh`；script 只派生 `dist/script/hidden-install.sh`。输出目录统一不等于所有脚本由同一插件生成，每项资产只能emit一次。模板移动与必要构建接线是原T077的局部工作，实际结果沿该Task方案核对，不由任务生成或分析保存推定完成。旧.sh路径只剩.gitkeep不代表没有隐匿实现。[T033](../../tasks.md#t033)复用[T007](../../tasks.md#t007)真实Git边界而非新建测试专用原型，[T034](../../tasks.md#t034)复用现有模板补齐成功集合与结果协议，由[T077](../../tasks.md#t077)承接script插件、迁移后的模板接线和路径注入，只生成独立Bash内容；[T069](../../tasks.md#t069)将获准路径、映射、附件和许可校验后归入统一包，不生成辅助manifest或第二归档。模板已有生成基础，安装调用和成功集合协议仍未接通；不重复版本插件或恢复旧.sh源。原入口保持原字节，派生辅助模板的路径数据是明确例外；无状态scanSkills可共用，不能靠插件执行偶然顺序或共享可变context同步。

[T035](../../tasks.md#t035)等待真实安装及归档，将本次installed/reused完整集合交给已核验脚本，处理模板候选、选择、成功集合的交集；[T036](../../tasks.md#t036)验证真实用户流程及支持边界，挂载后独占路径另由[T028](../../tasks.md#t028)补集成。原MVU-004在这里从Git边界走向真实材料消费：check-ignore、索引和status证明精确效果，未选和失败项仍可见，重复规则为零；无Git、父仓库子目录、.git文件及项目外global路径按约定跳过或报告限制。技术数据流统一见[归档与隐匿技术图](../../diagrams.md)，不在分析再复制一套。
