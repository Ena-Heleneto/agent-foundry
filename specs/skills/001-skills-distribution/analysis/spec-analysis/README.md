## 按需取得完整公开技能

外部用户希望选一个技能时只取得它与必要附件，选分类或整包时也不夹带未公开材料。正式选择范围仍为coding/frontend/workflow；eval评估源码可存在于开源项目，本地profile集合也不能因启用就自动成为获准发布内容。无选择、互斥选择、未知名称、缺依赖都须明确拒绝或要求补选，不能默认为全量。

技术上，现有vite-plugin-skill调用scanSkills读取TS集合配置，再复制启用正文与附件并生成dist/skill/skill.tar.gz。旧JSON描述及enabled字段变化未在本轮实施验收；[T076](../../tasks.md#t076)先核对当前代码/认可及完整性，保持既有用户手写。正式发布映射与schema2清单由[T069](../../tasks.md#t069)形成，[T012](../../tasks.md#t012)核对完整来源及四种选择，原T010/T011只保留旧模型/路径证据，不能重开为新协议完成事实。

此功能以原MVU-001/008衔接：先得到完整可检查内容，再让下载安装器消费。独立可观察里程碑是正文/普通及二进制附件与正式文件表完全一致、未选新增为零。已有[内容导出实验](../acceptance/content-export.md)及[旧集合证据](../acceptance/plugin-skill-config.md)只支持其当时输入；本轮未重跑新交付。业务入口见[用户流程](flows.md)，实际构建及安装映射沿[技术图](../../diagrams.md)和[依赖图](../../diagrams/logic-flow.md)阅读。

## 统一发布版本、最新入口与固定辅助包

用户最新确认[统一版本](../../requirements/raw/2026-11-16-unified-release-version.md)：技能、入口及辅助包同次发布共用package.json.version，install始终最新，辅助包必须与所选技能版本同版。因此“使用最新入口”不等于把历史技能的所有运行材料升级到最新；使用者应能分别核查入口、技能和辅助包的版本及来源。

共享新任务[T094](../../tasks.md#t094)承接SourceVersions与已核验发布记录，避免把旧完成T010重新打开。统一源版本沿package.json，dist外skills/curl记录、构建标记及版本表由新模型定义；[T069](../../tasks.md#t069)派生构建材料，[T017](../../tasks.md#t017)固定一次调用的索引及关联。辅助脚本注入的路径也是生成输入，字节变化就必须递增整体发布版本，不可覆写旧关联。数组release.json负责发现，release-manifest.json负责单版完整性；新schema2和紧急旧schema1显式分开。

原MVU-005/002把版本材料交给实际消费验证：清理dist仍保留历史记录；用新入口安装两版技能时分别取到各自固定helper；仅构建、上传或核验失败不能登记成功。这些是设计与任务，不是实际发布结果。跨版本技术前置在[T016](../../tasks.md#t016)与T094中证伪，正式登记仅在[T056](../../tasks.md#t056)/[T062](../../tasks.md#t062)对应实际核验成功之后。字段和固定对象边界统一阅读当前契约，不再维护另一份schema。

## 安全下载安装与失败续接

使用者得到的不只是命令退出码，还要知道哪些技能真正完整安装、哪些失败或未执行。下载、依赖和包核验在本次私有临时目录中进行；正式提交的暂存须与目标同文件系统。未知同名、不同版本、用户修改或已跟踪目标拒绝覆盖，部分成功不能把残缺目录记为已安装。

当前install.source.sh已有基础版本表/MD5、tar及项目级复制，固定下载根仍是占位，node-jq未固定，没有新辅助协议或完整阶段报告；此事实不能被旧Node入口证据覆盖。[T016](../../tasks.md#t016)先验证HTTPS/摘要/接口及恶意成员反例，[T017](../../tasks.md#t017)接获取核验，[T018](../../tasks.md#t018)处理逐技能提交与成功集合，[T019](../../tasks.md#t019)保留选择/平台目标，[T020](../../tasks.md#t020)报告实际阶段，[T021](../../tasks.md#t021)留真实消费和恢复证据。T070在实际安装之后复核，不再让T012反向等待消费者。

仅hidden辅助包失败是独立失败：已核验技能继续安装，实际成功后报告“安装成功、隐匿失败”、overall=partial且非零；技能自身失败仍不得报成功。原MVU-002的局部里程碑是完整可用技能及可操作重试说明；原三平台/动态agent/global、最低运行时和真实R2分别需要证据，局部Linux结果不能替它们通过。操作与样本矩阵见[验证指南](../../quickstart.md)，依赖转接见[流转图](flows.md)。

## 可检查辅助归档与可选精确隐匿

维护者需要能检查脚本目录，也需要压缩包供外部独立取得；使用者只有显式hidden时才需要隐匿行为。目录/归档同源同全集，缺件不构建成功，未核验代码绝不执行；隐匿失败保留安装，不将整个agent根或共享文件隐藏。

本轮重新核对后，实际hidden源是curl插件的hidden-install.template.ts；已有逐行Bash生成、占位符、本地Git及排除基础逻辑。旧.sh路径只剩.gitkeep不代表没有隐匿实现。[T033](../../tasks.md#t033)复用[T007](../../tasks.md#t007)真实Git边界而非新建测试专用原型，[T034](../../tasks.md#t034)复用现有模板补齐成功集合与结果协议，由[T077](../../tasks.md#t077)复用现有模板接线、路径注入及curl/scripts.tar.gz归档，再补正式校验与manifest。模板已生成独立Bash产物并归档，安装调用和成功集合协议仍未接通；不重复基础打包或恢复旧.sh源。原入口保持原字节，派生辅助模板的路径数据是明确例外；无状态scanSkills可共用，不能靠插件执行偶然顺序或共享可变context同步。

[T035](../../tasks.md#t035)等待真实安装及归档，将本次installed/reused完整集合交给已核验脚本，处理模板候选、选择、成功集合的交集；[T036](../../tasks.md#t036)验证真实用户流程及支持边界，挂载后独占路径另由[T028](../../tasks.md#t028)补集成。原MVU-004在这里从Git边界走向真实材料消费：check-ignore、索引和status证明精确效果，未选和失败项仍可见，重复规则为零；无Git、父仓库子目录、.git文件及项目外global路径按约定跳过或报告限制。技术数据流统一见[归档与隐匿技术图](../../diagrams.md)，不在分析再复制一套。
