## 审查、修正与边界

第一次运行在隔离 Git 初始化遇 spawnSync EPERM，按权限规则在沙箱外重跑后取得真实产品红灯。最初默认 Vite 配置打包器会在链接 node_modules 的 .vite-temp 写临时配置；最终使用真实 Vite runner，缓存设在自有临时根，仍运行同一有效配置。

只读独立审查提出3项 Important，均在本轮测试代码及方案中修正：

1. 零调用不能只拦 specify/uv/uvx：在临时材料的 register-hooks/register-commands 子模块路径增加直接调用哨兵；被测公共入口保持本次真实构建字节，禁止的下游调用由探针观察，不伪造公共占位实现。
2. generateBundle/writeBundle 时序不可靠：撤回该注入方式，改为真实阶段输出完成后注入，再调用真实复核；没有给生产新增测试 hook，也不冻结阶段属于哪个 Vite 钩子。
3. 只比对几个脚本会漏交附件/README：改为来源脚本全集和字节比较，并核对适用脚本全集进入 Release.files。

另外修正了测试期望本身：Eve 使用独立手写完整字面量；重复身份反例保留完整附件，非法版本只改 version；越界引用指向真实存在的测试自有哨兵，并保护其字节。没有为让测试变绿修改任何产品代码。审查后不重复派审；完整25项仍红，以上修正属于测试结构和断言的修正，不冒称新生产行为已经通过。
