**总体方案**：在 `build/plugins/vite-plugin-engine/index.ts` 导出异步工厂，配置加载时扫描 `src/*/plugins/vite-plugin-*/index.ts`；默认来源锚定该包的 `src/`，允许传入绝对来源目录用于隔离验证。只发现固定深度的普通目录与普通入口，不跟随符号链接，按集合名、插件目录名排序后顺序导入并调用默认导出的无参工厂。工厂返回 Vite `PluginOption`，引擎返回 `Promise<PluginOption[]>`；Promise、嵌套数组和 false 等值交由 Vite 原生处理，引擎不手工运行钩子或维护共享上下文。不存在子插件目录或匹配入口时该集合贡献空数组；真实读取、导入、非函数默认导出或工厂执行失败时带入口定位报错，停止配置加载。

**完整目标与本轮实现边界**：未来 workflow 子插件生成一个自包含的 `script/speckit-mount.sh`，先只含 Increment；hidden 的扫描、模板与生成逻辑回迁 curl，curl 交付安装入口及 hidden，移除旧 script 插件。所有运行资产仍在 `dist/script/`。本轮主代理仅按已确认方向新增引擎发现/加载能力；Speckit 子插件、生成 sh、curl 回迁及配置接线均不因本次规划被记为已实现。引擎发现不读取 `collection.config.ts`，不受 `script` 或技能启用配置控制。

**技术背景与必要前置**：沿用 ESM、严格 TypeScript、Node 内置 fs/path/url 与已装 Vite 8.3.8，不新增依赖；现场 Node 为 24.22.2、pnpm 为 12.16.1。已有集合扫描已使用动态导入 `.ts`，已装 Vite 的 `PluginOption` 与配置解析源码支持异步及嵌套数组；最低 Node 22.20.0 本轮未独立实测。固定入口约定、返回类型与失败边界见[构建契约](contracts/build-pipeline.md)，依据和替代方案见[研究](research.md)。动态导入失败、错误默认导出、工厂抛错及真实 Vite 消费由隔离夹具验证，未通过前不依赖引擎继续生成业务脚本；验证不运行真实挂载。

**Phase 1 与宪章复核**：增量同步研究、模型、构建/curl 契约、指南、同级闭环及技术图，保留既有正文和证据。复用下方唯一同级闭环文件入口，不新增业务身份、任务或 checkbox；本轮未执行 Tasks，不改其依赖、完成事实及原认可。工程检查按本轮实际实现范围执行，正式过滤、统一归档、安装保护、真实挂载和紧急版原范围仍须各自验收。需求已确认、实现授权限定引擎新增，Phase 0/1 未发现未解决设计选项或需豁免的宪章冲突；本节优先于下方旧插件归属目标，历史阶段记录保留。

### 总体方案与推荐顺序

先核对现有内容构建和根版本，保留用户手写插件；补齐发布前来源与完整性检查，再由流水线一次归档。当前开发dist不能直接递归压缩为正式包。包名采用skills-<version>.tar.gz，根布局保留VERSION、skill/、script/、curl/非脚本数据、README及许可；这是本次规划选择，非新增用户原话，也不是已生成产物。

随后接版本记录投影、固定一次调用的下载/摘要、安全解包和选择验证，再做目标同文件系统暂存、最小来源标记、提交与中断恢复；首次清理后的独立重试同时验证来源版本和完整字节，不认领未知同名内容。隐匿先以真实模板和自有Git验证成功集合协议，后接实际安装结果；仅对模板候选、本次选择和完整成功集合的交集操作。轻量技能映射是非执行数据，不恢复逐文件JSON。

本地统一包与安装/hidden验证后，汇合只读Actions、候选平台绑定、发布故障隔离实验和后置真实挂载。固定对象核验后先受控持久回存整版记录，再按“兼容入口→版本表”分别条件更新；无持久保存或适用授权时不推进发现，旧候选重试不回退latest，竞争不盲写其他版本。主线正式R2发布仍等待迁后独立检查、完整门禁、实际目标及具体候选授权；这些条件不冻结不依赖它的本地验证。首次没有真实历史发布时只用隔离多版本材料验证兼容机制，不冒认真实历史复验。

主线packages/skills保持用户主写，AI按每轮明确请求完成局部工作。紧急packages/skills-distribution-urgent保持自身schema1、Git固定来源与Linux/Codex项目级官方安装加显式挂载；T090已有4f7b331迁后候选和当时133/133证据，本轮未重跑。其下一步仍是具体候选发布授权、匿名公开消费与汇总；主线规划不改候选、不代发、不回退迁仓事实。

## 总体架构：一条链，逐步返回结果

**适用范围修正（2026-11-11）**：本节及下方原重做边界、推荐顺序中的旧三目录、BaseBuildPlan和MCP清单算法保留为旧重规划参考。当前主线遵循FR-048～060的集合来源、独立插件及空MCP目录；T068～T070执行前须按现有方案核对适用内容，不直接恢复已归档模型或提前决定T077。主线任务身份、顺序和用户手写分工保留；紧急副本只按上方增量及其契约实施，不将这些旧算法当作前置。

`读取来源 → 形成构建计划 → 写出并复核 → 准备候选 → 绑定平台归档 → 发布已验字节 → 只读远端核验`。

这是构建/CI 的内部阶段，不是新增终端用户命令。每个阶段只消费前一步已核验结果；失败抛出带阶段和原因的错误，外层报告 failed，并将依赖阶段标为 not-run。数据模型见 [data-model.md](data-model.md)，完整输入和返回契约见 [contracts/build-pipeline.md](contracts/build-pipeline.md)。

1. 来源读取固定实际技能、MCP、脚本及依赖证据，构建前拒绝链接、身份冲突、非法路径和缺必需材料。普通开发输入与干净提交候选分开；未提交字节不得冒认指定提交。
2. 内存中产生目标路径和内容；构建计划不写文件。T067/T068先验证的BaseBuildPlan/BaseBuildOutput只是原始三目录/MCP中间结果；T069补齐完整BuildPlan并校验后，才写出完整BuildOutput。单一有序编排负责三目录、MCP 清单、Release 和两种安装格式，避免多个独立钩子靠偶然顺序覆盖输出。
3. 从实际磁盘重新核验产物，不只比较内存计划。脚本与附件按原始字节交付，清单及格式转换按既定规则生成，源内手写 MCP 清单失败。
4. 全量 dist 与公开 payload 分开。payload 精确等于 release.json.files 加 release.json，额外文件也失败；candidate须显式选isolated/full，准入表见[pipeline契约](contracts/pipeline.md#候选范围与准入条件)。isolated只允许列明的局部来源和未执行完整门禁，不豁免严格字节/附件/README/许可证检查；full须全部内容门禁通过，上传前仍无ready。Foundry始终仅隔离用途。
5. 上传前固定内容索引；上传成功后把真实 artifact ID 与内容摘要绑定成独立平台收据。最终 CandidateResult 结合内容索引和收据，才判断正式资格；本地 isolated 材料不会升级为真实平台。
6. 发布只读取可信固定版本的工具和已核验候选，不安装依赖、不构建、不执行候选脚本、不回写 README。只读复验核对远端全部文件和实际主线curl入口结果。
