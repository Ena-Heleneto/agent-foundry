## 一、当前模式与实施入口

Pair、Tutor、Direct 的研发在工作流基座暂停，并从当前测试、移交和结案范围移出。本 Spec 同步停止三种模式的挂载、注册、重装和专项行为验收；保留来源与历史材料，不把暂停写成通过，也不以本需求永久删除模式源码。

当前保留 Increment 作为 MVU 规划入口。工程实施优先使用 Spec Kit 原生 Implement，通过工作流基座交付的同一个实施准备 skill 和官方已有 before_implement hook，完成实施前讨论、方案确认与恢复。Implement 是原生入口，不再包装成一个新的 modes 指令。

“宪章＋共用实施准备 skill”是已选择的方案；具体 skill 名称与附件以工作流基座正式交付为准，分发侧不另造一套讨论或执行逻辑，不把工作流规则写入 AGENTS、CLAUDE 等项目级规范。

## 二、挂载脚本需要修改的行为

1. 从受管 modes 生成、注册、补齐、完整性检查、重试和文档命令示例中移除 task-pair、task-tutor、task-direct 及对应 speckit-modes-pair、speckit-modes-tutor、speckit-modes-direct。
2. 删除“四项齐备才能挂载”“每次强制重装四项”的活动前置；安装或挂载 Increment 不再等待三种暂停模式的来源。对剩余入口仍核对本次选择、实际正文、附件和版本，不用历史安装冒充本次核验。
3. 所选适用 hooks 仍先核验、安装；成功或明确不适用后才处理剩余命令。实施准备 skill 与 before_implement 声明同版交付，复用已有 hooks-only 官方安装能力；不新增公开子命令、包根扩展声明、自有 YAML 合并或 registry 手改。
4. 同步实际参与挂载的 Bash、PowerShell、公共入口、官方安装后第二步及工作区集成调用。先读取实际代码和调用链，不凭旧文件清单臆造待改路径；仅在调用确实涉及三模式时修改。
5. 若历史 modes 扩展已生成三种模式入口，核实官方 CLI 缩减命令集合后的实际去留。需要迁移时采用官方支持的受管扩展更新/移除方式，并保护无关扩展、用户维护内容和历史证据；仅改脚本列表不能宣称旧入口已清理。
6. 官方 skills 文件安装与本包挂载继续区分。移除三模式的挂载映射不自动授权改变其他技能的整包、分类、单选、多选安装语义，或删除已有源码。暂停来源的交付和公开可发现性依主线当前正式规则说明，不继续宣传它们是本期可用的工作流模式。
7. 缺少本次所选必需来源、附件、目标项目或兼容条件时，按既有原则报告具体失败与已完成部分；失败后不进入依赖的后续阶段。旧三模式不再是必需来源，也不作为失败/未验阻塞项。

## 三、测试范围与恢复保护

删除当前活动矩阵中的三模式入口行为、角色切换、Tutor 学习/报告、Direct 真实业务协作及三模式同版消费要求，相关未完成任务标注暂停/移出本期，不继续作为整体交付必须补测的条件。旧任务身份、checkbox、历史运行结果与未实现事实保留。

旧项目移除三个受管入口的验证属于本次挂载迁移核对，不要求重新实施或验收三模式能力。当前至少覆盖：只选 Increment 即可按条件挂载；缺三模式来源不阻塞；三暂停入口不再生成/重装；历史受管入口的实际处理；重复挂载不复活；所选 hook 同版安装与缺项失败；无关内容保护；官方入口与下载入口的相同版本消费；未执行平台如实报告。

Implement 讨论行为由工作流基座负责；本 Spec 验证完整文件、附件、官方 hook 注册及实际可加载的消费结果，不在安装阶段实际发起业务实现。保留通用安装、隐匿、支持矩阵、候选、流水线、授权发布与真实独立使用者的必要验收，不能借暂停三模式缩减无关工程质量要求。

## 四、材料与双 Spec 移交

同步本 Spec 的 spec、plan、mvu、tasks、契约、验证指南、README/示例、构建清单与受影响测试。原生任务主文件保持原位；旧四模式描述需要明确替代，不只追加一个说明而让执行正文继续要求四项齐备。

保留当前其他会话的改动和已确认的直接源码迁移决定。先基于实际现状规划受影响未完成工作，再实施；已完成任务不重开，旧证据不改写为新行为通过。工作流基座移交同版技能与 hook，分发侧取得实际消费证据后回链，双方不自动互相勾选，也不形成对暂停模式的循环依赖。

这份提示词明确后续修改要求，本轮保存不代表挂载脚本已经修改、旧项目入口已经移除、公开发布已经发生，亦不新增迁移用户目录、远端发布或其他外部写入授权。
