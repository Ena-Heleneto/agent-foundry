# Issue 描述：技能发布、选择安装与工作流挂载

由 `artifact-issue-description` 于 2026-11-02 补执行此前挂起的 after_specify 钩子，首次生成原始意图快照；来源为 [spec.md](../spec.md) 的原始目标与用户场景。此前尚未生成快照，本文件不冒充澄清前已保存的历史记录；本轮确认的范围见 [澄清后需求描述](pr-description.md)，后续不自动更新本快照。

## 背景与痛点

当前技能主要在 Foundry 工作区内部使用。外部用户即使只需要一个技能，也缺少明确的公开获取方式；现有文本清单还不足以保证技能引用的资料和脚本一并交付。

希望把技能及必要材料交付给没有本工作区开发环境的用户，让他们能按需要安装，并在适用的项目中接入已有工作流程。

## 核心要做的事情

- 提供官方 skills 命令和下载执行脚本两条安装路径，都可以选择整包、一个分类、一个技能或多个技能。同版本、同选择应得到相同的完整内容。
- 下载脚本提供可选隐匿功能，让本次新增的本地文件不出现在普通未跟踪列表。默认关闭，不改项目共享忽略规则，不把技能搬进 Git 内部目录；没有适用仓库时说明原因并继续安装。
- 工作流技能安装后可以接入项目已有的阶段动作和用户指令。下载脚本按本次安装范围默认调用公共挂载入口，用户可关闭；官方安装路径由用户显式执行第二步，复用同一套公共能力。
- 挂载先检查环境，再按顺序处理阶段动作和指令；只处理本次已完整安装且具有对应声明的技能，不把历史安装或未选择的技能一并接入。
- 为维护者提供版本明确、内容可检查的发布材料与操作说明，保留原有工作区、文本清单和原生扩展的消费方式。

## 预期达成的效果

用户按文档能准确安装所选技能，正文和引用材料完整，没有多装其他技能。两条路径的版本与内容可核对，适用环境中的工作流挂载结果一致。

重复执行不会增加重复规则或指令，也不会覆盖未知文件和用户修改。安装、隐匿、阶段动作和指令注册分别报告结果；部分失败时能看清已完成与未完成内容，并按提示继续。

外部安装、平台兼容及失败恢复需要实际验证。本地验证与远端公开验证分别记录，远端尚未验证时明确说明，不把占位地址描述为可直接使用。

## 明确不做的事情

不开发自有 npx 命令，不自动初始化 Git 或 Spec Kit，不改写用户项目宪章，不强制覆盖冲突文件，不隐藏无关文件或整个共享配置。

当前仅完成需求规格及澄清材料，不执行安装器实现或远端发布。本功能可作为原工作流任务拆分验收的真实样本，但创建规格或完成功能都不自动完成原任务，也不代替用户学习实践。
