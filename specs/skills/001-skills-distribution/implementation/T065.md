# T065：新构建与原生挂载占位的失败契约

## 目标与认可

用户在上一轮看到三类验证范围后明确回复“开始”：来源生成正确产物与附件清单、错误输入明确失败、挂载占位零写入且关闭挂载保留纯安装事实。本方案据此开工，复用 T064 已完成证据与最新构建→Actions→真实挂载顺序，不重复请求同一范围认可。

本任务只建立并运行真实失败测试，保留测试骨架供 T067～T070 填充实现；不会为了使测试通过而提前编写新构建或挂载源码。工程 checkbox 仍只在 tasks.md 维护。

## 测试边界与文件

新增 `packages/skills/tests/distribution/build-pipeline.test.mjs` 作为唯一范围入口；新增 `helpers/build-fixture.mjs` 负责复用 createSandbox、复制当前 Vite 配置及存在的构建源码、创建测试自有来源、真实 Git 基线和文件快照。沿用 Node test、真实 Vite build、现有脚本和文件系统，不增加依赖、生产参数或第二构建配置，不导入已存档实现。

fixture 包含中文/空格路径、完整正文、文本与二进制附件、MCP 技能及 references、真实 script 副本。node_modules 只链接当前已准备依赖用于本地验证，不作为迁后独立工程证明；本次所有输出、安装、故障注入与 Git 写入只在自有临时根。原仓库 dist、来源和脚本不改写。

以用户可观察边界为主，通过唯一真实 Vite 配置检查产物。失败输入检查既定 StageError 的 stage/reasonCode 语义及输出不变，不接受任意异常或当前“重做中”报错作为路径、元数据等校验已通过。成功场景必须实际成功，防止总是拒绝也让全部负例通过。正常构建使用 Vite runner 加载配置，测试缓存位于自有临时根，避免默认 bundle 配置在链接的依赖目录写入临时配置文件。

独立审查指出 Vite 的并行 hook 无法可靠保证故障落在生成与复核之间，因此撤回 generateBundle/writeBundle 故障注入做法。改为编译并调用真实生产阶段：export.ts 提供 readSourceSnapshot({ packageRoot, validationScope })、createBuildPlan(snapshot, { outputRoot })、writeBuildOutput(plan)，verify.ts 提供 verifyBuildOutput(plan, output)。这些是既定阶段数据的内部函数名，不是新增外部命令或测试专用 hook。生成完成后再实际改来源/产物，再要求真实复核拒绝；不伪造 SourceSnapshot/BuildPlan/BuildOutput，不固定它们属于哪个 Vite 钩子。编译用的临时入口仅属于测试，缺真实模块/函数保持红灯，后续仍需 T070 验唯一 Vite 编排与复核的实际连接。

## 推进与信号

1. 保存、格式化并读回本方案，原任务回链；记录原来源、脚本、配置及存档摘要作为保护依据。
2. 建立三目录/MCP、原始脚本复制且不执行、Release/两种投影、空源及重建、同源稳定字节等正例；原始文本和附件期望手工给定，摘要从实际 fixture 原始字节独立计算。
3. 独立构造缺目录、来源链接、身份冲突、大小写路径冲突、非法 MCP 元数据、缺附件/越界引用、源内手写清单、危险输出根和生成后篡改/源变动等反例。先验证拒绝的具体阶段/原因，再核对哨兵与既有输出未被误改；不能靠 Vite 临时统一拒绝满足负例。
4. 从真实构建产物调用保留入口，验证 --no-mount 的纯安装及原生占位非零、报告保留已发生事实、零注册器调用/零目标配置写入；必要外部工具缺失单列，不能拿依赖下载失败抵扣占位验证。平台脚本按实际可运行平台判断，不把 Linux 代表全部平台。
5. 运行该范围测试并记录逐项真实红灯及现有通过部分，审查是否因 fixture 或测试错误而失败；再运行包 lint/check-types/build/test 与适用保留消费者。构建和新契约当前预期非零，其他失败须保留名称与原因。
6. 保存本轮验收证据并读回，独立审查测试的误通过风险及保护范围。审查发现的完整脚本集合缺口以源目录全集/字节和 Release 适用声明补齐；禁止的注册器调用在其子模块路径设置调用哨兵，不能只拦官方 CLI。只有测试骨架、真实运行和证据满足 T065 的红灯目标后才勾选本项，不宣称新构建或整个测试套件通过。

## 后续衔接

不修改既定 Release/MCP 线格式、公开范围和最终验收，不新增失败即跳过的绿色开关。T067 先填来源和内存计划，T068 接唯一配置/三目录及占位，T069 补 Release/投影，T070 补独立复核与完整适用兼容；保留同一测试入口逐步转绿。阶段内部接口调整是审查后为可靠测试作出的普通工程安排，保持已认可逻辑与验收；不把测试专用 hook 放入生产代码。
