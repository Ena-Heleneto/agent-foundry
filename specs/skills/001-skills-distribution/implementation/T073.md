# T073：插件工厂封装与技能清单配置

> 后续写法调整：用户已[移除组合式函数约束](../requirements/discussions/2026-11-11-independent-plugins.md#取消组合式函数写法)。下文工厂封装、声明位置和相关AST核验记录当时方案及结果，不再作为后续修改的结构要求；其他职责、配置和行为验收保持。本轮只同步文档，代码由用户手写。

## 目标及认可来源

用户要求每个plugin按组合函数组织，所有逻辑、变量、泛型/类型和辅助函数放在函数内部；顶层只保留必要ESM import及导出插件工厂。本轮针对现有集合插件落实该风格，不借此实现尚未确定的多个插件或调度器。

集合配置改为packageName、mcp及skill映射。用户在询问清单是否决定复制范围后答“是的”，因此只复制skill中列出的技能；集合本身仍自动发现，无配置生成空skill默认配置，不能把未选择目录自动复制。已有四集合迁移时显式列出当前全部技能以保留既有内容。

用户先提出hook可有多个事件，再明确“那就将 prompt 放到 kook的属性下面”，按上下文理解为hook：以事件名为键，每事件对象独立保存prompt、optional、priority及其他扩展属性。command/description不在配置重复维护，后续脚本生成时读取技能来源；所有脚本动态生成规则和MCP内容继续后置。

本轮沿用collection.config.json，仅改变结构，不擅自把伪代码示例认定为格式迁移要求。T072的完成事实保留；新增本Spec的T073，与工作流主线同编号任务区分。

## 数据形状与职责

skill是技能目录名到配置对象的映射，空对象也表示选择。每项hook可缺省；出现时为事件名到对象的映射。每事件prompt可为字符串，optional可为布尔值，priority可为有限数字；其他属性原样保留，不维护事件或扩展属性白名单。

配置的原字节仍进入dist集合根，不派生逐技能hooks文件或挂载脚本。只校验清单身份、来源存在、已知字段类型和路径安全，不实现原生注册。新增目录自动成为集合，但技能交付由该集合清单决定。

现有8项hooks技能的13份事件条目逐项迁移到skill.<技能>.hook.<事件>，仅移除重复command/description，原prompt、optional、priority、enabled、condition等其他内容保持。没有hooks的技能配置为{}。此规则按实际迁移前数据核对，不凭历史数量硬编码。
