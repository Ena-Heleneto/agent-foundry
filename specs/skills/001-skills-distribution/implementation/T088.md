# T088：独立手动发布驱动与 Git 故障验证

执行依据为用户本轮直接多代理完成且免审查的授权及 T079 已建立的真实缺能力基线。本项只在自有临时 bare Git 实施、验证；任何真实远端仍要求明确绑定目标仓库、version、sourceRevision 和 candidateDigest 的授权，不用本地测试授权代替。

独占独立工程 `build/publish.mjs` 与 `tests/publish.test.mjs`，复用已冻结的 `publishCandidate` 接口。发布驱动仅接受现成候选，再次独立读盘核对清单、自身摘要、每项文件原字节和完整树；不安装依赖、不构建、不执行 payload、不改 README、清单或候选目录。拒绝不完整、development、错身份、错摘要、缺说明或许可、路径越界和链接；许可是否真实合法仍由供件证据保证，不根据文件名声称合法。

在私有临时 Git 仓库以精确 payload 生成无父提交，仅无 force 推送新 `refs/tags/skills-v<version>`。推送前后和任何已有 tag 均从实际远端回读，取得真实 commit，核对父数为0和精确文件全集。已有同字节无父才复用；带父、非 commit、同版异字节一律保留并拒绝。并发或推送响应丢失先回读远端事实，不能以退出码推定未发布，不删除或覆盖旧版本。

先扩展真实发布断言并运行缺模块红灯，再实现驱动并复验。测试包含无授权/错仓库/错版本/错源码/错摘要/改字节/缺README或LICENSE零新ref、实际无父精确树、同字节复用、异字节冲突、带父/非commit tag、两个并发、推送已完成却响应丢失及失败保留旧版本。外部故障仅在 Git 进程边界注入，实际 bare 写入和对象读回继续由真实 Git 完成。

返回 prepare、publish、remoteVerify、consumption 各阶段 success/failed/not-run 和原因；真实发布事实不能被下游失败抹除。成功读回的 sourceRevision 与 publishedRevision 分别保存。不造 full/ready、平台收据或任务状态。具体命令与结果由协调者保存对应验收记录。
