# T064：旧构建存档、清退与重新实现起点

## 目标与认可依据

用户已确认全部打包构建重做，并纠正应先将旧架构与相关脚本移到存档，再重新实现；在该范围说明后明确回复“开始吧”。本方案落实这项认可，不重复请求同一范围审批。讨论依据见本轮纠正（原仓库私有记录，未迁移）。

按 writing-plans 保存方案，由当前 agent 按 executing-plans 在用户指定工作区执行；当前为功能分支且存在本功能未提交资料，保留现场，不另建缺少这些资料的工作区、不提交或发布。

## 边界与工程安排

旧 `vite.config.ts`、`build/plugins/` 四组件和 `build/distribution/` 六模块移到既有归档下 `retired-source/`，保持仓库相对路径和字节。直接依赖旧构建的测试、MVU-A 及 catalog/projection/selection helpers 随同存档；原测试契约和历史完成事实不取消，T065～T070 消费其原验收要求建立新验证。

`script/`、`src/`、在线 Agent 读取器、Node 入口、安装/挂载/隐匿测试、测试调度器及通用沙箱保留。`build/types/preset-config.d.ts` 是现有 ESLint 消费类型声明，保持字节迁到 `types/`，只更新 tsconfig 的声明包含路径，不新增兼容类型。

唯一 Vite 配置保留一个明确拒绝构建的临时入口：新构建未实现时退出非零，不能落回 Vite 默认行为、清理旧 dist 或返回成功。现有生成物不手工修改，也不作为本轮产物证据；新构建恢复后再由正常构建生成。

## 推进顺序与验证

1. 只读核验原压缩包与 63 项摘要，记录当前构建文件相对快照的变化，并保存本轮原始字节与保留文件摘要。路径、链接或摘要异常先停止，不覆盖历史归档。
2. 将上述旧实现及直接耦合测试逐文件移动到新归档子目录，记录路径、原摘要与去向。更新类型声明位置和临时拒绝入口，检查有效源码中没有悬空的旧构建导入。
3. 更新当前任务、方案、MVU、指南和包 README，明确旧实现已移出、新构建未实现、旧测试存档后的覆盖缺口及恢复入口；归档正文和历史证据不改写。
4. 运行目标包 lint、check-types、build、test，运行保留的在线读取器、调度/入口及工作区 link-skills 等适用消费者检查。build 预期因明确的重做提示失败，结合前后摘要证明未修改旧 dist；其他失败如实记录，不能通过跳过旧构建验收宣称新链通过。
5. 核对移动文件逐字节可恢复、保留来源与脚本不变、原已完成任务块不变；保存 build-rewrite 验收记录，只有清退范围通过后才勾选 T064。T065 及后续新功能方案不在本轮预填。

## 风险与恢复

主要风险是漏掉间接消费者、错误扩大清退范围、存档丢字节及旧产物被误用。通过导入/文件读取搜索、移动前后摘要、保留文件集合对照和明确拒绝 build 验证。需要恢复时先在临时目录核对 `retired-source` 和摘要，再按相对路径恢复具体文件；不使用整包 reset/revert，不覆盖期间用户修改。

本方案是 T064 的实施准备，工程状态只在 tasks.md 维护。T064 完成不表示新构建、正式来源、平台、安装矩阵或远端发布通过。
