# Agent Foundry 迁仓与文档站设计

> 实施状态更新：本次迁移及原仓库对应删除已执行；下文保留设计和准备时的语境，最终结果见 [执行记录](repository-migration-execution.md)。

## 已确认目标

用户于2026-11-13提供已初始化的新仓库 `<target-workspace>`，要求迁移 `packages/skills`、`packages/skills-distribution-urgent`、`apps/mcp`、相关技能和两个既有功能规格，并采用 monorepo 架构。用户明确文档站面向使用者，覆盖安装、技能目录、工作流和 MCP 使用。

本轮最初读取时两仓均无未提交改动，新仓库只有 README 和已有 Git 历史。旧报告所引用的三个临时准备目录当前均不存在，不能当作可用迁移副本。

## 架构与方案取舍

沿用现有 pnpm 12、Turborepo、ESM 和严格 TypeScript，保持三块代码的相对位置与现有公开包名。它能复用既有包引用、测试入口及脚本定位。改为独立多仓会破坏用户指定的 monorepo；将 Foundry 全部共享预设和业务应用搬入会扩大本次范围，因此不采用。

文档站采用 Nuxt 4 与 Nuxt Content 3。自有 Markdown 作为用户文档来源，使用内容集合、动态文档路由、侧栏导航与页内目录。选择轻量文档应用，避免将整个博客应用及 Cloudflare、D1、登录等配置带入。Docus 等更完整模板留待有明确需求时评估。

目录约定如下：

```text
apps/
  docs/                         # 面向使用者的 Nuxt Content 文档站
  mcp/                          # 原 Python MCP 应用
packages/
  skills/                       # 原主线，保留用户手写中间态
  skills-distribution-urgent/    # 原紧急辅线
tooling/
  preset-config/                # 原 ESLint 和 TypeScript 公共配置的最小依赖闭包
scripts/dev/actions/link-skills/ # 技能副本生成及其原测试入口
specs/skills/
  001-skills-distribution/
  20261029-speckit-workflow-foundation/
```

## 迁移行为与文件保护

1. 从当前实际文件重新建立来源清单和摘要，不以旧报告的数量、临时目录或旧 HEAD 替代当前输入。
2. 先准备目标副本并验证，再移除旧仓库被迁移的受管源码。已确认需要留在原仓库的私人记录及原始归档保留原件；公开派生内容标明改写范围，不能冒充原始验收。
3. 不迁移 `.git`、依赖目录、构建产物、缓存、凭据、环境变量或本仓库私人画像。迁入的通用技能规则继续沿用目标项目治理，不夹带本仓库个人资料。
4. 自有材料使用已选 ISC，保留已确认的 Spec Kit 等第三方来源和适用通知。逐成员核对压缩归档，不能只检查外层文件名。
5. 保留正式技能与附件的原字节。eval 源码与样本随主线保留，继续排除在正式分发和安装范围之外。
6. 新根只提供真实依赖和必要初始化，不复制旧仓库部署、发布或业务脚本。旧仓库初始化同步移除失效的本地技能注册依赖，仍保留其他业务应用初始化。
7. 相关技能通过源码和挂载脚本在新根生成副本，不搬入无来源的整个 `.agents/skills` 或已退役技能。

本轮迁移不接管主线 T076/T077，不重写 MCP 业务契约。MCP 当前依赖旧 `manifest.json`，而主线构建已变更；文档应明确真实前置与已知缺口，不能写成迁后已经可用。

## 文档站内容与行为

- 首页说明 Agent Foundry 的用途及主线、紧急版当前差异，提供清晰阅读入口。
- 安装指南区分作者本地开发和使用者安装；未发布的来源使用明确占位说明，不编造可用下载地址、版本或成功记录。
- 技能目录展示正式技能用途与适用场景，暂不将 eval 或已退役模式列为可安装能力。
- 工作流指南说明当前 Implement/Increment 和实施准备的使用方式，引用现有契约，保留未完成边界。
- MCP 指南说明启动命令、清单配置和已知构建契约缺口，不自动部署 MCP。
- 页面支持移动端导航、当前页面提示、清晰标题层级、代码阅读和无内容时的 404；不新增登录、在线编辑或外部业务服务。
- 规格与历史验收继续作为开发材料保存在 specs，文档站不自动公开渲染全部需求原话、日志或归档。

Nuxt Content 的集合与渲染方式已查阅[官方安装说明](https://content.nuxt.com/docs/getting-started/installation)及[集合文档](https://content.nuxt.com/docs/collections/define)。具体样式和目录实现由 AI 在该范围内安排，遵守加载的前端技能规则。

## 实施顺序与验收

迁移先核验来源、公开范围和依赖，再建立目标根与真实依赖，随后接入文档站，最后验证两仓的初始化与目标应用。本站无业务数据库或业务后端开发层；Nuxt Content 的内容索引由模块管理。

验证应包含文件摘要与正式技能原字节核对、共享配置构建及消费检查、目标 workspace 的 lint/check-types、适用原测试、文档站构建和真实路由请求。记录主线中间态和历史测试的既有失败，不关闭规则或改写测试求绿。

本轮不执行推送、发布、打版本标签或部署。紧急版 T090 的真实新身份冻结与后续发布任务按原条件分别处理；本次目录迁移不自动将 T090～T093 标为完成，也不自动创建 Git 提交。
