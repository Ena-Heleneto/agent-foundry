# T076 技能同名冲突校验

## 2026-11-19 局部实施

用户确认「这种情况直接构建报错」。当前复制保留集合路径，安装器使用技能末级目录名，因此不同集合的两个同名启用技能映射到同一个 `.agents/skills/<技能>`。已有隔离构建曾接受该输入并清理旧输出。

在 `vite-plugin-skill` 的 `buildStart` 扫描实际会复制的技能，按安装目录名检查冲突。冲突时列出两个来源并终止，校验通过后复用同次扫描结果进行原有复制。当前授权覆盖这项构建校验，T076 其余验收沿原任务继续。

先用真实 Vite 配置在临时项目预置两个同名启用技能和旧 `dist` 哨兵，再核对非零退出、两个来源及旧产物内容。随后复跑正常构建与包内相关测试。

## 本轮实际验证

真实 Vite 回归在修正前识别到构建错误地返回成功。修正后，同样输入非零退出，输出两个来源和共同安装路径，旧产物清单及字节一致。补查禁用同名项和缺少正文的同名目录都不影响有效技能复制。

默认构建成功，读回 11 个技能目录。定向 Node 测试 15/15，目标包类型检查和 lint 通过。首次 lint 报告新测试的导入排序，已调整并重跑通过。Python 套件 36/39 通过，旧 `register-commands.sh` 缺失使 `test_cli_failure_is_reported`、`test_every_run_reinstalls_all_sources`、`test_installs_increment_and_attachments` 失败。

本证据覆盖安装目录重名这一项，T076 的其他边界仍按原任务验收。
