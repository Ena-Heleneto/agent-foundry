# T066 逐次推送的技能测试

## 已确认范围（2026-11-23）

在本会话说明移除同分支取消、按推送 SHA 执行两套既有测试及本地验证后，用户回复「开始吧」。本次从已完成的 T002 续接，改动限定于推送测试工作流、对应隔离验证和本任务记录。实际 GitHub 运行沿已说明的正常开发推送取证。正式归档和发布分别归 T069、T095 及后续任务。[原任务](../tasks.md#t066) · [规格](../spec.md#2026-11-23-主线技能构建与发布流水线) · [业务闭环](../mvu.md#mvu-009-维护者能审阅并隔离验证-actions-发布链)

## 做法与验收

1. 先用 `packages/skills/tests/distribution/pipeline-workflow.test.mjs` 读取真实工作流，复现同分支运行互斥和缺少事件提交核验。用隔离 Git 仓库模拟同一分支先后两次推送，覆盖早期提交、最新提交、标签及检出错版。
2. 在 `.github/workflows/skill-release.yml` 保留无分支或路径筛选的 `push`，移除按分支分组的并发配置。对有效事件按 `github.event.after` 检出并在装依赖前核对 `HEAD`，日志关联提交、工具和直接依赖版本。保留现有 Python、Node 矩阵及 `fail-fast: false`，两套测试的退出状态由各自 job 保留。检出使用只读权限，关闭检出凭据持久化。删除引用或缺少有效提交时，单独记录跳过原因，避免使用 GitHub 删除事件的默认分支 SHA。[GitHub 推送事件](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#push) · [检出动作 v4](https://github.com/actions/checkout/blob/v4/README.md)
3. 先跑隔离契约和现有两套测试入口，核对错误 SHA、删除事件和测试失败的结果。两次实际推送及开放 `release` PR 源分支的结果，以 GitHub 运行记录核对推送 SHA 和两份 job。若 GitHub 未投递事件，另据平台证据记载。正式验收和下游发布仍需要对应证据。[验证指南](../quickstart.md#平台事件与权限预检)

## 本地验证（2026-11-23）

本地环境使用 Node 24.22.2、pnpm 12.16.1 和 Python 3.15.2。工作流为可检出的 `push` 保留两套原测试。删除引用或缺少新提交时，运行摘要记录跳过原因。检出后的第一步核对实际提交，支持将附注标签解析到对应的 Git 提交。[工作流](../../../../.github/workflows/skill-release.yml)

- `node --test packages/skills/tests/distribution/pipeline-workflow.test.mjs` 在旧配置上按预期失败 4 项，改动后 4 项全部通过。用实际 Bash 和隔离 Git 仓库核对两个顺序提交、错版 `HEAD`、附注标签及跳过报告。[隔离用例](../../../../packages/skills/tests/distribution/pipeline-workflow.test.mjs)
- Python 入口 `pnpm --filter @foundry/skills run test` 前后均为 36 项通过、3 项失败，退出 1。`test_cli_failure_is_reported`、`test_every_run_reinstalls_all_sources` 和 `test_installs_increment_and_attachments` 仍调用已移入 `script/old/` 的注册脚本旧路径。
- Node 分发入口 `node --test packages/skills/tests/distribution/*.test.mjs` 从 76 项通过、51 项失败、4 项跳过，变为 80 项通过、51 项失败、4 项跳过，退出 1。前后逐项核对了失败与跳过名称。失败涉及旧 Agent 读取器路径、已撤出的目录插件，以及无法解析当前 `#build/plugins/vite-plugin-curl/index` 的旧构建夹具。4 项跳过是缺官方 CLI 前置的 project、global 及附件集成场景。
- 工作流及新增用例通过定向 ESLint，工作流通过 `actionlint` 1.7.12。技能包类型检查及输出到临时目录的构建通过，生成的 curl 入口和引擎入口均通过 Bash 语法检查。包级 lint 仍因 `package.json` 中 `sh-syntax` 的版本未使用 catalog 而失败。
