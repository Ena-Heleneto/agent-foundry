# 技术调研 · 从 Codex 对话生成协作 Skill

规划中实际核对的环境为 `codex-cli 0.170.0`。以下是接口与源码核对得到的设计选择。真实交互、写入故障、跨日恢复、派发和兼容宿主消费是后续运行验证。输入范围沿[功能规格](spec.md)。

## 交互会话的接入时点

**决策**。以仓库根目录的 `.codex/hooks.json` 作为接入候选，在本仓库根目录和子目录确认项目层和 hook 的实际信任状态。写入前以本次交互入口的有效工作目录及原会话归属核定采集范围。用 `UserPromptSubmit` 验证用户文本先保存，再发送给模型。末轮用 `Stop` 尽早保存，`Interrupt` 和 `SessionEnd` 提供中断或结束线索及补读机会。用本仓库根目录、子目录和仓库外对照测试纳入范围。 [Codex 配置发现与信任](https://learn.chatgpt.com/docs/hooks#where-codex-looks-for-hooks)

**理由与备选**。同版首轮链路会执行 `SessionStart`。因此需要把首轮接入与真正开启时刻分别测量，尤其是无输入打开，以及跨午夜才发送首条消息。纯会话历史导入可供恢复，无法证明首条消息先保存；同步方案需要用真实开启信号或可信的开启时间补足。若首期版本没有可验证的开启来源，复核宿主版本或接入路径，再由用户决定任何影响原定范围的调整。 [0.170.0 首轮链路](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/core/src/session/turn.rs#L399-L467)

**范围依据**。项目级发现用于接入，路径归属以解析后的目录层级核对。宿主选择较近的项目根或从其他工作树复用配置时，也需要核对真实会话入口。0.170.0 在执行工具时可把工具工作目录填进事件的 `cwd`，该值按工具活动留档。交互恢复可加载历史目录，非交互恢复也可带有原交互线程的来源类型。前置验证要分别取得本次交互入口、恢复前的有效工作目录及原会话归属。若目标版本的原生入口无法证实这些条件，先保留前置失败证据并调整接入方案。改用有别于常规 CLI 的入口需重新确认实际覆盖范围。 [同版工具目录](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/hooks/src/events/common.rs#L24-L29) · [同版恢复时的目录选择](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/tui/src/lib.rs#L1035-L1071) · [同版原会话来源](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/core/src/thread_manager.rs#L1595-L1614) · [同版项目层发现](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/core/src/config/config_loader_tests.rs#L3513-L3642)

## 工具、附件与恢复来源

**决策**。用实时已验证来源记录完整可取得内容，再按已知会话身份定向补读。优先验证公开会话历史读取的 `thread/read`、`thread/turns/list` 的完整条目，以及存储支持时的 `thread/items/list`。如果需要补足公开投影遗漏的原始参数，只在合成样例证明内容实际存在后采用固定版本的只读会话记录适配。 [Codex 会话历史接口](https://learn.chatgpt.com/docs/app-server#read-a-stored-thread-without-resuming)

**理由与备选**。0.170.0 的 shell hook 提供有限参数，输出可按显示策略截断。用户文本 hook 提取文本，图片或音频的结构化条目可能只有本地路径。历史投影和持久化也有范围限制。单用 hook 或历史读取都需逐字段验证。收到附件或可读路径时及时留存原件，用哈希核对。截断、不可读和未持久化均记录实际范围，完整采集验收以已核对的原值为依据。 [shell hook 负载](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/core/src/tools/context.rs#L424-L490) · [附件协议](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server-protocol/src/protocol/v2/turn.rs#L481-L507) · [持久化策略](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/rollout/src/policy.rs#L231-L285)

## 本地保存、写入失败与 Git

**决策**。沿本地文件存储，默认将资料区置于业务仓库外，按真实会话身份协调同一会话的写入。以会话、轮次和事件的可靠身份核对已保存范围。详情与附件确认后为索引提供定位，失败保留已写部分，由恢复读取修复可核实的缺项。

**理由与备选**。单按日期共写文档无法稳妥地区分多会话，纯文本相同也不能区分重复执行与不同事件。业务仓库内的忽略规则因项目而异，仓库外资料区更适合用户要求的提交兼容。验证时用两个并行会话、重复跨日恢复、受控部分失败和一次真实提交，分别核对会话缺口、用户任务继续、工作区和暂存区。 [数据模型](data-model.md) · [验收指南](quickstart.md)

## 提炼与分析的独立派发

**决策**。记录接入提供已确认材料的可用线索，父代理使用两个独立 Skill 的适用说明分别判断。优先验证仓库内的普通任务可进入判断及发起对应派发。提炼使用来源位于本仓库目录树的已确认记录。一次明确的持续偏好可以支持提炼，普通观察以可核对证据决定。分析需要足以形成或修订规则的已确认提炼文档，既有特点可独立进入分析。交接以实际提供的材料定位和回传产物核对，父代理读回后再确认证据资格与版本。

**理由与备选**。Codex 支持适用的项目或 Skill 指令发起子代理。计划先用受控模型核对子线程和回传，再用普通用户任务观察父代理按证据选择。验证用三组独立起始材料观察实际派发数，并核对父轮、子线程、任务职责、交接材料和可读取产物。0.170.0 的事件表示在不同子代理版本中有差异。 [Codex 子代理](https://learn.chatgpt.com/docs/agent-configuration/subagents#triggering-subagent-workflows) · [0.170.0 派发事件](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server-protocol/src/protocol/v2/item.rs#L459)

## 可移植交付与旧入口切换

**决策**。三份流程 Skill 和一份协作 Skill 采用通用目录规范。用规范校验和独立宿主实际应用共同验收协作产物。按规格澄清，旧影子画像对话保留为历史依据，首次自动提炼使用新流程保存并确认落盘的本仓库记录。首期采集本仓库内发起的交互会话，主会话中可取得的子代理活动随主会话工具详情留存。其他采集入口和旧资料导入可在有明确需求时评估。 [Agent Skills 规范](https://agentskills.io/specification)

**现有证据**。主线扫描已只读核对，当前 `profile` 的交付结果包含 `dist/skill/profile/shadow-profile`。Bash 常规及定向同步按源目录发现技能，且保留来源未声明的已装条目。切换需要原样归档旧维护源、撤下启用条目、移除旧安装副本，并验证真正重新发现。现有同级候选中与旧入口相关的引用，在对应候选进入新流程时核对。 [集合配置](../../../packages/skills/src/profile/collection.config.ts) · [开发同步脚本](../../../scripts/dev/actions/link-skills/link-skills.sh) · [旧技能历史依据](../20261029-speckit-workflow-foundation/contracts/shadow-profile.md)

**理由与备选**。新记录先通过隔离验收，再退役，能保持记录连续。便携目录只能携带规则和所需资源，以目录外的本地溯源支撑维护。仅校验元数据覆盖不了实际消费，兼容宿主与其权限由后续验收环境提供。

**运行前置**。本机 `PATH` 未发现 `skills-ref` 及本次核对的 Claude Code、Goose 或 OpenCode。后续准备可用的兼容宿主，格式核验可采用官方校验工具或等价检查。当前尚未执行兼容代理应用测试。
