# 技术调研 · 从 Codex 对话生成协作 Skill

首轮隔离实测使用 `codex-cli 0.170.0`。当前方案由 AI 读取 Skill 并直接使用宿主已有工具。原 T004 项目 hook 试验提供历史对照，当前方式的证据由相关 Task 获取。 [功能规格](spec.md) · [无脚本确认](requirements/raw/2026-11-20-no-scripts.md)

## 交互会话的接入时点

**历史试验**。隔离仓库根目录和子目录能发现同一份项目 `.codex/hooks.json`。该试验观测到首条保存先于模型请求，`Stop` 提供末轮回复，还观测到了用户中断与退出。 [T004 实测](analysis/recording-host.md)

**首条消息与日期**。原试验在提交首条消息后才收到 `SessionStart`，提供的 `transcript_path` 带有实际开启日。现行验收关注 AI 能否在首条消息时核对实际开启日、保存原文并读回，再执行首个业务动作。空白会话的主记录和详情数量为零。 [T004 实测](analysis/recording-host.md#打开首条与退出)

**范围与末轮**。原试验的事件字段无法区分交互和 `exec`，两种跨边界恢复的事件目录都是宿主所选的目录。后续实测取得了当前轮次的交互类型。按最新范围，恢复使用原会话归属和恢复后的有效工作目录。普通末轮另与宿主实际发出的内容比对，业务工具的工作目录用于详情回查。[T004 作用域对照](analysis/recording-host.md#作用域对照) · [最新确认](requirements/raw/2026-11-23-resume-effective-directory.md)

**现行方式的技术观测**。2026-11-20 的无 hook 受控样例已验证：工具环境可取得真实会话 ID，父 CLI 进程参数及工作目录可在本版区分 `exec` 和恢复前启动目录；跨午夜时可用匹配 ID 的会话文件名核对开启日，不能用模型的 `current_date` 代替。工具先保存并读回首条再开始业务，以及预存末轮后发送、退出后比对实际输出，两条受控路径均成立。固定回包未验证真实 AI 自主遵循，T004 仍未完成；详细信号、失败尝试和可复核快照见[本轮技术核查](analysis/recording-host.md#ai-直接方式的技术核查2026-11-20)。

## 工具、附件与恢复来源

用宿主已有工具取得可核实的内容。T005 用合成样例验证 AI 当轮可读取的工具参数、短、长及流式输出和附件原件，按原值、顺序及哈希比对。只出现摘要、截断文本或路径线索时按实际缺口标明。归属可核实的恢复在原文件中续写，原文丢失时保留缺档。归属无法核实的恢复跳过自动记录。 [记录验收](quickstart.md#记录验收)

**同名附件决策**。先核对目标路径及已有原件。若路径已用于内容不同的同名附件，为新原件选择会话附件目录内的另一可用路径。保存并读回后，再让对应工具事件的详情链接指向该路径。不同路径可保住两个原件及各自的来源关联。直接按原名覆盖会使先前链接指向错误内容，跳过后一个附件则会丢失可取得的原件。具体命名沿实施方案确定。已有 T005 验证覆盖原件内容比对，同名碰撞及恢复重试由第一里程碑补验。[验收指南](quickstart.md#记录验收)

## 本地保存、写入失败与 Git

**决策**。沿本地文件存储，按 FR-003 在项目内选择资料根，按真实会话身份协调同一会话的写入。以会话、轮次和事件的可靠身份核对已保存范围。详情与附件确认后补充对应链接，首条用户原话先独立落盘，失败保留已写部分，原文仍可取得时才可重试。提交步骤及其结果回复的记录写入次数为零，其他内容按业务步骤继续处理。

**记录自身的边界**。按操作用途排除仅为记录保存、附件复制、断点核对和读回产生的内部工具活动，确认后返回业务工作，避免保存动作再次触发保存。业务工具及提炼/分析派发仍保留，不能按工具名或资料路径整体排除。T006/T008/T010/T014 核对有限结束及范围内内容完整性，恢复时沿同一边界。

**同轮提交重试**。每次提交及其结果回复分别跳过；失败后、重试前的修复恢复正常记录。T006/T010/T014 必须覆盖一次受控失败、修复、重试及恢复后的事件范围，不能以单次成功提交替代。以上为[2026-11-20 上下文修订](requirements/discussions/2026-11-19-open-questions.md#一致性分析后的修订2026-11-20)，尚未取得新记录入口的运行证据。

**理由与备选**。单按日期共写文档无法稳妥地区分多会话，纯文本相同也不能区分重复执行与不同事件。按项目规则选择 Git 可见的项目内目录，提交阶段通过停写保证工作区和暂存区的记录新增差异为零。验证时用两个并行会话、重复跨日恢复、受控部分失败和一次真实提交，分别核对会话缺口、用户任务继续、工作区和暂存区。 [数据模型](data-model.md) · [验收指南](quickstart.md)

## 提炼与分析的独立派发

**决策**。记录接入提供已确认材料的可用线索，父代理使用两个独立 Skill 的适用说明分别判断。优先验证仓库内的普通任务可进入判断及发起对应派发。提炼使用来源位于本仓库目录树的已确认记录。一次明确的持续偏好可以支持提炼，普通观察以可核对证据决定。分析需要足以形成或修订规则的已确认提炼文档，既有特点可独立进入分析。交接以实际提供的材料定位和回传产物核对，父代理读回后再确认证据资格与版本。

**理由与备选**。Codex 支持适用的项目或 Skill 指令发起子代理。计划先用受控模型核对子线程和回传，再用普通用户任务观察父代理按证据选择。验证用三组独立起始材料观察实际派发数，并核对父轮、子线程、任务职责、交接材料和可读取产物。0.170.0 的事件表示在不同子代理版本中有差异。 [Codex 子代理](https://learn.chatgpt.com/docs/agent-configuration/subagents#triggering-subagent-workflows) · [0.170.0 派发事件](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/app-server-protocol/src/protocol/v2/item.rs#L459)

**一致性修订后的待验边界**。主会话的子代理工具活动需要在详情中逐项对照可取得的名称、完整参数、输出及顺序，无法取得的部分保留缺口，不由派发成功推定已完整留存。不同父会话向同一 Skill 回传时，采用同一写入协调范围核对版本并采纳，删除也推进版本，过期候选不覆盖当前结果。候选探针与最终流程入口分开取证，最终来源变化后刷新隔离安装副本并证明真实读取及受影响流程复验。这些为[本次修订](requirements/discussions/2026-11-19-open-questions.md#一致性分析后的修订2026-11-19)补齐的规划约束，尚无实际运行证据。

## 可移植交付与旧入口切换

**决策**。三份流程 Skill 和一份协作 Skill 采用通用目录规范。用规范校验和独立宿主实际应用共同验收协作产物。按规格澄清，旧影子画像对话保留为历史依据，首次自动提炼使用新流程保存并确认落盘的本仓库记录。首期采集本仓库内发起的交互会话，主会话中可取得的子代理活动随主会话工具详情留存。其他采集入口和旧资料导入可在有明确需求时评估。 [Agent Skills 规范](https://agentskills.io/specification)

**现有证据**。T001 只读扫描时，`profile` 的交付结果包含 `dist/skill/profile/shadow-profile`。Bash 常规及定向同步按源目录发现技能，且保留来源未声明的已装条目。切换需要原样归档旧维护源、撤下启用条目、移除旧安装副本，并验证真正重新发现。现有同级候选中与旧入口相关的引用，在对应候选进入新流程时核对。 [集合配置](../../../packages/skills/src/profile/collection.config.ts) · [开发同步脚本](../../../scripts/dev/actions/link-skills/link-skills.sh) · [旧技能历史依据](../20261029-speckit-workflow-foundation/contracts/shadow-profile.md)

**理由与备选**。原规划在新记录验收后退役，以保持记录连续。用户随后确认提前退役并接受记录空档，现状见[退役证据](analysis/shadow-retirement.md)。便携目录只能携带规则和所需资源，以目录外的本地溯源支撑维护。仅校验元数据覆盖不了实际消费，兼容宿主与其权限由后续验收环境提供。

**当前安装差异**。本轮核对发现当前工作区仍有旧安装正文，主线配置已无旧启用项，同步脚本已有相应清理能力。执行现有同步后旧副本移除，新宿主在仓库根和子目录均发现零个旧入口，其他安装项保持原样。差异原因尚未确认，历史验收原文保留，新的实际信号另记[当前工作区复核](analysis/shadow-retirement.md#当前工作区复核2026-11-20)。

**运行前置**。本机 `PATH` 未发现 `skills-ref` 及本次核对的 Claude Code、Goose 或 OpenCode。后续准备可用的兼容宿主，格式核验可采用官方校验工具或等价检查。当前尚未执行兼容代理应用测试。
