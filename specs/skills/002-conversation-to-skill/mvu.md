# 业务闭环 · 从 Codex 对话生成协作 Skill

里程碑按**记录 → 提炼 → 分析**推进。每个闭环以可观察的用户结果为交付依据。工程任务身份与唯一 checkbox 见[任务清单](tasks.md)，本文件说明关联职责，不维护工程状态。需求与验收编号见[功能规格](spec.md)。

## 里程碑一 · 记录

### MVU-001 自动保存首条消息与末轮回复

用户从本仓库根目录或子目录打开交互式 Codex CLI 会话，自动得到可按轮次查阅的索引与详情。正常路径先保存已发生的用户消息，再推进对应工作，并在正常关闭时保留已经产生的末轮回复。

关联 T004 的宿主接入验证、T006～T009 的身份与成对文档及事件接入、T013 的记录入口和 T014 对最终安装来源、真实读取及记录业务的验收。共用准备与定位契约由 T001～T003 承接。先在隔离用户环境核对无输入开启、首条提交、普通末轮后立即退出和打开后跨日才提交首条的来源。仅有首轮信号时，开启时刻继续待证。验收应看到首个任务动作前可读的消息内容、独立的索引与详情和末轮回复。仓库外会话和非交互式运行的对照记录数量为零。已纳入的会话调用仓库外工具时，工具活动仍可在该会话详情回查。覆盖 FR-001 至 FR-004、SC-001、SC-009。 [前置验证](research.md)

### MVU-002 回查完整工具参数、输出和附件

沿记录文档补齐详情，用户从当轮索引能查到改动文件、工具名称、完整参数和完整输出，并能打开会话或工具活动中保存的附件原件。

关联 T005 的完整内容来源探针、T008/T010 的详情与附件留存，以及 T014 的真实原值验收。验收用已知原值的命令选项、流式及长输出、本地工具样例和附件逐项核对字段、内容及原件哈希。受控子代理工具样例及后续实际派发还须核对主会话可取得的工具参数、输出、顺序及父轮/子线程定位，子线程内部独立留存不在首期范围。只有摘要、截断或不可取的项标出缺口。完整留存依赖已验证的数据来源。覆盖 FR-004、FR-005、SC-002。 [采集边界](research.md)

### MVU-003 并行记录与跨日续写

同日从本仓库同时打开的会话各写各的文档。用户关闭、终止或中断会话后，次日在本仓库目录内恢复时，按真实会话身份回到原日期和原文件，仅补写可核实且尚未保存的事件。

关联 T004 的恢复范围取证、T006 的回归、T007/T011 的归属与写入协调、断点和历史补读，以及 T014 的真实恢复验收。先核实启动及恢复使用的会话身份以及持久事件可读范围。验收用两个有相同文本的并行会话和一次不可控中断，跨日恢复同一会话两次。每个真实事件只出现一次，确实缺失的内容可辨认。分别从仓库内恢复仓库外会话、从仓库外恢复仓库内会话，两种对照的新增与续写记录均为零。依赖自动记录。覆盖 FR-003、FR-007、SC-001、SC-003。

### MVU-004 写入失败后带着缺口继续

正常任务遇到记录写入失败时，用户可看到受影响内容，然后继续任务。写入恢复后，资料能如实补记缺口和可核实内容，之前确认的材料可继续提炼。

关联 T006 的失败回归、T011/T012 的可核实补写与缺口提示，以及 T014 的受控写失败验收。验收用受控写入失败分别覆盖索引、详情或附件部分落盘和资料区暂不可写，核对缺口提示先于后续工作、任务正常继续及补写后的真实覆盖。依赖记录及恢复规则。覆盖 FR-006、SC-003。

### MVU-005 提交完成后继续记录

用户在业务仓库完成一次真实提交后，仍能查到提交动作、结果和后续回复。自动记录引入的工作区与暂存区新增差异均为零。

关联 T002 的隔离 Git 基线、T008 的仓库外保存和 T014 的真实提交及后续记录验收。用有已知预期 Git 状态的临时仓库跑完整流程，分别比对工作区与暂存区，回查后续新增的记录。依赖会话落盘和提交工具活动回查。覆盖 FR-008、SC-004。 [验收操作](quickstart.md)

### MVU-006 归档并切换旧影子画像入口

新记录通过隔离验收后，将旧 `shadow-profile` 原样移入新 Spec 的归档，撤下活动源、启用条目与项目级安装副本。维护者仍可回查归档和历史依据，正常同步后由新记录入口提供记录。

关联 T027 的原样归档、T028 的启用及安装入口切换和 T029 的同步与真实发现验收；执行前置为 T014，不因故事章节位于 US2 之后而后移记录里程碑的切换。核对完整文件清单及字节，检查主线扫描、常规同步和旧的定向同步均无旧入口，再用新开的真实 CLI 会话确认旧入口未被发现、新记录可工作。依赖记录里程碑其余闭环通过。覆盖 FR-015、SC-008。 [现有入口核查](research.md)

## 里程碑二 · 提炼

### MVU-007 按证据派发并保存一项特点

父代理只有在已确认材料足以支持特点时才派发提炼子代理。用户可以查到一份独立特点文档、它的适用情境及原始对话依据。单次明确的持续偏好或纠正可以作为充分证据，普通观察随材料积累。

关联 T015 的父代理派发探针、T016 的独立特点格式与资格测试、T017 的提炼入口和 T022 的多阶段真实验收；共用交接依据为 T003。先确认普通用户任务下父代理可以得到已确认材料的线索，并能实际派发和核对回传。证据不足时的提炼派发为零，证据充分时可核实提炼子线程。首次自动提炼使用实际记录入口生成的样例，对照旧样例、仓库外样例和未确认落盘样例，核对真实交接材料及产物依据。探针注明候选安装来源，T022 刷新最终流程入口并取得父/子代理真实读取和工具详情留存证据。依赖已确认的记录材料。覆盖 FR-001、FR-009、FR-010、SC-005、SC-009。

### MVU-008 用多项目材料提炼并回查来源

同一用户在本仓库不同项目目录的已落盘材料可以共同支持特点。先前的范围内资料能再次参与提炼。一次性项目决定和跨项目习惯在文档里各有具体适用情境。

关联 T016/T017 的多项目来源核对、证据定位和已有材料复用，以及 T022 的双项目真实材料验收。验收用本仓库两个项目目录的记录、一个只在单项目成立的约定和一份仓库外来源样例，核对所用依据均来自本仓库且保留情境。再次处理已保存材料时，依据仍能定位到相同的真实对话块。依赖基本提炼和跨会话稳定定位。覆盖 FR-009、FR-010、SC-005 的材料前置。

## 里程碑三 · 分析

### MVU-009 独立派发分析并生成一份协作 Skill

父代理在提炼文档足以形成或修订可执行规则时启动分析子代理。分析将来自不同项目的特点整合成一份带适用情境的协作 Skill。用户可在本地回查每条规则的提炼依据。

关联 T018 的独立分析派发、T019 的规则与多对多依据、T020 的目录生成、T021 的分析入口及 T022 的实际派发和溯源验收。材料不足时的分析派发为零。分析正例用此前已确认的特点，在本轮没有待提炼证据时独立启动，能核实实际分析子线程、回传及有效目录；T022 同时验证 T017/T021 的最终安装来源与父/子代理读取。两个父会话可并行分析，但同一 Skill 的版本核对及采纳在同一写入协调内完成，过期候选保留核查后重新判断，不覆盖较新规则、关联或目录；由 T019 回归与 T022 真实交错验证承接。使用本仓库至少两个项目目录的材料，核对目录入口与必要资源可定位，每条规则都能回查其实际依据。依赖两个提炼闭环和已验证的派发链路。覆盖 FR-001、FR-011、FR-012、SC-005、SC-009。

### MVU-010 把生成目录带到另一兼容代理使用

用户带走生成的目录，即可在另一个项目通过兼容代理的常规 Skill 加载方式应用规则。目标环境只取得最终目录，规则和所需资源仍可正常读取。

关联 T020 的完整目录与资源、T022 的格式核验及使用者和兼容宿主的实际消费证据。生成 Skill 的便携消费与三个流程 Skill 的最终来源消费分别取证。先核对实际交付目录的入口、元数据和相对资源，再用另一个兼容代理做代表性任务，记录发现、读取和实际行为。依赖生成完整目录和可用的兼容宿主。覆盖 FR-012、SC-006。 [验收操作](quickstart.md)

### MVU-011 删除规则、保护共享依据并允许再次形成

用户删除当前的一项规则后，独占提炼文档和关联可被清理，共享依据仍可支持其他规则，原始对话与附件可回查。后来满足条件的处理可以基于已有或新增对话重新形成该规则。

关联 T023 的维护回归、T024 的本地删除及共享保护、T025 的旧回传版本校验和 T026 的真实删除与重新形成验收。验收用两条规则和独占、共享各一项依据，两个父会话分析均已派发后执行删除，删除在同一共享协调边界内推进版本，再回传两项旧结果，随后单独运行一次有足够依据的新提炼与分析。T026 在 T024/T025 修改后刷新最终流程安装副本，核对版本或快照、完整正文/附件、父/子代理真实读取并复验。核对删除仍生效、共享证据仍可用及规则可在新的处理中形成。依赖带来源关联的提炼和分析产物。覆盖 FR-013、FR-014、SC-007。
