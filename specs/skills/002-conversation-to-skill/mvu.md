# 业务闭环 · 从 Codex 对话生成协作 Skill

里程碑按**记录 → 提炼 → 分析**推进。首期记录由项目级安装后的会话入口自动触发，提炼和分析由对应代理按各自 Skill 使用宿主已有工具。每个闭环以可观察的用户结果为交付依据。工程任务身份与唯一 checkbox 见[任务清单](tasks.md)，需求与验收编号见[功能规格](spec.md)。

## 里程碑一 · 记录

### MVU-001 自动保存首条消息与末轮回复

**状态**：进行中。**依据**：T034 已有新版资料布局，隔离 Hook 对照取得用户原话的前置写入，`Stop` 在宿主最终回复事件之后可以取得全文。 [T034 交付核对](implementation/T034.md#交付核对) · [T035 Hook 对照](analysis/recording-acceptance.md#hook-是否会漏启动的隔离对照) · [最终回复保存时机确认](spec.md#最终回复保存时机确认)

**闭环结果** 项目级安装完成后，用户照常打开 `codex`，第一条「读一下 README」即建立项目内的记录，后续每个合格轮次续写。用户能逐字回查原话与实发回复，零模型工具调用的普通问答也有记录。

**节点与关键逻辑** 先在隔离项目核对安装与信任、回调时点的范围判定，以及正常最终回复发送结束后自动保存和读回全文。候选通过前置后，接入既有资料根和按轮保存，由正式来源复验首条、后续轮次、失败及提交例外。若采用 Hook，完整通过后移除其接替的旧记录逻辑，再用最终安装版本复验。T033 依赖最终安装来源的完整复验。 [前置验证](research.md#技术前置验证)

**关联 Task** T001～T004、T006～T009、T013、T014 提供既有定位、保存与运行证据，T034 提供当前资料布局。T035 承接新增前置验证和新版正式来源隔离复验，T033 承接最后的真实工作区试用。具体工程职责及依赖在任务阶段衔接。 [任务清单](tasks.md#依赖与实际执行顺序)

**验收信号** 两个不同目录的空白会话零建档，首条在业务动作前保存并读回，首轮及后续轮次各有零模型工具调用样例。每个合格轮次恰有一个对话组，正常最终回复发送结束后在当轮自动保存全文并读回，无需再发消息，正常退出后仍可回查。跨午夜建档沿实际开启日，可信 `exec` 和范围外对照零写入及零额外正文补读。覆盖 FR-001～FR-004、SC-001、SC-009。 [记录验收](quickstart.md#记录验收)

### MVU-002 回查完整工具参数、输出和附件

沿记录文档补齐详情，用户从主记录中当轮「查看经过」能查到工具名称、完整参数和完整输出，并能打开会话或工具活动中保存的附件原件。

仅为保存、核对记录而发生的内部工具活动不进入待记录集合，按实际用途与业务操作区分。T006/T008/T010 及 T014 核对同一文件工具的业务调用完整可查、内部记录调用不递归追加，读回确认后能够结束本次保存并继续任务。提炼/分析派发仍按原范围留存，恢复时保持同一边界。

关联 T005 对宿主已有工具实际可提供的来源核对、T008/T010 的详情与附件留存，以及 T014 的旧版原值验收。T035 按最终来源核对已知原值的命令选项、流式及长输出、本地工具样例和附件，逐项比对字段、内容及原件哈希。受控子代理工具样例及后续实际派发还须核对主会话可取得的工具参数、输出、顺序及父轮和子线程定位，子线程内部独立留存不在首期范围。只有摘要、截断或不可取的项标出缺口。同一会话中两次工具调用生成同名异内容附件时，逐条打开详情链接核对原件字节，并在恢复续写后复查。已有新版对照提供部分证据，变更入口后按实际来源复验。覆盖 FR-004、FR-005、SC-002。 [隔离复验](analysis/recording-acceptance.md#2026-11-25-t035-新版隔离复验)

### MVU-003 并行记录与跨日续写

同日从本仓库同时打开的会话各写各的文档。用户关闭、终止或中断会话后，项目记录已启用且原会话和恢复后的有效工作目录均可核实属于本仓库时，沿合规的原资料根和原日期从断点续写。若旧资料位置命中 Git 忽略规则，从新选的项目位置记录当前及后续内容，旧文件留在原位。来源不符或无法核实的恢复跳过写入和正文补读，既有记录仍可回查。写入前关闭且原文丢失的内容保留为缺档。

关联 T004 的恢复范围取证、T006 的回归、T007/T011 的归属、写入协调和断点核对，以及 T014 的真实恢复验收。代理在临时仓库验收两个有相同文本的并行会话。核实原会话归属和恢复后的有效工作目录后，验证同一会话两次跨日恢复沿用原文件，新事件各记录一次，丢失内容仍为缺档。从仓库内恢复仓库外创建的会话及归属无法核实的恢复均验收零新增、零续写和零正文补读。依赖自动记录。覆盖 FR-003、FR-007、SC-001、SC-003。[记录验收](quickstart.md#记录验收)

### MVU-004 写入失败后带着缺口继续

正常任务遇到记录写入失败时，用户可看到受影响内容，然后继续任务。写入恢复且原文仍可取得时，可重试保存。之前确认的材料可继续提炼，失去原文的部分保留缺档。

关联 T006 的失败回归、T011/T012 的缺口提示与写入重试，以及 T014 的受控写失败验收。验收用受控写入失败分别覆盖主记录、详情或附件部分落盘和资料区暂不可写，核对缺口提示先于后续工作、任务正常继续及重试后的实际保存范围。T012 在已核实的同次启动中使用 T011 已验的会话锁、断点核对与保存确认。跨启动恢复的实际续写沿 MVU-003 及 T014 补验。覆盖 FR-006、SC-003。

### MVU-005 提交步骤跳过记录

用户要求修复后提交时，原始请求和提交前的修复过程可回查。提交步骤及其结果回复期间的记录写入次数为零，由记录引入的工作区和暂存区新增差异为零。提交后的普通对话继续落盘，产生的记录文件在 Git 工作区可见。

关联 T002 的隔离 Git 基线、T006 的回归、T008 的成对保存、T010 的按步骤采集和 T014 的真实提交验收。用有已知预期 Git 状态的临时仓库跑完整流程，另让同一轮首次提交失败、修复后再提交。核对原请求、两段修复和后续普通对话可回查，每次提交及结果回复零写入，恢复后仍保持同一边界。验收分别核对普通记录的工作区可见性，以及各次提交及其结果回复期间由记录引入的 Git 差异。覆盖 FR-008、SC-004。[验收操作](quickstart.md)

### MVU-006 归档并切换旧影子画像入口

关联 T027 的原样归档、T028 的启用及安装入口撤除和 T029 的同步与真实发现验收。核对完整文件清单及字节，检查主线扫描、常规同步和旧源定向同步，再用新启动的真实 CLI 宿主核对旧入口发现为零。新记录通过 T014 后补齐新入口可用性证据。覆盖 FR-015、SC-008。[现有入口核查](research.md)。

历史退役结果与当前安装现场分别记录；安装现场变化时先核对实际来源和同步结果，再取得宿主重新发现证据，不用历史快照替代当前核查。T029 的新记录补验沿隔离样例使用新开的 Codex 会话。[当前工作区复核](analysis/shadow-retirement.md#当前工作区复核2026-11-20) · [T029 验收方案](implementation/T029.md)

## 里程碑二 · 提炼

### MVU-007 按证据派发并保存一项特点

父代理只有在已确认材料足以支持特点时才派发提炼子代理。用户可以查到一份独立特点文档、它的适用情境及原始对话依据。单次明确的持续偏好或纠正可以作为充分证据，普通观察随材料积累。

关联 T015 的父代理派发探针、T016 的独立特点格式与资格测试、T017 的提炼入口和 T022 的多阶段真实验收；共用交接依据为 T003。先确认普通用户任务下父代理可以得到已确认材料的线索，并能实际派发和核对回传。证据不足时的提炼派发为零，证据充分时可核实提炼子线程。首次自动提炼使用实际记录入口生成的样例，对照旧样例、仓库外样例和未确认落盘样例，核对真实交接材料及产物依据。探针注明候选安装来源，T022 刷新最终流程入口并取得父/子代理真实读取和工具详情留存证据。依赖已确认的记录材料。覆盖 FR-001、FR-009、FR-010、SC-005、SC-009。

### MVU-008 用多项目材料提炼并回查来源

同一用户在本仓库不同项目目录的已落盘材料可以共同支持特点。先前的范围内资料能再次参与提炼。一次性项目决定和跨项目习惯在文档里各有具体适用情境。

关联 T016/T017 的多项目来源核对、证据定位和已有材料复用，以及 T022 的双项目真实材料验收。验收用本仓库两个项目目录的记录、一个只在单项目成立的约定和一份仓库外来源样例，核对所用依据均来自本仓库且保留情境。再次处理已保存材料时，依据仍能定位到相同的真实对话块。依赖基本提炼和跨会话稳定定位。覆盖 FR-009、FR-010、SC-005 的材料前置。

## 里程碑三 · 分析

### MVU-009 独立派发分析并生成一份协作 Skill

父代理在提炼文档足以形成或修订可执行规则时启动分析子代理。分析将来自不同项目的特点整合成一份带适用情境的协作 Skill。用户可在本地回查每条规则的提炼依据。

关联 T018 的独立分析派发、T019 的规则与多对多依据、T020 的目录生成、T021 的分析入口及 T022 的实际派发和溯源验收。材料不足时的分析派发为零。分析正例用此前已确认的特点，在本轮没有待提炼证据时独立启动，能核实实际分析子线程、回传及有效目录；T022 同时验证 T017/T021 的最终安装来源与父/子代理读取。两个父会话可并行分析，但同一 Skill 的版本核对及采纳在同一写入协调内完成，过期候选保留核查后重新判断，不覆盖较新规则、关联或目录；由 T019 回归与 T022 真实交错验证承接。使用本仓库至少两个项目目录的材料，核对目录入口与必要资源可定位，每条规则都能回查其实际依据。依赖两个提炼闭环和已验证的派发链路。覆盖 FR-001、FR-011、FR-012、SC-005、SC-009。

### MVU-010 把生成目录带到另一兼容代理使用

用户带走生成的目录，即可在另一个项目通过兼容代理的常规 Skill 加载方式应用规则。目标环境只取得最终目录，规则和所需资源仍可正常读取。

关联 T020 的完整目录与资源、T022 的格式核验及使用者和兼容宿主的实际消费证据。生成 Skill 的便携消费与三个流程 Skill 的最终来源消费分别取证。先核对实际交付目录的入口、元数据和相对资源，再用另一个兼容代理做代表性任务，记录发现、读取和实际行为。依赖生成完整目录和可用的兼容宿主。覆盖 FR-012、SC-006。 [验收操作](quickstart.md)

### MVU-011 删除规则、保护共享依据并允许再次形成

用户删除当前的一项规则后，独占提炼文档和关联可被清理，共享依据仍可支持其他规则，原始对话与附件可回查。后来满足条件的处理可以基于已有或新增对话重新形成该规则。

关联 T023 的维护回归、T024 的本地删除及共享保护、T025 的旧回传版本校验和 T026 的真实删除与重新形成验收。验收用两条规则和独占、共享各一项依据，两个父会话分析均已派发后执行删除，删除在同一共享协调边界内推进版本，再回传两项旧结果，随后单独运行一次有足够依据的新提炼与分析。T026 在 T024/T025 修改后刷新最终流程安装副本，核对版本或快照、完整正文/附件、父/子代理真实读取并复验。核对删除仍生效、共享证据仍可用及规则可在新的处理中形成。依赖带来源关联的提炼和分析产物。覆盖 FR-013、FR-014、SC-007。
