# Implementation Plan: 从 Codex 对话生成协作 Skill

**Branch**: `feature/init` | **Date**: 2026-11-19 | **Spec**: [功能规格](spec.md)

## Summary

用户已确认先归档和撤下旧影子画像，随后按**记录 → 提炼 → 分析**推进。旧入口撤下至新记录可用期间有自动记录空档。记录先用隔离环境验证 Codex CLI 会话接入，再交付可恢复、可回查的本地资料。提炼使用本仓库内不同项目目录的已确认记录，保留对话证据。首次自动提炼使用新流程保存的记录，旧影子画像对话作为历史资料保留。分析使用提炼文档产出一份可独立应用的协作 Skill，并支持规则维护。完整节点、依赖和验收见[业务闭环](mvu.md)。

| 里程碑 | 可交付结果                                                                   | 推进依赖                                                   |
| ------ | ---------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 记录   | 首条消息时建档，原文件可续写，提交步骤跳过记录，完成旧入口切换 | 先核实 AI 可取得的会话信息、数据原件和恢复依据              |
| 提炼   | 父代理按证据派发提炼，得到可回查、带情境的独立特点文档                       | 使用记录阶段已确认的资料与定位契约，验证真实派发与回传     |
| 分析   | 从特点生成一份通用协作 Skill，另一兼容代理能应用，规则可删除并再次形成       | 使用可回查的提炼文档，验证独立分析派发、产物消费及并发维护 |

## Technical Context

- **交付**。记录、提炼、分析各提供 `SKILL.md` 和必要文档资源。由相应代理读取规则并直接使用宿主已有的文件和派发工具。目录沿 `packages/skills` 既有集合及交付路径维护。以本机 `codex-cli 0.170.0` 为首轮取证版本，按实测确认兼容范围。 [无脚本确认](requirements/raw/2026-11-20-no-scripts.md)
- **接入**。AI 在交互式对话中按记录 Skill 执行。首条消息出现时核对会话身份和实际开启日期，使用现有文件工具建立索引与详情，再处理任务。普通末轮的实际原文、交互入口身份与恢复前的目录归属由 T004 在此方式下核对。恢复从已保存断点续写新内容，原文丢失时允许缺档。T005 核对现有工具提供的内容与附件，已确认材料供父代理判断和派发。 [技术调研](research.md)
- **存储**。资料区默认在业务仓库之外。日期下每个会话各有一份索引和详情，附件保存原件。提交步骤及其结果回复的记录写入次数为零，提交前修复和后续普通对话照常保存。提炼文档和规则溯源留在资料区，协作 Skill 将需要的资源放在可独立复制的目录内。 [数据模型](data-model.md)
- **共享规则采纳**。不同父会话可以并行分析，但同一资料区内同一份协作 Skill 的版本核对、规则与依据关联更新、目录采纳和删除使用同一写入协调边界。版本过期即不采纳，保留候选及来源，重新依据最新材料判断；不静默覆盖或自动合并。不把会话记录的单会话协调推定为共享规则协调已通过。 [接口契约](contracts/collaboration-workflow.md)
- **平台和边界**。首期记录在本仓库根目录或子目录内打开的交互式 Codex CLI 会话，验收覆盖仓库内两个工作目录与仓库外对照。提炼按同一仓库边界核对资料来源。主会话可取得的子代理活动随工具详情记录。生成的协作 Skill 通过兼容代理独立验收。 [接口契约](contracts/collaboration-workflow.md)
- **验证目标**。用真实 CLI 核对保存和业务执行顺序，验证长输出、附件、写入失败、跨日续接、提交和派发。格式校验之外，以另一兼容代理的实际规则应用作为可移植验收。 [验收指南](quickstart.md)
- **最终来源消费**。记录、提炼、分析入口及其必要资源变化后，从实际交付来源刷新隔离正式入口，核对版本或快照、完整正文与附件，并证明父/子代理实际读取。探针只证明所测候选；生成 Skill 的独立消费另行验收。真实派发时还需核对主会话可取得的工具参数、输出、顺序和缺口。 [验收指南](quickstart.md)

## Constitution Check

- **输入和边界**。本次依三项规格澄清复核规划，沿用户指定的三个里程碑推进。原始需求及确认继续作为需求来源，工程 Task 及实施准备由后续阶段承接。
- **依赖验证**。按会话入口与内容来源、写入与恢复、父代理入口与派发、独立消费组织前置验证。分析可从既有确认特点直接启动。T004 项目 hook 的实测作为历史对照，当前路径在隔离 CLI 中重新核对。完整记录、派发与兼容消费沿各自任务验收。失败只影响依赖该结果的闭环。 [T004 实测](analysis/recording-host.md)
- **方案与证据**。保存恢复、子代理回传和规则变更由各 Skill 指令及资料契约规定，实际行为按对应 Task 取证。 [逻辑图](diagrams.md)
- **退役**。先归档旧源，撤下启用和安装入口，再核对正常同步及宿主发现。新记录仍需按最终入口完成真实验收，两项证据共同确认切换后的项目可用状态。[提前退役确认](requirements/raw/2026-11-20-early-shadow-retirement.md)。
- **一致性修订**。最终流程入口复验、共享规则采纳和子代理工具留存已纳入规划，运行证据由对应工程任务取得。 [修订依据](requirements/discussions/2026-11-19-open-questions.md#一致性分析后的修订2026-11-19)
