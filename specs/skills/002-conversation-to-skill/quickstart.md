# 验收指南 · 从 Codex 对话生成协作 Skill

本指南验收 AI 按三个 Skill 使用已有工具的运行结果。使用合成对话、受控工具和隔离项目。T004 的项目 hook 试验提供历史对照，当前记录方式、实际派发与兼容宿主应用仍待实测。 [T004 实测](analysis/recording-host.md) · [业务闭环](mvu.md)

## 准备隔离环境

核对 `codex --version`、`node --version` 和 `pnpm --version`。沿现有 Skill 安装方式在隔离样例启用待验入口，从仓库根目录和子目录核对 AI 实际发现和读取的来源，以及执行时调用的现有文件工具。目标仓库内设两个项目目录，另建一个仓库外的对照目录，资料区放在目标仓库之外。准备已知字节的附件、可输出已知长文本的工具和可控写入失败条件。后续阶段准备能实际派发的模型，以及一个可安装最终目录的兼容代理。

T002 已提供隔离样例，包含两个项目、仓库外对照及资料、二进制原件、长输出工具和 Git 基线。故障场景使用可控的资料写入目录。可运行 `node --test packages/skills/tests/distribution/conversation-sandbox.test.mjs` 核对样例行为。Skill 的发现、读取和业务执行沿下文实测。 [样例支持](../../../packages/skills/tests/conversation-workflow/helpers/sandbox.mjs) · [环境证据](analysis/environment.md)

## 记录验收

使用 T013 的最终记录来源完成下节的流程入口刷新与读取核对后，再执行本节真实验收；T004/T005 的探针证据单独注明候选身份。

1. 在两个终端从目标仓库内不同项目目录使用 `codex -C <仓库内项目目录>` 开启会话。输入之前核对两个会话的索引及详情数量均为零。提交第一条消息后核对各自的索引和详情已建立，消息在首个业务动作前可读。另测跨午夜才发首条消息的会话，核对首条消息时建档且使用实际开启日归档。
2. 输入带附件的任务，调用具有额外选项的工具，覆盖短输出、长输出、流式输出和工具附件。对照真实参数、结果与原件哈希。核对索引、详情和实际改动文件的定位。收到正常末轮回复后立即正常退出，核查末轮已经保存。
3. 在一个样例会话中触发用户停止，另测已建档会话在新消息落盘前关闭且原文不可取得。下一本地日期运行 `codex resume -C <样例项目目录> <原会话标识>` 并发新消息，再恢复一次。核对沿用原日两份文件，两个会话的相同文本仍独立，新事件各保存一次，丢失原文的内容仍为缺档。
4. 模拟资料区无法写入及部分写入失败，记录用户看到缺口的时点和任务继续的结果。原文仍可取得时，恢复可写后核对写入重试的实际保存范围。
5. 在样例仓库让代理修好一个问题后提交。回查原始请求和提交前的修复过程。观察提交步骤开始至结果回复发出期间的写入活动，并比对前后的索引、详情和附件，核对该步骤引入的记录写入次数为零。再发普通消息并恢复一次会话，核对新内容继续保存，提交步骤及结果回复仍被跳过。用 `git status --porcelain=v1`、`git diff --binary`、`git diff --cached --binary` 对照预期结果，核对自动记录引入的工作区和暂存区新增差异均为零。
6. 从目标仓库外的同名前缀目录开启交互式会话，并在仓库内运行 `codex exec` 样例和 `codex exec resume <仓库内交互会话标识>`。用样例会话的真实标识验证两种跨边界恢复。仓库内恢复仓库外会话时选择仓库内目录，仓库外恢复仓库内会话时选择原历史目录。对照结果为零新增、零续写、零范围外正文补读。
7. 在已纳入记录的会话中调用一个在对照目录运行的样例工具，核对工具活动仍归入原会话，详情可回查它的工作目录。

## 流程 Skill 最终来源消费

这项门禁针对记录、提炼、分析三份流程 Skill，生成的协作 Skill 另按便携消费验收。T014 核对最终记录来源；T022 在 T017/T021 保存后核对三份流程来源；T026 在 T024/T025 的维护改动后刷新并复验受影响流程。收尾检查或清理再改变最终来源时，同样刷新并复验，不沿用旧快照结果。

1. 记录实际维护源、版本或源码快照、交付产物、隔离安装位置及启用/信任依据。先核对实际安装命令的来源；当前根 `pnpm skills:link` 指向紧急版，不能仅因命令成功便推定主线新入口已安装。沿既有交付/同步路径在隔离目标刷新本次范围内的最终来源，保护其他来源条目，不手改安装副本。
2. 对照源与安装结果的文件清单、完整 `SKILL.md` 正文和必要文档资源，检查同名旧副本、相对引用及宿主实际发现位置。实际消费由下一步的宿主读取和业务证据确认。
3. 新开实际 CLI 会话，在使用该阶段的父代理及对应子代理上取得发现、完整读取和资源读取的真实证据，将路径及文件快照关联到相应父轮次、子线程和后续行为。子代理直接读维护源不能替代读取安装副本；记录阶段没有对应子代理时只核对适用角色。
4. 用当前快照重新执行受影响的业务流程，将证据放回 T014、T022、T026 的原验收文件。来源再变化即复验对应入口；缺少刷新、读取或复验时保留该项未验，不凭先前候选探针勾选业务任务。

## 提炼与分析验收

先完成上述最终流程来源消费门禁，再用相应安装入口开展以下业务验收；此前 T015/T018 的最小探针另记候选来源及其适用范围。

先用受控模型和真实 Codex CLI 核对派发与回传链路。再分开准备三组起始材料，用普通用户任务触发判定，提示词不点名工作流或提供样例中的关键依据。通过 `/subagents` 和宿主事件关联父轮次、阶段、子线程与回传，核对实际派发数。

| 起始材料                                             | 提炼派发数 | 分析派发数 |
| ---------------------------------------------------- | ---------- | ---------- |
| 对话不足以提炼，特点也不足以形成规则                 | 0          | 0          |
| 本轮对话足以归纳特点，特点尚不足以形成或修订规则     | 1          | 0          |
| 已有可形成或修订规则的确认特点，本轮没有待提炼的证据 | 0          | 1          |

首次自动提炼的验收由记录入口实际生成仓库内两个项目目录的合格记录，并在同一资料环境配置可读的仓库外、旧影子画像和未确认落盘样例。各组样例用可区分的内容。核对实际交给子代理的证据及产物溯源均采用仓库内两个合格来源，旧样例可继续查阅。每条规则经特点文档回查到实际采用的原始对话。

在每个实际派发样例中，从父轮索引定位详情，对照宿主活动逐项核对主会话可取得的派发、交互及回传工具名称、完整参数和输出、事件顺序与子线程关联。用带已知文本的输入和返回比对原值；只能取得活动摘要或字段缺失时，核对对应缺口而非补造。T005 先以受控子代理工具样例验证来源，T015/T018 核对实际链路，T022 验收最终流程入口产生的记录。子线程内部独立留存仍在首期范围之外。

通过 `skills-ref validate <协作 Skill 目录>` 或等价检查核对实际生成目录，确认全部必要资源可在目录内定位。把同一份产物按另一兼容代理的常规方式装入隔离项目，给代理一个代表性任务，记录它发现、读取和应用规则的证据。格式校验和真实消费分别取证。 [Agent Skills 格式校验](https://agentskills.io/specification#validation)

准备包含独占和共享依据的两条规则，删除其中一条，再接收删除前发出的旧分析结果，最后运行一次符合条件的新处理。逐项核对规则、特点及原始对话的变化。

## 共享规则并发采纳验收

先在 T019 的本地回归验证采纳契约，再由 T022/T026 用两个真实父会话及独立分析子线程验收。记录每次派发版本、父轮、子线程、候选位置和采纳前后规则/关联/目录快照，采用受控回传顺序，不能仅靠两次串行分析代表并发。

1. 两个父会话都以同一当前版本 V0 派发独立分析，并让两个候选均在父代理确认前可回传。先采纳 A，核对版本推进到 V1，规则、依据关联和目录一致；再回传 B，核对它因 V0 已过期而未被采纳，V1 及其有效依据未被覆盖或清理，B 的候选及来源仍可核查。交换 A/B 先后顺序复验。
2. 在采纳入口设置可控交错点，让两个写入者都尝试核对 V0，证明版本检查与写入采用同一协调边界，最多一项按 V0 成功；不能在边界外各自检查后轮流覆盖。部分写入失败时不报告成功版本，保留最后确认结果和可恢复的实际缺口。
3. 在两个分析均已派发后删除当前一条规则，核对删除推进版本；随后回传两项旧结果，均不能恢复删除项、清理共享依据或回退目录。继续用最新版本及足够的已有或新增材料发起一次新处理，允许自然重新形成同一规则。

同一资料区、同一份协作 Skill 内进行上述协调，其他独立会话的原始记录仍可继续保存；不新增工程状态服务或永久禁止规则重新形成的名单。

## 旧入口归档切换验收

按用户确认提前执行归档及撤除。在候选工作区比对旧源码与 archive 中的相对文件清单和哈希，核对活动源码、启用声明、构建产物及项目安装副本。依次执行主线交付扫描、常规本地同步和旧源定向同步，再通过新启动的 CLI 宿主重新扫描项目，验证旧入口发现数量为零。T014 完成后补核对新记录能工作且旧入口仍未发现。真实对话及历史规格按退役时的现状保留。[开发同步脚本](../../../scripts/dev/actions/link-skills/link-skills.sh)。

下列命令用于候选工作区的只读交付清单检查。预期输出的名称中没有 `shadow-profile`。常规同步在隔离工作区执行，定向同步可指定临时目标目录。

```bash
pnpm --filter @foundry/skills exec node --input-type=module -e 'import { scanSkills } from "./utils/scan-skills.ts"; for (const entry of await scanSkills()) console.log(entry.name)'
```
