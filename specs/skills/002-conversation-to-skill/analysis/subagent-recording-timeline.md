# 业务子代理跨轮时间线取证

2026-11-27 在两个临时 Git 仓库运行 Linux Codex CLI 0.172.0，分别使用 V1 和 V2 的直接派发工具。两个仓库都从维护源通过 `install.py` 安装记录 Skill，逐个比对 17 个文件的 SHA-256，再用原生界面完成项目和 Hook 信任。回环端点只控制合成输入及回复的发出时机，派发、线程、回调和落盘均由实际宿主执行。探针以额外的只读观测 Hook 取证。 [结构化观测](acceptance/subagent-recording-timeline.json)

## 实测顺序

第二轮的合成回复有单独的放行点，以便观察该轮进行时到达的子代理回复。父会话的工具调用只有两次 `spawn_agent`。表中时间均为 UTC，区分宿主日志时间、回调接收时间和文件读回时间。

| 事件                                    | V2           | V1           |
| --------------------------------------- | ------------ | ------------ |
| 父日志记录派发 A                        | 01:09:03.861 | 01:09:03.872 |
| 父日志记录派发 B                        | 01:09:04.695 | 01:09:04.683 |
| 主记录首轮回复已读回，A 和 B 均尚未放行 | 01:09:05.575 | 01:09:05.545 |
| 父会话空闲时收到 A 的 `SubagentStop`    | 01:09:05.837 | 01:09:05.768 |
| 父日志记录第二用户轮开始                | 01:09:07.500 | 01:09:07.416 |
| 第二轮进行时收到 B 的 `SubagentStop`    | 01:09:08.030 | 01:09:07.958 |
| 主记录第二轮回复已读回                  | 01:09:08.718 | 01:09:08.742 |

A 和 B 回传前后分别比较记录文件清单、哈希和修改时间，两组各自一致。当前记录入口生成的主记录包含两轮用户与主代理的消息。无子代理对照用同一安装独立启动，发起和回复各保存一次，未生成详情文件。 [结构化观测](acceptance/subagent-recording-timeline.json)

## 字段来源

| 字段                 | 已核实的宿主来源                                                                                                                                                                                                                                                  |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 派发输入原文         | V1 和 V2 的父会话 `PreToolUse`、`PostToolUse` 均在 `tool_input.message` 提供原文，与两条含空行的合成输入逐字一致。                                                                                                                                                |
| 派发所属父轮与子线程 | 父会话工具回调提供父轮 `turn_id` 和 `tool_use_id`。V1 的工具回包带 `agent_id`，父日志的 `CollabAgentToolCall.id` 也可用工具调用 ID 关联子线程。V2 的工具回包给出代理路径，父日志的 `SubAgentActivity` 启动事件以同一工具调用 ID 关联 `agent_thread_id`。          |
| 子代理身份和回复全文 | `SubagentStop` 直接提供 `agent_id` 和 `last_assistant_message`。两组四条回复的原文与对应子线程的宿主 `task_complete` 逐字一致。V2 的父日志在所测两轮内出现了 A 的回复副本，B 的全文当时可从回调取得。                                                             |
| 子代理回调归属       | `SubagentStart` 和 `SubagentStop` 的 `session_id` 是父会话 ID，`turn_id` 是子线程轮次。启动回调的 `transcript_path` 指向子线程记录。停止回调的 `transcript_path` 指向父会话记录，另有 `agent_transcript_path` 指向子线程记录。                                    |
| 发生时间             | 两种子代理回调均未携带事件时间字段。父日志提供派发时间，子线程 `task_complete` 提供宿主完成时间。实测停止回调先于子线程完成条目持久化，表中的回调接收时间来自探针。V2 的父日志还保留两次子代理完成事件，其中 B 的完成事件出现在第二轮开始后，归属仍指向原派发轮。 |

## 证据边界

首轮探针确认了直接派发时的父会话输入来源，以及父会话空闲和活跃时的子代理回复回调。随后用下面的样例补验了 Code Mode 和补充消息。正式主记录的交错写入和分隔仍待接入并复验 SC-010、SC-011。 [验收标准](../spec.md#measurable-outcomes) · [早期子代理取证](content-source.md#子代理活动及父会话可见字段)

## Code Mode 与补充消息补验

2026-11-27 复用 Linux Codex CLI 0.172.0、维护源本地安装和回环合成样例。父代理在第一轮启动一个子代理，第二轮再向同一子代理发送不同的多行文本。父代理先保存第二轮回复，第三轮开始后才放行子代理的补充回复。原生回调的观测脚本在收到 `SubagentStop` 时立即读回合成子线程日志。 [结构化补验证据](acceptance/subagent-recording-code-mode.json)

- **V1**。在 Code Mode 的 `exec` 中调用 `multi_agent_v1__spawn_agent` 和 `multi_agent_v1__send_input`，动态拼成含空行的消息。两次内部工具的父会话 `PreToolUse` 和 `PostToolUse` 都暴露逐字一致的 `tool_input.message`。父日志中的 `CollabAgentToolCall.id` 匹配工具回调的 `tool_use_id`，两条活动关联到同一个子线程。补充回包的 `submission_id` 对应补充回传的子线程轮次。
- **V2**。启用 Code Mode 后，两组 `exec` 工具目录查询（关闭及开启 `multi_agent_v2_dynamic_tools`）均没有匹配的派发和补充工具。同一 Code Mode 设置下，模型可从独立的 `collaboration` 工具入口使用 `spawn_agent` 和 `followup_task`。该入口实测取得两段原文，父日志以不同的 `SubAgentActivity` 调用 ID 将它们关联到同一子线程。两条链路的补充回复均跨到第三个父轮。
- **回复时间**。V1 和 V2 对照的初次与补充回复共四条。每次 `SubagentStop` 执行时，根据回调的 `agent_id` 和子线程 `turn_id`，从 `agent_transcript_path` 读到了唯一匹配回复全文的 `final_answer` 条目及其宿主时间。该条目早于回调接收时间，当轮 `task_complete` 均在回调之后落盘。配对以子线程和轮次为依据，回调带来的回复原文用于核对。
