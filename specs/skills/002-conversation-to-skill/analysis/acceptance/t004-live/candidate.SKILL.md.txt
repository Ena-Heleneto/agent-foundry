# 合成会话记录接入候选

此入口仅验证 T004，不是正式记录功能。业务来源范围为 `/tmp/foundry-conversation-lwxSrQ/repository`，资料根为 `/tmp/foundry-conversation-lwxSrQ/records`。本候选只使用宿主已有工具，不运行记录脚本或 hook。

每轮先读取本入口；完成准入和首条保存前不发送业务进度消息。再取得当前工具环境中的真实 `CODEX_THREAD_ID`。通过父进程链的命令参数及工作目录核对本次入口是交互式 CLI，区分 `exec` 和 `exec resume`；恢复前启动目录必须位于来源仓库内。工具当前目录不能代替恢复前目录。原会话归属还须从当前会话已有的初始环境或同一线程的已确认记录核对，不能以恢复后的目录替代。只允许查看与当前线程 ID 匹配的会话文件名及已确认记录，不读取范围外会话正文、不读取任何认证或用户机器配置。实际开启日从匹配当前 ID 的会话文件名核对，当前日期不是开启日证明。

核验需实际调用工具取得证据，不能因上下文未直接给出就声称不可取得。使用 Python 标准库从 `os.getpid()` 沿 `/proc/<pid>/status` 的 `PPid` 向上检查；对每层读取 `cmdline` 的 NUL 分隔参数及 `cwd` 链接，只把可执行名为 `codex` 的进程当入口候选。检查 CLI 的独立参数是否含 `exec`、`resume` 或 `--no-daemon`，不要按 shell 脚本文本中的字符串判断。沿 `Path.home() / ".codex/sessions"` 只列出文件名含当前 ID 的 `rollout-*.jsonl`，不读取正文；文件名 `rollout-YYYY-MM-DDT…-<ID>.jsonl` 给出日期。首次会话以宿主初始环境的目录核对原归属，恢复会话还需可核查原来源；没有证据就保留缺项。上述核验均只输出与当前 ID 及祖先进程入口有关的字段。

来源、交互身份或开启日期无法核实时，只报告具体缺项，不建立或续写记录；依旧完成用户业务任务。仓库外、非交互及两种跨边界恢复均不写资料。核对身份和读取规则属于内部记录操作，不是业务动作。

符合范围时，直接用文件工具在 `records/<开启日期>/details/<线程ID>.md` 保存本轮用户原文，读回确认后，再在对应 `index/<线程ID>.md` 保存链接；此时才能开始首个业务动作。详情保留会话 ID、原来源、此次入口目录及已核对证据。恢复同一线程时续写原文件，不重复已有事件。新的用户消息使用新块。

普通助手消息在发出前直接保存原文并读回；随后发出的文字必须与保存版本相同。最终回复也按这个步骤在本轮发送前保存，发送后不再追加解释或修改。保存失败时明确标出缺口，继续用户任务；被停止或关闭后没有机会执行保存的内容不伪造。

仅为记录保存、核对和读回的工具调用不递归记录。候选只核对首条、普通回复、末轮与归属，工具完整采集和正式记录功能另行验收。不要派发子代理。
