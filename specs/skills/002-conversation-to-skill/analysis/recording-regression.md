| 观测 | 实测结果 |
| --- | --- |
| 开启、输入和并行 | 两个交互终端空白时资料区无文件。本地 23 日开启，24 日发送首条，两个实际线程各自保留相同用户文本。Alpha 另有一轮相同文本，合计两次真实用户事件 |
| 工具与附件 | Alpha 在仓库外实际执行 `exec_command`，返回自身线程标识、业务标记及 6 字节原件的 SHA-256。原件哈希与工具返回相符 |
| 部分写失败 | 用目录阻断 Alpha 的索引文件位置，真实打开收到 `EISDIR`。随后执行本轮业务，解除占位并发下一条重试输入 |
| 停止、缺档与续接 | 实际终端显示进度原文后收到 Ctrl+C，宿主保存中断事件。验证端只从本次独占线程移除含该原文的两行，再于本地 24 日以原线程 ID 恢复两次，两轮回复实际发出 |
| Git | 独立首次成功用例退出 0。另一轮首次提交退出 1，随后修复、暂存和重试退出 0。三个结果回复均可在实际会话事件中找到。最终两个测试提交的主题与预期一致，工作区和暂存区均干净 |
| 提交窗观测 | 每个提交调用前开始观察，经过结果回复和用于划定边界的空操作后结束。三个区间实际变化事件均为 0 且起止快照一致。独立写入再删除对照虽然最后仍为空，观察到 4 个变化事件 |

## 失败基线与复跑

从仓库根运行 `node --test packages/skills/tests/conversation-workflow/recording-regression.test.mjs`。新增 [Node 回归入口](../../../../packages/skills/tests/conversation-workflow/recording-regression.test.mjs)与 [隔离场景驱动](../../../../packages/skills/tests/conversation-workflow/helpers/recording-regression.py)。准备阶段、格式检查和窗口判定使用独立观测，回归断言读取真实文件快照。

本次退出 1。合成输入与真实工具组通过。其余五组在预期的记录产物断言失败：首条先保存、同工具与附件、两次续写、提交前保存四组缺少 Alpha 索引，部分写失败组缺少应能单独回查的详情。Node 汇总把父测试也计为失败，因此显示 1 通过、6 失败。当前资料区未生成记录文件，提交窗内的零写入是基线实况，跳过逻辑仍须和已保存的修复事件一起验收。

设置 `FOUNDRY_RECORDING_SAVE_OBSERVATION` 为独占文件路径可保存新观测。设置 `FOUNDRY_RECORDING_OBSERVATION` 为上述已保存 JSON 路径可重放断言，复现相同的五组业务失败。T014 可从安装后实际运行采集相同结构，包括按用途标记的 `record-readback` 调用、索引失败后到继续业务前的提示、各窗口文件观测和最终成对文档。只有最终入口实际消费产生的观测才能支持记录通过结论。

首次工具验证遇到共享 ESLint 把 Node 静态导入改写为 Vitest，之后沿 Node 进程内置模块运行本探针。早期观测误读了会话消息所在事件以及在结果回复边界重复开启观察，现按 `response_item` 消息取原值，并为每次提交只打开一个观察区间。两类工具问题均在最终基线前修正。
