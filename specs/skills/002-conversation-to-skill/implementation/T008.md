# T008 · 成对保存对话索引和详情

用户听取了「先定单项方案，再用隔离样例验证仓库外保存、先确认详情和附件、再写索引」的推进方式，回复「开始吧」。本次沿原任务、FR-003～FR-005 和现有资料契约，定义 AI 用宿主文件工具保存已核实会话的步骤。[原任务](../tasks.md) · [功能规格](../spec.md) · [资料契约](../../../../packages/skills/src/profile/conversation-recording/references/storage-contract.md)

在记录 Skill 的 `references/paired-save.md` 保存操作规则。复用 T007 已核实的会话身份、仓库、开启日与实际轮次，在仓库外资料根下定位同一会话的两份文档。每次进入保存时确定已有业务事件的范围，按实际事件定位写详情，附件以原始字节和 SHA-256 与所属详情块关联。读回确认详情及可取得的附件后，才写入带相对路径和轮次锚点的索引，读回确认后继续业务。用同一文件工具分别运行业务操作与记录维护，按调用目的和实际事件定位排除本次维护调用。[会话归属规则](../../../../packages/skills/src/profile/conversation-recording/references/session-scope.md) · [业务闭环](../mvu.md)

以 T006 的实现前观察重放原有业务工具和附件两项断言，再用 T002 临时仓库、仓库外同名前缀对照目录及六字节原件验证候选。临时入口加载本次规则，按普通任务实际调用工具取得已知 README 内容，再验证显式保存。比对宿主事件、资料目录读写顺序、索引与详情锚点、业务工具参数和输出、原件哈希以及读回之后的工具轨迹。用实际观察复跑 T006 对应断言。触发时机由 T009 验证，正式入口由 T013 整合、T014 验收。[回归用例](T006.md#重新采集用例) · [验收指南](../quickstart.md#记录验收)

## 2026-11-23 隔离验收

Linux 下以 Codex CLI 0.171.0 的 `app-server` 临时线程和 `gpt-6.2-sol` 运行。样例第一轮在同名前缀仓库外目录执行 `head -n 1 README.md`，真实返回 `T006-OUTSIDE-TOOL` 及末尾换行。下一轮显式读取临时 `SKILL.md` 和本次参考文档，用宿主实测的会话、轮次、工具与回复作为已核实输入，完成一次保存。观测包含实际读取事件、临时入口和三份参考文档的摘要。[成对保存规则](../../../../packages/skills/src/profile/conversation-recording/references/paired-save.md) · [最终观测](../analysis/acceptance/t008-paired-save/observations.json)

资料根在临时业务仓库之外。原件六字节逐字节一致，详情保留命令、工作目录、原始输出和轮次锚点。附件和详情分别在文件事件 259、265 读回，随后在 270 发布索引，在 273 读回索引。该次发布通过刷新临时文件再创建硬链接完成，按真实工具调用和目标文件的 `CREATE` 事件共同确认。索引指向本轮详情，带中文和空格的附件路径编码后仍定位到原件副本。业务读取与内部维护使用同一文件工具，实际详情保留业务调用，确认后零新增写入，隔离仓库的工作区、暂存区及 HEAD 与基线一致。

T006 实现前重放的两项正向断言均因缺少详情文件而失败。首轮候选将输出末尾换行写成 JSON 转义，随后明确为原文块。一次候选仅对附件名的空格编码，触发既有附件回归，随后统一为逐段 UTF-8 百分号编码。最终观测重放三项 T006 相关断言全部通过，T002 样例回归 8 项通过。其余记录能力沿 T009～T014 的原任务继续验收。
