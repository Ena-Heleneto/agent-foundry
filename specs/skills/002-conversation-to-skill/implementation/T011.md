## 2026-11-23 已取得的验收证据

使用 Linux `flock` 验证同一目录上的会话锁。持锁时第二个同目录调用取锁失败，另一会话目录成功取锁，释放后第一会话可重新取锁。记录 Skill 入口及成对保存规则都引用持锁范围。[续写规则](../../../../packages/skills/src/profile/conversation-recording/references/resume-records.md) · [观测](../analysis/acceptance/t011-resume-records/observations.json)

用真实 Codex CLI 0.171.0 的临时模型会话处理两组合格假设输入。原成对文件来自 T010 实测，开启日为 11 月 23 日，候选输入用 11 月 24 日和 25 日检验按原日续写。三个持锁完成的步骤依次是第一次续写、重放同一批、第二次续写。原成对路径保持一致，重放时两份文件哈希一致且零写入，两条相同正文以不同轮次及事件保存。新详情保留同一可定位缺档及失去原文的原因，两次实际修复的定位保留，两次提交和各自结果回复仍跳过。首轮候选写入调用把目录描述符用于文件写入，收到 `EISDIR`，随后重新持锁核对并完成该批。上述输入用于验证续写规则的执行结果。[T010 来源](../analysis/acceptance/t010-event-capture/observations.json)

在隔离 CLI 状态中使用当前候选从仓库外恢复 T009 线程，并在仓库内使用 `exec resume`。宿主分别给出 `user` 和 `exec`，均完成普通 README 读取。记录区零打开、零新增或改写，原文件逐份哈希一致，实际工具轨迹只有规则读取、范围核验和普通任务所需操作，零会话正文补读。非交互复核的首个取证解析漏解 Code Mode 的嵌套回包，从同一实际轨迹解码了本轮元数据。[T009 来源](../analysis/acceptance/t009-recording-timing/observations.json)
