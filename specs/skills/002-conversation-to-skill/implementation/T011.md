## 2026-11-23 已取得的验收证据

使用 Linux `flock` 验证同一目录上的会话锁。持锁时第二个同目录调用取锁失败，另一会话目录成功取锁，释放后第一会话可重新取锁。记录 Skill 入口及成对保存规则都引用持锁范围。[续写规则](../../../../packages/skills/src/profile/conversation-recording/references/resume-records.md) · [观测](../analysis/acceptance/t011-resume-records/observations.json)

用真实 Codex CLI 0.171.0 的临时模型会话处理两组合格假设输入。原成对文件来自 T010 实测，开启日为 11 月 23 日，候选输入用 11 月 24 日和 25 日检验按原日续写。三个持锁完成的步骤依次是第一次续写、重放同一批、第二次续写。原成对路径保持一致，重放时两份文件哈希一致且零写入，两条相同正文以不同轮次及事件保存。新详情保留同一可定位缺档及失去原文的原因，两次实际修复的定位保留，两次提交和各自结果回复仍跳过。首轮候选写入调用把目录描述符用于文件写入，收到 `EISDIR`，随后重新持锁核对并完成该批。上述输入用于验证续写规则的执行结果。[T010 来源](../analysis/acceptance/t010-event-capture/observations.json)

在隔离 CLI 状态中使用当前候选从仓库外恢复 T009 线程，并在仓库内使用 `exec resume`。宿主分别给出 `user` 和 `exec`，均完成普通 README 读取。记录区零打开、零新增或改写，原文件逐份哈希一致，实际工具轨迹只有规则读取、范围核验和普通任务所需操作，零会话正文补读。非交互复核的首个取证解析漏解 Code Mode 的嵌套回包，从同一实际轨迹解码了本轮元数据。[T009 来源](../analysis/acceptance/t009-recording-timing/observations.json)

## 2026-11-24 隔离复验

在 T002 临时仓库使用 Codex CLI 0.171.0、`gpt-6.2-sol`、前台分页交互和 `workspace-write`，用合成会话验证更新前后的行为。旧版在仓库内恢复时完成了普通任务，原索引和详情的摘要均未变化，续写断言按预期失败。更新后的记录入口明确使用本次安装的规则，并从当前有效目录和匹配线程首行元数据核对归属。[观测](../analysis/acceptance/t011-effective-recovery/observations.json)

一条从新版开始的会话、一条先用旧版建档再更新安装的会话，均在原开启日之后实际恢复两次。每次继续使用原日期的索引和详情，新请求和实际回复各出现一次，可从两份文档定位到本次轮次。使用独立进程时区构造跨日条件，两次恢复均发生在各自案例开启日的次日。

在仓库内恢复仓库外来源、以及用 `exec resume` 恢复仓库内会话，两组分别结束普通业务，记录文档摘要保持一致，工具轨迹没有会话正文补读。初次监视把资料根的瞬时目录活动计入。按路径重跑后，实际活动限于 `.git`、`.agents`、`.codex` 和 `.aws` 空目录的创建及清除。未加载记录 Skill 的独立普通读取在同样的可写目录配置下复现相同事件，记录文档零写入。

另一条旧会话已有按旧规则跳过记录的历史。复验中模型虽读取了新版规则，仍报告需要恢复前启动目录并跳过续写。真实任务正常结束，既有记录保持，新增事件缺失。数次澄清规则及隔离候选复验仍复现该失败，T011 保留待验。T014 的最终来源复验及提交后恢复由原验收任务继续承担。

`@foundry/skills` lint、类型检查、39 项 Python 测试及 8 项隔离样例均通过。旧 T014 观测回放 12 项通过、2 项按旧观测的缺前置跳过。新候选的真实恢复结果见本节观测。Markdown 命中 ESLint 既有忽略规则，另行读回正文、引用及 Git 差异。

## 2026-11-24 对齐共用资料契约

同一失败会话再次恢复时报告当前安装的记录 Skill 与存储契约冲突。回查确认，共用资料契约的范围正文和「本次入口」字段仍要求使用载入历史目录前的工作目录。将两处改为恢复后的有效工作目录，并沿会话归属规则核验。原有资料契约中的链接和交接条件继续适用。[修正位置](../../../../packages/skills/src/profile/conversation-recording/references/storage-contract.md#资料根与适用来源)

重新隔离构建和同步，八份入口及引用与维护源逐文件一致。恢复采用原测试项目入口和普通 README 请求。原失败会话在会话开启日之后两次恢复，每次保持原索引与详情路径，既有内容保留，本轮请求和实际回复各记录一次，两份文件均可定位本轮。第二次恢复前的成对文件摘要与第一次恢复后的摘要一致。[修复前后实测](../analysis/acceptance/t011-contract-alignment/observations.json)

用同一份更新快照复验仓库外来源和 `exec resume`，两组均完成任务，未写入记录文档或补读会话正文。资料根里观察到的瞬时目录事件与未加载记录 Skill 的宿主对照一致。结合前轮的锁、断点、已丢失原文及提交边界取证，T011 的原验收条件已满足。提交后的正式入口运行仍由 T014 按验收指南核对。
