## 2026-11-23 隔离核验

使用 Linux 下的 Codex CLI 0.171.0 前台分页会话、`workspace-write` 和真实模型。隔离项目约定先读取候选及实际参考文档。临时探针按活跃轮次索引只读返回宿主元数据，由模型按文档作准入决定。准入结果通过独立工具返回，随后运行普通 README 读取。观测保留参考文档摘要、实际工具调用、入口目录、会话与轮次以及资料区前后哈希。[七轮实际判定](../analysis/acceptance/t007-session-scope/observations.json)

| 入口 | 实际观察 |
| --- | --- |
| 仓库子目录新开交互 | 活跃事件紧接 `session_meta`，实际匹配线程、TUI 来源及两个目录。模型允许记录并保存本次宿主临时归属。 |
| 同次启动第二轮，业务工具在仓库外运行 | 从宿主工具读回同一线程与仓库的临时值，沿用原工作目录和开启日。仓库外 README 读取正常完成。 |
| 同名前缀仓库外新会话，显式加载候选 | 活跃轮次确认为新交互，取得的首次目录和默认目录均在仓库外。模型跳过记录并完成业务。 |
| 仓库内 `exec resume` | 当前活跃轮次确认为 `exec`，沿用原线程，模型跳过记录并完成业务。 |
| 仓库内交互恢复 | 本次为 `user`，缺少当前启动凭据和可绑定的恢复前目录。模型跳过记录并完成业务。 |
| 仓库外恢复仓库内会话 | 使用原历史工作目录执行业务。缺少本次可信归属，模型跳过记录并完成业务。 |
| 仓库内恢复仓库外会话 | 以仓库内目录执行业务。此次目录改变不能提供合格归属，模型跳过记录并完成业务。 |

五个拒绝轮次的实际工具轨迹中没有记录正文补读。资料区 Inotify 无写入事件，两份既有文件逐份哈希保持一致。隔离候选只验证准入，T008 的实际成对保存和 T014 的正式来源消费分别由原 Task 验收。

两次早期候选偏差保留在归档中。显式加载的仓库外样例首次只按工具目录判断，未实际调用活跃轮次核查。后续一次同次启动样例把原始目录和日期与本轮未返回的字段比较，先判跳过，在业务开始前改正。更新文档明确核验顺序及两组字段各自来源后，七个最终候选轮次的判定均与宿主证据一致。

T002 样例回归 8 项通过。T006 默认回放仍为对照 6 项通过、实现前断言 6 项失败、缺前置 2 项未运行。内置候选格式检查因缺 PyYAML 未运行，使用仓库现有 YAML 解析器核对临时候选名称、描述与引用。对变更 Markdown 执行 `pnpm exec eslint --fix`，按现有忽略规则另行核对正文与本地引用。pnpm 预安装仍报告文档站无法加载 `@nuxt/nitro-server`。
