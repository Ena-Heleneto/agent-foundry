# T006 · 记录回归与实现前基线

上一轮说明下一项是 T006，将 T004 的时序与范围和 T005 的内容来源整理为可重复执行的回归基线。用户回复「开始吧」。本轮使用原 Task、规格、资料契约和已实测的入口与内容来源。[原 Task](../tasks.md) · [功能规格](../spec.md) · [资料契约](../../../../packages/skills/src/profile/conversation-recording/references/storage-contract.md) · [T004 取证](../analysis/recording-host.md) · [T005 取证](../analysis/content-source.md)

先用 T002 的真实临时 Git 仓库、原件及故障目标准备合成用例。在当前工作区对应状态运行可取得的真实对话和 Git 操作，分别保存宿主事件、业务输出、记录文件和 Git 状态。将真实观察值交给 Node 回归断言，确认待实现行为在对应正向断言失败，同时核对样例、对照及观察方式。记录流程仍由 AI 读取 Skill 并使用现有工具完成。

通过启动位置或宿主返回值建立真实会话归属，原始事件、验收观察和实际记录文件分别取证。归属可核实的跨启动恢复需要本次入口的独立可信证据，T004 当前受测环境缺这项信号，准备同一原会话两次恢复的判据并按缺前置记录。归属不明的恢复继续业务且保持记录和正文补读为零，候选的既有实测来源仍可回查。

保存实际回归命令、输入、预期和基线于本方案及所属验收目录。T007～T013 使用相同判据推进记录 Skill。T014 刷新正式安装来源、证明该版本实际消费，再用相同样例重新采集并运行断言。

### 观察数据的读回

- `ordinary` 保存两会话的实际身份、开启日、发言、工具、末轮及业务标记出现时的文件快照。用真实宿主行号填 `firstBusinessLines` 和 `firstPairReadbackLines`。由实际索引定位与详情核对 `retainedUserTurnIds` 和 `retainedCallIds`，内部调用按实际用途取证。
- 文件快照按资料根内真实相对路径索引。记录每个文件的字节数、SHA-256，Markdown 还要读回原文。若正式入口为安全基名做映射，按实际核对结果在对应会话提供 `recordKey`。用真实文件核对附件引用，摘要取实际读出的字节。
- `resumes`、`partial` 和 `commit` 保存当前 CLI 轮次、各阶段文件和工具事件。逐个核对资料区事件及会话正文补读。每次提交的写入观察起于该次步骤、止于相应结果回复，和同轮修复使用不同区段。已录入的修复与结果用实际详情定位关联到工具调用或发言。
- 有合法的恢复证据时，`eligibleResume.launches` 依顺序保存两次启动的证据定位、实际读回和事件去重结果，提交后合格恢复用 `commit.eligibleResume`。缺少来源时保留 `eligibleResume.unavailable` 和原因，对应项在断言结果中明确标为未运行。

## 2026-11-23 实现前结果

两会话在试验本地时间 11 月 22 日开启，11 月 23 日发首条。两条业务标记均已出现，退出后的记录快照仍为空。仓库外工具返回了预设第一行，附件原件的六字节摘要与 T002/T005 一致。实际索引位置得到 `EISDIR`，既有合成详情保持原样。首次提交退出 128，同轮补上修复与提交信息后重试退出 0，实际只提交 README。仓库外恢复、`exec resume` 及提交后的交互恢复均完成普通业务，暂无记录区写入及正文补读活动。

保存的基线为 **6 项对照通过、6 项记录断言失败、2 项缺前置未运行**。五项正向断言在缺少原日期详情时失败，索引缺口提示单独失败。当前维护源和隔离安装均尚无正式记录入口。两项归属可核实的跨启动恢复需等待可消费的本次启动证据。首次恢复对照的伪终端输入在恢复完成前进入输入框，未按原样提交。复验改为启动参数直接传同一提示，最终按实际完成的轮次归档。[真实观测](../analysis/acceptance/t006-recording-baseline/observations.json)

T002 隔离样例 8 项通过。用临时合成预期值核对断言本身，14 项均可通过。将首条读回、正文补读、索引缺口、提交写入及恢复去重各改错一处，五项相应断言均失败。这两组为断言自检，真实记录结论以上述基线为准。

新增测试文件的 ESLint 检查通过，`@foundry/skills` 类型检查通过。包级 lint 仍报告 `package.json` 的 `sh-syntax` 版本未走 catalog。对变更 Markdown 执行 `pnpm exec eslint --fix` 后，按现有忽略规则另行检查正文和路径。pnpm 的预安装另报文档站无法加载 `@nuxt/nitro-server`。
