# T009 · 记录触发、首条与末轮时机

用户在听取下一项为 T009、验证首条保存和正常末轮后回复「开始吧」。本轮沿 FR-002 和 T004 的实测入口，在记录 Skill 的 `references/recording-timing.md` 定义时机。正式入口整合仍由 T013 承接。[原任务](../tasks.md) · [功能规格](../spec.md) · [宿主时序与范围](../analysis/recording-host.md#记录时序与首期范围复验2026-11-23)

复用 T007 对当前轮次和归属的核验及 T008 的成对写入。项目入口收到用户消息时，先加载规则和取得本轮核验结果。合格消息先落盘并读回，随后另行调用业务工具。普通末轮先将准备发送的精确文本存入实际轮次的详情并核对索引，再发出同一文本。主动停止时核对已确认文件，并以真实宿主事件判断有没有发出末轮。[会话归属规则](../../../../packages/skills/src/profile/conversation-recording/references/session-scope.md) · [成对保存方案](T008.md)

复用 T002 临时仓库、伪终端和合成输入。在隔离项目用 `AGENTS.md` 接入候选 Skill，分别运行普通回复并立即退出、业务开始后 Ctrl+C 两个样例。比对候选实际读取、空白时文件数、首条成对文件读回与业务标记的顺序，以及退出后的详情文本或停止前的文件哈希。用宿主实际发出事件核对普通末轮，并在 T006 相关断言中重放首条顺序。观察证据覆盖当前候选与版本，正式安装来源的消费由 T014 验收。[记录验收](../quickstart.md#记录验收)

## 2026-11-23 隔离验收

在两个 T002 临时仓库中从项目子目录启动 Linux Codex CLI 0.171.0 的 `--no-daemon` 前台分页交互会话，使用真实 `gpt-6.2-sol` 和 `workspace-write`。隔离项目的 `AGENTS.md` 要求普通用户任务先调用临时 Skill。两轮通过实际文件工具读取了完整候选与时机规则，从宿主工具读回 `user` 轮次、线程及仓库归属。观测保留入口、规则摘要、实际读取和独立文件事件。[记录时机规则](../../../../packages/skills/src/profile/conversation-recording/references/recording-timing.md) · [最终观测](../analysis/acceptance/t009-recording-timing/observations.json)

空白时两组均为零份记录。首条保存和索引读回分别早于普通样例第 64 行、停止样例第 55 行的业务调用。文件系统事件也显示两组都先读回详情与索引，再出现业务标记。普通样例在第 79 行读回末轮准备文本，第 85 行宿主确认实际发出 `T009-对话记录合成基线`。收到答复即正常退出，详情中仍可逐字回查。停止样例在业务命令运行时按 Ctrl+C，宿主记录 `turn_aborted` 和 `interrupted`。停止时两份记录与首个业务动作时的快照及哈希一致，宿主没有发出普通末轮。

实现前重放的两项断言因缺少详情文件失败。初次启动验证将模型显示名称区分大小写，修正等待条件后进入真实会话。首轮时序探针把无对应业务调用的 README 读取计入业务，随后用实际工具调用、读回和独立业务标记复验，并从 Code Mode 工具的 `input_text` 回包读回完整规则。最终 T006 的首条时序断言和 T002 的 8 项样例回归均通过。跨午夜沿 T004 的已取证样例，正式入口由 T013 整合、T014 重跑完整验收。
