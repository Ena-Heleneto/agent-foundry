# T012 · 写入失败时保留已确认内容并重试

用户听取同次启动内的依赖安排，并确认 T012 包含 Skill 规则和故障验收后回复「开始吧」。依 FR-006 和 MVU-004，T012 使用 T008～T010 及 T011 已验的会话锁、断点和保存确认。原生跨启动合格恢复在其原验收处补证。[原任务](../tasks.md) · [业务闭环](../mvu.md#mvu-004-写入失败后带着缺口继续) · [T011 验收](T011.md)

在 `references/write-failures.md` 说明如何核对写入结果、识别受影响的目标和保留此前已确认范围。从 `SKILL.md` 和成对保存规则触达。失败后在继续业务前告诉用户实际缺口，给出已确认详情的可定位范围。恢复可写时重新取得同一会话锁，读回实际断点，补写仍有可靠原文的事件或附件，原文失去时沿原定位保留缺档。[已确认的保存契约](../../../../packages/skills/src/profile/conversation-recording/references/storage-contract.md#保存确认与失败恢复)

从 T006 索引失败基线起步，用 T002 临时仓库和真实 Codex 隔离候选。以目录占用索引、详情和附件目标，另在资料根位置设置普通文件。比较宿主可见缺口提示与独立业务调用的时序，核对详情可读范围、索引链接、附件 SHA-256 和资料区状态。解除索引及附件阻挡后沿同一线程重试，并对实际不可取得的原文核对缺档。T014 使用正式来源复验。[T006 样例](T006.md#重新采集用例) · [验收指南](../quickstart.md#记录验收)

## 2026-11-23 隔离验收结果

从候选入口和成对保存规则接入失败处理。T006 旧观测中的索引路径确实拒绝写入，但缺口提示时序断言失败。复验使用真实 Codex CLI 0.171.0 的 app-server、T002 临时仓库和显式核实的同次启动输入。四个隔离会话分别读取候选入口与失败规则，业务调用独立读取合成 README 首行并返回原文，隔离仓库的 Git 状态一致。表中位置是实际宿主轨迹中的行号。[失败处理规则](../../../../packages/skills/src/profile/conversation-recording/references/write-failures.md) · [验收观测](../analysis/acceptance/t012-write-failures/observations.json)

| 失败位置 | 路径的实际结果 | 提示、业务调用行号 | 可回查的保存结果 |
| --- | --- | --- | --- |
| 索引 | 目标由目录占用，`EISDIR` | 190、192 | 原有详情和当轮用户原文可查，提示给出当轮详情链接。 |
| 详情 | 目标由目录占用，`EISDIR` | 124、126 | 提示当轮用户原文和索引尚未保存，资料区没有未确认的索引链接。 |
