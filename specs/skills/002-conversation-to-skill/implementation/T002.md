## 样例边界与复用

在 `packages/skills/tests/conversation-workflow/helpers/sandbox.mjs` 提供 `createConversationSandbox()`，只使用 Node 内建模块和本机 Git。每次创建独占的系统临时根目录，内含真实目标 Git 仓库、两个子项目、名称与仓库同前缀但位于仓库外的对照目录、仓库外资料目录及独立输入目录。初始化合成基线提交并保留初始 revision，调用方可取得工作区、暂存区和 HEAD 基线。

现有 distribution sandbox 展示了临时目录、Git 环境隔离及 cleanup 的用法，但还承担安装器专用用户目录/环境设置。本次复用思路，不直接依赖它的安装协议或改写 HOME/CODEX_HOME。Git 子进程清除继承的 Git 覆盖项，禁用系统/全局 Git 配置、用户 hooks 和提交签名，以样例身份创建临时提交；不访问或改变用户真实仓库和 Git 配置。

提供已知二进制附件与 SHA-256、可实际执行的长输出命令描述及预期输出。写失败使用临时资料写入目录的文件/目录冲突产生实际 ENOTDIR，不靠 root 用户可绕过的 chmod；阻断时将已有目录移到保留位置，恢复后原有数据可继续使用。故障仅作用于样例资料，cleanup 仅删除该次临时根目录，支持重复清理。

## 验证安排

先在 `packages/skills/tests/distribution/conversation-sandbox.test.mjs` 写行为测试，复用项目已有 Node 测试约定与 lint 适用范围，不修改规则。测试捕获的破坏包括：资料误放进业务仓库、跨样例混用目录、Git 覆盖项导致越界、附件或长输出损坏、故障恢复丢数据、清理影响其他样例。

以动态导入并核对 helper 导出使未实现行为产生明确失败，再实现 helper 并验证真实文件系统、Git 和工具输出结果。继承 Git 覆盖项测试在独立子进程中运行，恶意路径仅指向测试自有临时哨兵，不能访问用户实际仓库。采用真实故障与 Git 操作，不以 mock 的调用次数代替结果。

运行 `node --test packages/skills/tests/distribution/conversation-sandbox.test.mjs`、目标包 lint 和 check-types。测试 helper 在新目录，原分发构建源码及其未提交改动保持原样；没有需要隔离执行的产品构建，本次样例的实际 Git 操作均在系统临时目录内。
