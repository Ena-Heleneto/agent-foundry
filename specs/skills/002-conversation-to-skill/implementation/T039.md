## 接收与保存

- 复用 T038 的会话归属与子轮实发校验。在 Codex 0.172.0 V2 已取证的数据中，原生 `collaboration.spawn_agent` 的 `task_name` 为 `recording_title`。从实际派发调用及 `SubAgentActivity` 核对同一父轮和子线程，再由首次子轮的实际回复验证回包。同轮后续补充按实际业务消息保存。按宿主身份识别命名任务，派发正文作为记录材料保留。
- 命名回包采用仅有一个字段的 `{"title": "短标题"}` 或 `{"title": null}`。保留首个通过校验的单行标题，在主记录 `foundry-recording` 元数据中写入 `titleCandidate`，附父轮、派发调用、子线程、子轮及实际回复时间。旧记录的前言可核对会话 ID 时，在接收有效标题时一并补齐元数据。空值、无效格式及来源不符时保留现有记录位置。
- 空闲父会话和安全父回调补记沿用 T038 的锁与恢复路径。候选和同次回传在同一主记录中原子写入并读回，已保存候选由正常续写保留。提交及相应回复期间沿用停写规则。

## 验收

先用已安装脚本的 Python 测试覆盖真实形状的派发和回包，核对有效标题、空值、重复回调、相同 JSON 的业务子代理、错误归属、提交及恢复。实际候选由主记录头部读回，普通业务消息仍可回查。从维护源刷新 Linux Codex CLI 0.172.0 的隔离安装，复用首条派发探针验证真实模型的标题可按父子身份接收。目录和链接的改名验收属于后续步骤。
