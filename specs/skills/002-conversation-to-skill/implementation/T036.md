# T036 · 主记录消息块分隔

2026-11-26，用户对按仓库规则检查过的 Markdown 样例回复「emm，可以吧这样子」。认可范围是主记录的分组与排版：用章节区分整组对话，不用框、不在正文行首加 `>`，消息标题与正文分开。对应 [FR-018 / SC-011](../spec.md#主记录样式) 和[原始分隔要求](../requirements/raw/2026-11-26-recording-message-block-separators.md)。本次保存方案，不涉及源码或已有记录的改写。

## 样式与边界

- 一份主记录使用一个一级标题。每组对话用二级标题，每条发起、补充或回复用三级标题。组间用横线和下组的二级标题区分；组内相邻消息用独占一行的 `---` 分隔，横线前后各留空行。
- 消息标题标识角色及类型，有可核实的时间时展示时间；正文另起一段，保持多行、空行、列表和代码块原样。示例中的组标题用于帮助阅读，不要求为每组另派子代理生成标题。
- 横线和标题只是展示内容，不作为解析依据。续写、去重和详情定位继续依赖可核实的会话、轮次及消息身份；需验证正文中的横线、标题或看似定位标记的文字不会被当成外层边界。主、子代理交错记录以后沿用该样式：迟到回复留在实际发生的组，能关联到原派发；本任务不实现其采集或时序。

1. 复用 T035 隔离夹具和 T033 本地试用基线，先固定普通对话的同轮补充、下一轮及恢复续写样例。分别使用多行原话、正文中的 `---`、代码围栏及类似消息标题的文字，核对边界和回读。对已有带 `>` 的记录补做定位与续写对照，不批量重写历史记录。
2. 对齐记录 Skill 的 `template/record.md` 和实际写入。现有入口与共用存储模块直接拼装主记录，单改模板不会改变输出。调整时保留原有保存时机、详情链接与恢复去重。
3. 用技能包当前的 ESLint 规则定向检查实际修改的模板。默认规则忽略 `src/**/*.md`，使用 `--no-ignore` 对目标文件做检查；不修改忽略规则。本轮会话中的候选样例用 `--fix-dry-run` 检查为零报错、零警告、无改写，这不等于实际产物已通过。现有 `detail.md` 的围栏格式报错不纳入本任务。
4. 刷新隔离安装并打开实际输出，核对不用组号也能辨认对话组、消息标题与正文能区分、同轮和跨轮边界不漏不重复，详情仍能打开。用 SC-011 核对普通对话；主、子代理交错的补验依赖 SC-010，不以样例通过代替实际验证。
