## 自动记录接入前置与推进条件

沿 FR-002 和 SC-001 验证普通 `codex` 启动后自动记录首条及后续轮次。项目安装可一并交付记录 Skill、Hook 配置和必要脚本。此前「开始吧」覆盖隔离准备和前置探针。本轮用户确认正常最终回复发送结束后自动保存并读回。交付仍沿 T034 的主记录和按轮详情布局。 [用户确认的原文](../requirements/raw/2026-11-25-recording-final-reply-after-send.md) · [记录验收](../quickstart.md#记录验收)

1. **安装与信任。** 在无预置信任的隔离状态通过 Codex 原生流程确认项目和该 Hook。读回项目内来源、启用状态和当前定义的信任结果。空白引导会话零建档。重新普通启动，核对首条「读一下 README」在读取文件前已保存并读回。预置信任的受控运行可用于观察后续回调，并单独记录首次启用的证据。
2. **回调范围。** 用 `UserPromptSubmit` 测试回调时即可取得的线程、轮次、交互归因、原会话归属和有效目录。先读取所需的宿主元数据，再按归属决定是否读取正文或写入。合格首条和续轮在业务前保存并读回，重复原话按实际轮次各保存一次。可信 `exec`、`exec resume`、仓库外和归属不符的恢复另行核对零新增、零续写及零额外正文补读。
3. **正常最终回复。** 优先验证 `Stop` 是否能稳定提供对应轮的实发全文。用两轮零模型工具调用的分段回包，取证宿主发送结束、文件写入及重新打开读回。按实际会话和轮次关联同一对话组，自动保存并读回完整原文。写入确认后同轮重复事件保持幂等。按 FR-008 跳过提交及对应结果回复，按 FR-006 和 FR-007 处理写入失败与发送后保存前的中断。 [技术前置](../research.md#技术前置验证)

前置通过后，从实际交付来源刷新隔离安装，核对宿主实际使用的文件和组件，再按验收指南完成恢复、Git 忽略、附件、提交停写、失败补写和记录去重。若采用 Hook，完整验收通过后移除它接替的旧记录逻辑，重新安装并复验最终版本，再交接 T033。 [最终来源复验](../quickstart.md#正式来源复验)

原生信任与首末轮联动已在普通 `codex` 的合成回包探针中通过。两条临时 Hook 按同一轮次保存，真实读取 README 的首条和零工具续轮均取得时序与完整性证据；可信 `exec` 及 `exec resume` 也已核对零新增、零续写和零额外正文补读。后续复用探针核对正式交付的 Hook 与脚本，补齐完整范围及业务场景。 [隔离验收记录](../analysis/recording-acceptance.md#t035-原生首次启用与首末轮联动)

## 独立 Hook 入口与交付

主线构建使用 `pnpm --filter @foundry/skills build`。Vite 递归复制启用的 Skill 目录。从 `dist/skill/profile/conversation-recording/` 运行 `install.py`，将 Skill 装入目标工作树的 `.agents/skills/conversation-recording/`，并按以下映射登记项目 `.codex/hooks.json`。 [构建复制逻辑](../../../../packages/skills/build/plugins/vite-plugin-skill/index.ts#L223-L228) · [安装器](../../../../packages/skills/src/profile/conversation-recording/install.py)

| Codex 事件 | Python 入口 | 职责 |
| --- | --- | --- |
| `UserPromptSubmit` | `scripts/user_prompt_submit.py` | 在业务开始前保存并读回用户原话，处理同轮补充。 |
| `PostToolUse` | `scripts/post_tool_use.py` | 补记已完成工具的调用、结果和附件，跳过 Git 提交步骤。 |
| `Stop` | `scripts/stop.py` | 从 `last_assistant_message` 取得实发回复，在发送结束后保存并读回。 |

`recording/events.py` 提供宿主事件采集，`recording/record.py` 提供会话范围核验、锁及文件存储。安装器按归属清单替换旧配置中的记录命令，保留项目其他 Hook 及原生信任流程。 [初次拆分的复验](../analysis/recording-acceptance.md#t035-独立-hook-入口复验)

## 2026-11-26 三个 Hook 各自处理事件

用户明确「三个 hook，三个脚本，逻辑解耦，不互相调用」。`scripts/` 仅放三个事件入口，项目安装器移到 Skill 根目录，宿主事件采集、会话归属和文件存储放在 `recording/`。三个脚本分别处理用户原话、工具结果补齐及最终回复。它们直接读取宿主提供的事件和同一份记录，共用会话锁、详情格式和原子写入。
