# 契约 · 记录、提炼、分析与协作 Skill

本文件记录阶段职责和可观察结果。记录候选沿现有主记录、详情、附件和交接约定设计，实施时核对真实安装的 Skill 资源与实际记录的一致性。 [资料契约附件](../../../../packages/skills/src/profile/conversation-recording/references/storage-contract.md)

## 记录入口

首期接入本仓库根目录或子目录内用户开启的 Linux 交互式 Codex CLI 会话。项目级安装可同时交付记录 Skill、Hook 配置及必要脚本。若候选需要信任，安装完成时从 Codex 读回实际项目来源、启用状态与当前定义的信任结果。空会话及信任确认零建档。用户按日常方式启动后发出的首条正常对话消息就进入记录流程，零模型工具调用和未选用记录 Skill 的合格轮次同样进入。

接入需提供可核实的宿主会话、轮次、交互归因、原会话归属和当前有效工作目录。首次建档使用实际开启日，项目记录已启用且恢复的两个位置均可核实属于目标仓库时续写。非交互或范围不成立时，记录器零新建、零续写、零额外正文补读。范围核对早于正文处理和写入，工具事件沿已核定的会话归属关联，工具工作目录留作详情字段。回调时可用的宿主字段由版本实测确定。 [技术前置](../research.md#2026-11-25-自动记录的技术前置)

| 输入                                                 | 可观察产物                                             |
| ---------------------------------------------------- | ------------------------------------------------------ |
| 已验证的会话与轮次、用户原话及实际开启日 | 每个合格轮次恰有一个对话组，原话在业务动作前保存并读回 |
| 将实际发送的正常最终回复全文及可核实的发送时点 | 全文保存并读回早于首段发送，保存原文与实发全文逐字一致 |
| 可取得的进度、工具参数与输出、原始附件               | 项目内 Git 可见的详情及附件原件，由本轮「查看经过」打开，同名异内容原件各有对应链接 |
| 中断、写入失败及归属可核实的恢复                     | 原文件续写、可识别的缺口及原文仍可取得时的写入重试     |
| 归属无法核实的恢复                                   | 保留既有记录，用户任务继续，零写入和零正文补读         |
| 提交步骤及其结果回复                                 | 该步骤对应的主记录、详情和附件写入次数为零               |

当轮无业务动作时，先完成用户原话的保存和读回，再处理正常最终回复。仅为保存、核对记录产生的内部工具活动不进入待记录事件，业务工具、用户要求查阅记录及提炼和分析派发按实际用途留存。保存失败先标记缺口并继续任务。归属可核实的恢复核对已保存断点并续写新内容，写入前关闭且原文丢失的部分保留缺档。提交例外按每次实际步骤匹配，用户请求、提交前修复及同轮提交失败后重试前的修复照常记录，每次提交及各自结果回复均跳过。实时记录与恢复使用相同边界。 [功能规格](../spec.md) · [数据模型](../data-model.md#会话记录)

正式安装核对项目内的实际 Skill、Hook 配置和脚本来源。若采用 Hook，候选先通过完整的记录验收，再移除被接替的旧记录逻辑。最终安装复验宿主实际使用的新入口和每轮只生成一个对话组。正常回复若只有发送后保存的证据，仍缺发送时序验收。 [记录验收](../quickstart.md#记录验收)

## 父代理及子代理

| 流程 Skill | 入口条件及输入                                                     | 阶段产物                                                   |
| ---------- | ------------------------------------------------------------------ | ---------------------------------------------------------- |
| 记录       | 首条正常对话消息触发建档，按实际步骤跳过指定事件，归属可核实的恢复续写新内容 | 主记录、详情、附件及已确认的保存范围和缺口供其他阶段读取 |
| 提炼       | 本仓库已确认保存的对话足以支持用户特点，提供可定位的对话与来源目录 | 每项一份特点文档，含情境、证据解释和原始块定位             |
| 分析       | 提炼文档足以形成或修订规则，提供有依据的特点和当前有效的规则范围   | 一份协作 Skill 的规则与依赖资源，以及留存在本地的依据关联  |

记录入口向父代理提供已确认材料的可用线索。父代理分别判定两个阶段，已确认的特点可以在后续会话中直接成为分析输入。首次自动提炼以新流程保存并确认落盘的本仓库记录为输入，旧影子画像对话作为历史资料保留。

每次派发交接要关联父会话、轮次、实际子线程、阶段及范围内的证据定位。分析还记录派发时的规则版本。子代理回传候选产物和所用依据，父代理读回并核对来源、确认状态及当前版本后再采纳。派发失败或回传未确认时继续使用当前有效产物。 [数据模型](../data-model.md)

真实派发时，记录入口同时保存主会话可取得的派发、交互及回传工具名称、完整参数和输出、发生顺序及相应缺口，并关联父轮次和实际子线程。宿主事件用于对照真实来源；派发结果存在不等于详情已经完整保存，不要求独立采集子线程内部日志。

多个父会话向同一份协作 Skill 回传时，子代理只交付独立候选。父代理的版本核对与规则、依据关联和目录采纳在同一次写入协调内完成，删除使用相同边界并推进版本。两个候选基于同一版本时，先采纳者推进版本，另一项保留为过期候选，不覆盖较新结果或清理其有效依据；仅在重新核对最新材料和版本后，后续有效处理才可形成新结果。部分保存失败不报采纳成功，沿最后确认版本及实际交接恢复。 [并发验收](../quickstart.md#共享规则并发采纳验收)

## 协作 Skill 的消费和维护

候选探针通过后，从实际交付来源刷新隔离正式入口，核对版本或源码快照、完整正文及必要资源。记录入口取证宿主实际加载及执行已安装组件。提炼和分析取证父、子代理读取对应安装副本及所用资源。后续维护或清理改动来源时复验受影响流程。 [最终来源验收](../quickstart.md#流程-skill-最终来源消费)

最终目录依照 Agent Skills 规范交付，可按兼容代理常规方式加载。正文使用适合跨项目协作的规则及适用情境，所需资源通过目录内相对路径定位。消费端仅凭交付目录即可应用，原始对话和依据在本地回查。 [Agent Skills 规范](https://agentskills.io/specification#file-references)

用户删除本地当前的一条规则时，同步清理独占提炼依据及失效关联，共享依据继续服务其他规则。旧分析返回时依据当前删除决定处理，后续有效的新一轮可按原始材料重新形成规则。
