# 契约 · 记录、提炼、分析与协作 Skill

字段含义、成对文档定位、已确认范围及交接内容统一沿[资料契约附件](../../../../packages/skills/src/profile/conversation-recording/references/storage-contract.md)。本文件保留各阶段职责和可观察结果，不另维护一份字段副本。

## 记录入口

首期记录工作目录位于本仓库根目录或子目录、由用户开启的交互式 Codex CLI 会话。AI 读取记录 Skill，直接使用宿主已有工具。以开启时的有效工作目录和交互入口证据核定源会话，在首条对话消息出现时按宿主提供的稳定身份建档。恢复同时核对原会话的归属和本次交互入口的有效工作目录，后者取宿主切换到历史目录前的来源。工具事件按已核定的会话归属关联，其工作目录用于详情回查。

| 输入                                                 | 可观察产物                                             |
| ---------------------------------------------------- | ------------------------------------------------------ |
| 已验证的会话身份、用户发言、工具活动、回复及关闭信号 | 按日期保存成对记录，索引直接定位对应详情和实际改动文件 |
| 可取得的完整工具参数与输出、原始附件                 | 对应详情块及本地附件原件                               |
| 中断、写入失败及恢复                                 | 原文件续写、可识别的缺口及原文仍可取得时的写入重试     |
| 提交步骤及其结果回复                                 | 该步骤对应的索引、详情和附件写入次数为零               |

正常发言先落盘再执行对应会话工作。保存失败先标记缺口并继续任务。恢复时核对已保存断点并续写新内容，写入前关闭且原文丢失的部分保留缺档。提交例外按实际步骤匹配，用户请求和提交前修复照常记录，提交步骤及结果回复在实时记录与恢复中均跳过。具体来源随宿主版本取证。 [功能规格](../spec.md) · [技术调研](../research.md)

## 父代理及子代理

| 流程 Skill | 入口条件及输入                                                     | 阶段产物                                                   |
| ---------- | ------------------------------------------------------------------ | ---------------------------------------------------------- |
| 记录       | 首条对话消息触发建档，按实际步骤跳过指定事件，恢复时续写新内容       | AI 用现有工具保存索引、详情、附件和缺口供其他阶段读取      |
| 提炼       | 本仓库已确认保存的对话足以支持用户特点，提供可定位的对话与来源目录 | 每项一份特点文档，含情境、证据解释和原始块定位             |
| 分析       | 提炼文档足以形成或修订规则，提供有依据的特点和当前有效的规则范围   | 一份协作 Skill 的规则与依赖资源，以及留存在本地的依据关联  |

记录入口向父代理提供已确认材料的可用线索。父代理分别判定两个阶段，已确认的特点可以在后续会话中直接成为分析输入。首次自动提炼以新流程保存并确认落盘的本仓库记录为输入，旧影子画像对话作为历史资料保留。

每次派发交接要关联父会话、轮次、实际子线程、阶段及范围内的证据定位。分析还记录派发时的规则版本。子代理回传候选产物和所用依据，父代理读回并核对来源、确认状态及当前版本后再采纳。派发失败或回传未确认时继续使用当前有效产物。 [数据模型](../data-model.md)

真实派发时，记录入口同时保存主会话可取得的派发、交互及回传工具名称、完整参数和输出、发生顺序及相应缺口，并关联父轮次和实际子线程。宿主事件用于对照真实来源；派发结果存在不等于详情已经完整保存，不要求独立采集子线程内部日志。

多个父会话向同一份协作 Skill 回传时，子代理只交付独立候选。父代理的版本核对与规则、依据关联和目录采纳在同一次写入协调内完成，删除使用相同边界并推进版本。两个候选基于同一版本时，先采纳者推进版本，另一项保留为过期候选，不覆盖较新结果或清理其有效依据；仅在重新核对最新材料和版本后，后续有效处理才可形成新结果。部分保存失败不报采纳成功，沿最后确认版本及实际交接恢复。 [并发验收](../quickstart.md#共享规则并发采纳验收)

## 协作 Skill 的消费和维护

三个流程 Skill 的候选探针通过后，仍须从实际交付来源刷新隔离正式入口，核对版本或源码快照、完整正文及必要资源，并取得父/子代理读取对应安装副本的真实证据。后续维护或清理改动这些来源时重复核对并复验受影响流程；直接读取源码不代替正式入口消费。详细门禁见[验收指南](../quickstart.md#流程-skill-最终来源消费)。

最终目录依照 Agent Skills 规范交付，可按兼容代理常规方式加载。正文使用适合跨项目协作的规则及适用情境，所需资源通过目录内相对路径定位。消费端仅凭交付目录即可应用，原始对话和依据在本地回查。 [Agent Skills 规范](https://agentskills.io/specification#file-references)

用户删除本地当前的一条规则时，同步清理独占提炼依据及失效关联，共享依据继续服务其他规则。旧分析返回时依据当前删除决定处理，后续有效的新一轮可按原始材料重新形成规则。
