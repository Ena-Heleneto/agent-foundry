# 从 Codex 对话生成协作 Skill 的需求讨论与确认

## 已确认

1. **跨项目提炼与分析。** 同一用户在本仓库不同项目目录的对话材料可以汇总成一份协作 Skill。提炼文档保留来源项目及原始对话块的位置，便于回查。
2. **工具详情保留范围。** 详情保留完整工具参数、输出和附件原件。详情块关联实际保存的附件，无法取得的内容标明缺口。
3. **正常会话中的写入失败。** 标记缺口后继续当前工作。后续可根据可核实的信息补记，提炼基于已确认落盘的材料。

4. **本版会话类型。** 用户于 2026-11-19 在规格澄清中选择 A，本版记录用户打开的交互式 Codex CLI 会话。 [规格澄清](../../spec.md#clarifications)

5. **仓库目录范围。** 用户于 2026-11-19 在回答跨项目材料范围时纠正「不是，你理解错了，就是这个仓库目录下的」。自动记录和提炼的会话来源限定在本仓库根目录及子目录，仓库内不同项目目录可共同提供依据。已同步规格及相关规划和验收材料。 [规格澄清](../../spec.md#clarifications)

6. **首次自动提炼的输入。** 用户于 2026-11-19 选择 A。首次使用新流程保存并确认落盘的本仓库记录，旧影子画像记录作为历史资料保留。 [规格澄清](../../spec.md#clarifications)

## 后续取舍

- **惰性触发的判断。** 用户明确纠正一次即可触发提炼，还是等到同类行为反复出现？可以让明确偏好或纠正单独成为提炼依据，让普通观察随证据积累，让分析在有实际规则变化时启动。
- **子代理线程的资料。** 主会话能取得的子代理活动作为工具详情记录。子代理线程的独立留存作为后续范围议题。
- **旧 `profile` 集合的迁移。** 旧 `shadow-profile` 的归档和退役范围已明确。是否沿用旧 `conversation-recording`、`conversation-summary`、`conversation-analysis` 中可复用的部分，由后续规划核对。

需求入口见[规格提示词](../prompts/2026-11-19-conversation-to-skill.md)。
