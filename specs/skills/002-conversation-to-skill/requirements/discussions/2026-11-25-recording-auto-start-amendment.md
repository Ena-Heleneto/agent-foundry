# 会话记录自动启动需求追加草案

2026-11-25 · 待评审。范围限于第一里程碑的会话记录。评审确认前，正式验收沿用现行规格。[追加需求原文](../prompts/2026-11-25-recording-auto-start-amendment.md) · [现行规格](../../spec.md)

## 隔离实测与候选方案

- 仅安装记录 Skill 的普通交互已复现漏记。相同首条输入在模型未选用 Skill 且零工具调用时收到正常回复，项目内零主记录。[同文首轮对照](../../analysis/recording-acceptance.md#t035-同文首轮对照)
- Hook 提醒可以促使模型读取入口。三个真实模型样例取证止于读取 Skill。受控回包样例虽收到提醒，模型仍零工具调用，项目零记录。[Hook 隔离对照](../../analysis/recording-acceptance.md#hook-是否会漏启动的隔离对照)
- Hook 直接保存是候选。在同一交互会话的首轮和后续轮次，模型工具调用均为零，`UserPromptSubmit` 均在回环端点收到对应请求前写入用户原话，端点收到请求时可读到原文。两次 `Stop` 保存的原文都与实际回复一致，写入时点均晚于宿主的最终回复事件。通过末轮验收仍需取得回复发出前保存并读回的证据。[Hook 实测数据](../../analysis/acceptance/t035-isolated-recheck/hook-probe.json)
- 隔离项目首次交互启动出现 Hook 信任提示。`codex exec` 在未信任时完成业务且零 Hook 执行，信任后 `UserPromptSubmit` 和 `Stop` 都执行。候选须在记录读写前核实是否为合格的项目内交互轮次。[信任与非交互对照](../../analysis/recording-acceptance.md#hook-是否会漏启动的隔离对照)

## 拟修订条文

### FR-002

项目完成经评审确认的记录交付安装后即启用记录。用户在本仓库根目录或子目录按日常方式运行 `codex` 并发送消息，无需手改配置、点名 Skill 或执行记录启动命令。每个符合记录条件的交互轮次自动进入记录流程，包括模型未选用记录 Skill 且没有发起任何工具调用的轮次。空会话保持零记录，收到首条用户消息时按 FR-003 在项目内建立 Git 可见的主记录，后续轮次按会话续写。

纳入记录的用户发言按原文先保存、再读回，随后才开始对应业务动作。无需工具且没有其他业务动作的轮次，也须完成用户原话的保存和读回，再保存并读回正常最终回复。正常最终回复全文须先保存并读回，再向用户发送逐字相同的文本。主记录可独立保存，已有过程按 FR-004、FR-005 随本轮推进写入。写入失败、恢复及不可控中断、Git 提交停写分别按 FR-006、FR-007、FR-008 处理。

### SC-001

在隔离 Git 仓库通过经确认的交付入口安装记录功能，在两个项目目录各按日常方式并行打开交互会话。发送消息前，各会话的主记录和详情均为零。各会话收到首条消息时建立一份项目内 Git 可见的主记录，至少再发送一条后续消息并续写同一文件。每个合格轮次恰有一个对话组。首轮和后续轮次各覆盖至少一个模型未选用 Skill 且零工具调用的普通回复样例，并核对用户原话先于最终回复保存并读回。含业务动作的轮次中，用户原话在首个对应业务动作前已保存并读回。

所有纳入记录的轮次均可逐字回查用户原话。正常最终回复均在开始向用户发送前全文保存并读回，读回内容与实际发出的全文逐字一致，正常退出后仍可回查。每组可按本地日期、宿主轮次和记录顺序定位，有实际详情的组可打开本组详情。仓库外的交互会话及非交互式新会话的新增主记录和详情均为零，非交互式恢复零续写、零额外正文补读。合规恢复和提交停写按 SC-003、SC-004 验收，旧索引版生成产物按 FR-003 的切换要求核对移除结果。

## 受影响的约束与待确认决策

1. **Hook 配置能否随安装交付。** FR-002 及 11 月 24 日的确认将交付限定为仅安装记录 Skill、无需额外配置。评审需确认能否由同一项目级安装入口一并交付 Hook 配置，并沿用用户免手改配置、免另行启动的使用方式。[安装约束原文](../raw/2026-11-24-recording-install-enables.md)
2. **宿主能否代行记录及交付处理脚本。** FR-001 和 11 月 20 日的确认规定三个流程由 AI 按 Skill 直接使用宿主已有工具执行，并明确无脚本。若候选需要宿主直接写入，须确认第一里程碑可交由宿主执行哪些记录动作。需要配套处理脚本时，还须单独确认能否随项目级安装交付以及允许的职责范围。后续提炼和分析沿用现行约定。[无脚本确认](../raw/2026-11-20-no-scripts.md)
3. **首次 Hook 信任如何计入启用。** 既有要求以安装完成即启用。若需用户确认信任，评审需决定是否允许一次明确确认并将其计入安装过程。若确认只能在首次普通启动时完成，则须明确是否接受确认完成后才启用，并相应修订 FR-002 和 SC-001 的首次启动口径。未确认或拒绝时如何向用户说明尚未开始记录，也需随该决定明确。[安装即启用原文](../raw/2026-11-24-recording-install-enables.md) · [信任实测](../../analysis/recording-acceptance.md#hook-是否会漏启动的隔离对照)

交付范围和首次启用的评审结果将用于同步计划的交付约束、T035 的正式来源核对和 T033 的手动试用口径。[现行计划](../../plan.md) · [任务顺序](../../tasks.md#依赖与实际执行顺序)

## T035 待补实测证据

从评审确认的实际交付来源在隔离仓库复验。以下各项记录对应的会话、轮次、时间顺序和项目内文件结果，沿现有验收资料区保存。T035 通过后，再按既有顺序由 T033 完成真实工作区试用。[现行验收指南](../../quickstart.md#记录验收) · [验收顺序](../../spec.md#记录验收与试用顺序)

1. **正式安装与普通启动。** 核对实际来源、安装文件、宿主版本、项目级发现位置与适用信任状态，核对必要资源可读及旧入口发现数为零。从全新隔离项目按评审认可的安装条件启动，取证用户直接发普通消息即可记录。若采用 Hook，补齐安装至首次启用的实际步骤和未信任的对照结果。[现有 Hook 探针](../../analysis/recording-acceptance.md#hook-是否会漏启动的隔离对照)
2. **空会话、并行首轮与后续轮次。** 两个目录交互会话均先验证空白时零建档，再完成首轮及续轮。覆盖跨午夜后才发送首条的原开启日归档、相同原话在不同轮次各保存一次、项目内 Git 可见与退出后可读。现有并行复验中一个会话未在窗口内取得末轮，仍须取得两个会话的完整结果。[并行复验](../../analysis/recording-acceptance.md#轮次核验和入口链接修正复验)
3. **原文保存时序与零模型工具调用。** 取得普通交互首轮及后续轮次未选用 Skill、零模型工具调用，且用户原话和正常最终回复完整落盘的证据。含业务动作的轮次另核对用户原话保存、记录流程读回、首个对应业务动作的顺序。将正常回复的全文保存、读回与向用户发送的时点关联，分段发送时取首段，并核对读回原文与实际发出全文逐字一致。受控对照已取证用户原话在请求到达端点前写入、`Stop` 在最终事件后写入。[现有时序数据](../../analysis/acceptance/t035-isolated-recheck/hook-probe.json)
4. **范围排除。** 在同一正式来源下覆盖仓库外交互、仓库内 `codex exec`、对已有会话的 `codex exec resume`，以及原归属不符或无法核实的交互恢复。核对业务正常完成、零新建、零续写、零记录所需的额外正文补读。若采用 Hook，覆盖已信任条件下宿主触发但记录范围排除的结果。此前的非交互记录快照对照仍缺独立的正文读取证据。[现有范围对照](../../analysis/recording-acceptance.md#2026-11-25-t035-仅安装-skill-补验)
5. **合规恢复。** 在同一项目内跨日交互恢复两次。核实原会话归属和恢复后的有效工作目录，确认原开启日和主记录路径一致、已有内容保持、新事件各保存一次，正常回复仍符合发出前的读回时序。用最终交付来源复核已取得的仅安装 Skill 恢复正例，并补齐提交后的合规恢复。[已有恢复结果与缺项](../../analysis/recording-acceptance.md#2026-11-25-t035-仅安装-skill-补验)
6. **Git 提交停写。** 实跑成功提交及同轮首次失败、修复后重试。分别从每次提交步骤开始取证至对应结果回复发出，记录写入次数和记录引入的工作区、暂存区新增差异均为零。原请求、提交前和两次提交之间的修复以及后续普通对话均可回查，普通轮次的记录在 Git 工作区可见。[既有提交验收口径](../../quickstart.md#记录验收)

T035 还需补齐现行验收中主动停止后的缺档保留、写入恢复后的正常末轮、长输出与流式详情的证据，并按最终来源复核受影响的详情链接、附件和 Git 忽略续写用例。[隔离复验缺项](../../analysis/recording-acceptance.md#自动触发失败与其余未验项) · [现行 T035 方案](../../implementation/T035.md)
