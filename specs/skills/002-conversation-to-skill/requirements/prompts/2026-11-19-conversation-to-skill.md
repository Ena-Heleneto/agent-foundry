# 从 Codex 对话生成协作 Skill 的规格提示词

以下内容可直接交给 `$speckit-specify`。 [需求讨论与确认](../discussions/2026-11-19-open-questions.md) · [Agent Skills 格式规范](https://agentskills.io/specification)

```markdown
$speckit-specify SPECIFY_FEATURE_DIRECTORY=specs/skills/002-conversation-to-skill

请为 `packages/skills` 创建《从 Codex 对话生成协作 Skill》规格和需求检查清单。下文的迁移与运行行为属于功能的交付和验收范围。

## 目标

持续记录我与 AI 的实际协作对话，从中提炼有依据的编码习惯、思考与决策方式、沟通偏好和协作模式，再整理为可执行的协作规则。记录、提炼和分析分别由独立的 Skill 定义，首期在 Codex CLI 中运行。最终产物是一个通用协作 Skill，由支持 Skill 的 Agent 按常规方式读取和应用。

## 旧影子画像退役

将 `packages/skills/src/profile/shadow-profile/` 中的旧 Skill 原样归档到本 Spec 的 `archive/shadow-profile/`。核对归档完整后，移除 `.agents/skills/shadow-profile/` 安装副本，并撤下旧入口的启用与交付配置。验收时检查正常安装或同步后能否发现旧入口，预期发现数量为零。保留历史规格和已有对话资料的原始依据。

## 记录 Skill

- 用户打开 Codex CLI 会话即自动纳入记录。新的可记录内容产生时，优先保存已发生的内容，再继续该会话的工作。正常结束时保存已产生的末轮回复，包括用户没有再发消息的情况。
- 以日期为总目录，日期下分别设置索引和详情目录。每个会话在两个目录中各有一份记录文档，并保留来源项目。不同会话并行进行时，各自写入对应文件。建议按会话首次开始的本地日期归档。
- 每轮对话在索引和详情中各占一个可对应定位的块。索引说明本轮内容、结果和实际改动的文件。详情按发生顺序保存可记录的用户与助手发言、工具调用的完整参数和输出，以及会话和工具调用中的完整附件。附件原件保存在本地资料区，详情块提供可定位的引用。无法取得的内容标明缺口。
- 正常会话中写入失败时，标记受影响的对话块和缺失内容，再继续用户任务。资料区暂不可写时，在会话中标明缺口，并在可以落盘时补记缺口和能够核实的内容。提炼仅使用已确认落盘的材料。
- 会话从打开开始，涵盖 CLI 关闭、指令终止及用户停止等结束或中断场景。不可控中断允许缺档。使用 `resume` 时核对索引和详情的断点，在原会话文件中续写，包括跨日恢复的情况。只补可核实的缺项，并按会话和对话轮次识别重复内容。原始记录可反复用于提炼和分析。
- 用户要求代理撰写提交说明并提交时，提交动作、结果及提交后的回复仍正常记录。验收以自动落盘给业务仓库工作区和暂存区引入的新增差异为零为准。建议将持续写入的资料存放于仓库外的本地资料目录。

## 提炼 Skill

父代理惰性判断已落盘的对话材料是否足以提炼有依据的用户特点，满足条件时启动子代理。子代理读取适用范围内的索引和详情，可以综合同一用户在不同项目的对话材料。每条特点写成独立文档，标注适用情境、来源项目、关联的原始对话块及支持该特点的依据。区分用户明确表达、反复出现的行为和仅适用于一次任务的决定。

## 分析 Skill

父代理独立判断已有提炼结果是否足以形成或修订规则，满足条件时启动子代理。子代理将特点整理成具体、可执行且带适用情境的协作规则，支持将多个项目的材料汇总成一份协作 Skill。规则保留到提炼文档的关联。特点和规则依据实际材料自动形成，生成后即可按常规方式使用和维护。

记录、提炼和分析各自有独立的 Skill 目录，定义自己的触发条件、输入和产物。生成的协作 Skill 也有独立的完整目录，包含带有效 `name` 和 `description` 的 `SKILL.md` 以及正文实际引用的资源。把该目录带到另一个项目或支持通用 Skill 的 Agent 中，仅凭目录内容即可发现、读取并应用规则。原始对话和溯源资料保存在本地资料区。

## 删除规则与再次生成

用户可以删除某条生成规则，并清理仅支撑该规则的提炼文档及关联。仍支撑其他规则的提炼文档继续为对应规则提供依据。原始对话可供后续处理。后续再次满足提炼和分析条件时，已有或新增的对话材料都可以使同一条规则自然形成。

## 验收重点

- 实际启动两个 Codex CLI 会话，验证自动纳入、并发独立记录、索引与详情对应及正常退出时的末轮记录。
- 使用含工具调用和附件的对话，验证详情可回查完整参数、完整输出和附件原件。
- 在正常会话中验证写入失败后的缺口标记和任务继续执行。恢复后核对补记内容与可取得的事实一致。
- 验证异常中断的缺口可识别，跨日 `resume` 仍写回同一会话的文件，重复恢复时已有对话块只保留一份。
- 验证真实提交后继续记入提交结果和回复，业务仓库因记录产生的新增 Git 差异为零。
- 分别验证父代理在两个阶段满足条件时派发子代理，特点可追溯到原始对话，规则可追溯到提炼结果。
- 使用两个项目的对话材料生成一份协作 Skill，验证来自不同项目的规则依据均可回查。
- 验证删除规则会清理独占依据、保留共享依据，后续可从保留的对话重新形成规则。
- 将协作 Skill 目录带到另一个项目，验证支持 Agent Skills 的 Agent 能实际应用其中的规则。

需求确认和仍待讨论的事项见本 Spec 的 `requirements/discussions/2026-11-19-open-questions.md`。把已确认要求、待确认决策和建议默认值写清楚。Codex CLI 的具体接入方式、落盘机制及触发条件的实现留给后续规划。
```
