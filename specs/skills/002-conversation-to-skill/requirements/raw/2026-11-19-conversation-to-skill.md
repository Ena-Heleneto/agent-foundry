# 从 Codex 对话生成协作 Skill 的原始需求

以下为用户最初提供的需求原文。 [后续需求确认](../discussions/2026-11-19-open-questions.md)

```text
我现在有一个原始需求，我们需要讨论一下，然后生成 speckit-specify的提示词， 我们移除项目中的影子画像功能，将影子画像的skill移动到之后的spec的存档目录，然后删除 .agents/skills中的skill， 接下来是原始需求 目的是为了记录分析与ai的对话，将自己的编码习惯，思维惯性等整理成一组skill,能够与ai更好的协作

记录、提炼、分析分别由三个独立的 Skill 定义。当前在 Codex CLI 中使用，由父代理判断提炼与分析的启动时机，并交给子代理执行。最终生成的协作 Skill 可脱离原项目、Codex CLI 和上述父子代理流程，像普通 Skill 一样被读取和使用。

我们的skill要有完整的文件结构，并且符合通用规范





记录





记录时机在新的对话内容出现的时候就优先落盘，落盘后再继续对话的工作



记录落盘的结构为详细记录+索引的形式



索引和详细记录都为记录文档的形式



不同的对话来源要分为不同的文件，会有多个对话同时进行的情况



我想以日期为总文件夹，索引和详细记录在不同的两个文件夹内



一个对话文件的定义是新的对话开始到对话结束,结束包括cli关闭，对话通过指令终止，对话被用户停止等非正常情况



如果出现不可控的非正常情况，记录缺失也是可以接受的



我们目前只使用codex cli



当用户使用 resume 继续对话时，检查落盘断点是否完整，并在旧对话对应的文件中续写



一个完整对话中，每一组对话都占有单独一块，文档结构为快结构



索引块要能清晰的看出对话的内容，改动的文件等



详细内容块包含的调用工具等等详细的信息



记录的产物要可以反复提炼分析



但是要注意一个场景，比如我让ai写commit message 并提交，出现提交之后修改对话记录导致新的改动没有提交的情况，我们要规避这个问题



提炼





从用户的对话数据中提炼出用户的行为特点



产物形式已经是记录文档的形式



每一条特点单独一个文件



特点要标注关联的原始对话



需要标注依据



分析





将提炼产物分析整理成skill



skill要能够脱离任何项目和工具，保持独立性



skill产物有完整的文件结构，并且符合通用规范



QA





三个 Skill 分别在什么时候工作，处理哪些材料？



期望打开任何 Codex CLI 会话就开始记录



遇到不想保留的对话，你是否需要暂停记录或删除已有记录





如果想删除，应该也是删除skill产物，没有必要删除对话记录



我们可以提供删除逻辑，删除某一条规则后移除相关的提炼产物的记录产物



生成的 Skill 怎样进入你的实际协作





最终生产的skill就会按照通常的skill一样使用，被agent读取，然后做为项目协作的规范



提炼和分析由什么触发





提炼和分析惰性触发



在子代理中执行



由父代理判断是否满足提炼和分析的条件，满足由父代理启动



删除规则以后，允许它再次自然出现吗





允许



我们的规则来源是我们的对话方式，协作模式等等

补充





记录范围：打开任何 Codex CLI 会话即开始记录，每个新会话自动纳入，使用 resume 时接续原会话记录。



产物形成：提炼 Skill 从对话记录中归纳有依据的用户特点，分析 Skill 将这些特点整理为协作规则。特点和规则随材料自然形成，无需逐条人工确认。



使用方式：最终产物是可独立使用的通用 Skill。由支持 Skill 的 Agent 按常规方式读取，在适用的项目协作场景中使用。



删除范围：用户可以删除生成的某条规则，并清理与它关联的提炼产物。原始对话记录继续保留，可供后续提炼和分析。如果同一条提炼结果还支撑其他规则，需要保留那些规则的依据。



提炼与分析的触发方式：提炼和分析均采用惰性触发。父代理分别判断两个阶段的启动条件。满足提炼条件时，由父代理启动子代理，从已记录的对话中提炼用户特点；满足分析条件时，由父代理启动子代理，将已有的提炼产物整理成协作 Skill。父代理负责判断何时启动，特点与规则从实际协作材料中归纳形成。



规则删除与再次生成：规则来源于用户实际表现出的对话方式、编码习惯、思考方式和协作模式。用户可以删除某条规则及其关联的提炼产物，原始对话继续保留。后续提炼与分析时，已有或新增的对话材料都可以使同一条规则再次自然形成。
```
