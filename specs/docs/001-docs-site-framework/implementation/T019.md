# T019 实施方案

2026-11-27，用户在收到「按 T018 选定方式一次写入首页和技能集合页的桌面、手机四块画板，并验证可编辑性、裁切与可见状态」后回复「开始」，确认执行代表性转换并写入其提供的 Design 文件。 [T018 实测](../analysis/figma-conversion.md#t018-转换方式实测) · [原任务](../tasks.md#phase-8-user-story-6---一次启动将原型页面和状态转换为可编辑画板priority-p2) · [Design 目标页面](https://www.figma.com/design/xd4v3YLbHr6MFrshieoSPs/Untitled?node-id=0-1)

用 T017 核对过的 Make 源码启动本地预览。一次 Playwright 批次依次采集首页 Skills 章节和 frontend 集合页，桌面使用 1440 × 900，手机使用 390 × 844。首页两块取当前默认章节，集合桌面取默认侧栏，集合手机打开目录并保留 frontend 展开。各项确认标题、正文、视口和导航就绪后提交给 Code to canvas，四次采集指向同一文件的 `Page 1`。 [原型输入](https://www.figma.com/make/FOn29DUppcpuJ3bRP9QEOU/Agent-Foundry-%E6%96%87%E6%A1%A3%E7%AB%99) · [页面转换契约](../contracts/site-navigation.md#页面转换契约figma)

以任务清单中的实际视图和状态为画板命名，逐块对照浏览器参考画面与 Design 结果。核对常规文字是否为可编辑文本层、布局是否为可选和可调整的图层，以及正文、导航、裁切、字体、图片和 3D 的可见表现。将成功或失败、实际画板链接、差异与恢复条件追加到 `analysis/figma-conversion.md`。发生字体、图片替代时记录具体项及设计协作者的确认结果。 [需求与验收](../spec.md#user-story-6---一次启动将原型页面和状态转换为可编辑画板-p2)
