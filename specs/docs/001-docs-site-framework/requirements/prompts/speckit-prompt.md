# Agent Foundry 文档站 Spec Kit 提示词

根据以下讨论结论，为 apps/docs 起草 Agent Foundry 文档站规格。先读取 AGENTS.md、.specify/memory/constitution.md 和现有站点。按仓库约定设置 SPECIFY_FEATURE_DIRECTORY，将规格归入 specs/docs/NNN-<功能名>/，保留原始输入和讨论依据。根目录原有的 a.md 如可取得，一并保留为历史输入。本次交付 spec.md 及适用的规格检查结果。

本期目标是搭出可浏览、可扩展的文档站框架，采用 Nuxt UI。五个模块使用四套布局。

- home 承载首页。首页是以项目 AI 相关包为主题的全屏杂志式页面流。先用 Skills 和 MCP 作为可替换的章节示例，每章显示包名、占位正文和独立的 Three.js 模型。正式章节清单和文案后续补齐。
- skill 承载技能集合页和技能详情页。左侧是两级文件夹目录，一级是集合，二级是技能。集合页预留说明区域。技能详情页可直达，标题显示技能名称，正文先用占位。
- work-with-speckit 承载与 Spec Kit 协作。交付可点击、可切换选中项的一级左侧导航。栏目名称及正文均使用可替换的占位内容，正式目录后续确定。
- empty 供 MCP 文档和项目开发文档共用。两个模块分别有可直达的占位页，MCP 使用现有 /mcp 路由。

全局顶部提供技能文档、MCP 文档、与 Spec Kit 协作、项目开发文档四个一级入口。仅技能文档有集合子菜单，集合与左侧目录一致。品牌入口回首页。本期可用一份可替换的集合和技能样例数据验收导航。

Skill 包后续提供产物。dist/core 对应现有构建产物，新增 dist/docs 作为集合说明来源。集合文档字段省略或为 true 时读取默认 README，为字符串时读取集合目录中的指定文件，为 false 时跳过读取。找不到文件时告警并跳过该文档，继续处理其他集合。本站规格记录内容接入点，真实产物接入随 Skill 包就绪后验收。

使用可独立验证的用户故事和 Given/When/Then 场景，覆盖首页章节、全局菜单、两级技能目录、技能名称与占位正文、Spec Kit 占位栏目切换、移动端导航和路由直达。核对现有有效链接、无效地址的 404，以及 3D 加载失败时文档入口的可达性。将 Nuxt UI 集成、Three.js 渲染和 dist/docs 跨包接入列为后续 Plan 的技术验证项。当前工作止于需求规格。

## 关联交付与开发协作

`packages/skills` 先完成测试环境约定的验收，再扩展到生产。测试范围和版本回退边界沿用现行发布规格。文档站在 `dist/docs` 就绪后验收跨包接入。 [主线技能构建与发布规格](../../specs/skills/003-skills-release-pipeline/spec.md)

开发阶段，在彼此独立且不阻塞主代理的情况下，尽量把调研、核对和审查并行交给多个子代理。主代理继续推进手头工作，子代理得出结论后主动汇报。

## Figma Make 原型批量转设计稿

将已完成的文档站 Figma Make 原型批量转成可在 Figma Design 中继续编辑的设计稿。将本轮需求和原型提示词保留为规格依据。 [本轮原始需求](./1.md) · [Figma Make 原型提示词](./figma-make-prompt.md)

### 批量转换需求

从实际原型整理页面清单，覆盖五个模块和各模块中可达的页面或视图，标记需转化的桌面、移动端和关键交互状态。调研可批量导入的工具，以及由 AI 或脚本按清单采集的方式。选定的流程应在一次启动后处理清单内的所有项，在同一个 Figma Design 文件中生成与页面和状态对应的具名画板，常规文字和布局图层可直接编辑。用户无需逐页打开、复制和粘贴。

### 初步调研

- Figma Make 的「复制设计」可以把当前预览状态转为可编辑图层。其操作以当前页面或状态为单位，可用作代表性页面的对照。 [Figma Make 帮助](https://help.figma.com/hc/en-us/articles/35060759685015-Copy-a-Figma-Make-preview-as-design-layers)
- Figma MCP 的 Code to canvas 可以把浏览器中实际渲染的界面采集到同一个 Design 文件，每次采集对应一个页面或状态。可验证由 AI 或脚本按清单批量触发，输入可来自已有的可访问站点，或运行从 Make 导出的代码。 [Figma MCP 文档](https://developers.figma.com/docs/figma-mcp-server/code-to-canvas/) · [Figma Make 导出代码](https://help.figma.com/hc/en-us/articles/33649966245783-Edit-the-code-of-a-functional-prototype-or-web-app)
- 有可直接访问的页面 URL 清单时，可验证 html.to.design 的批量导入。该能力需要该插件的 PRO 订阅。 [批量导入文档](https://html.to.design/docs/bulk-import-url-list/)

以上为文档调研结论。项目实测待取得可访问的原型或可运行的源码，以及可编辑的 Figma Design 文件或工作区。

### 验证需求

把实测写成一条独立需求及对应的验收场景。后续 Plan 先以实际原型中的首页和至少一个内页验证批量触发、桌面和移动布局、文字与布局图层的可编辑性。比对原型，检查内容、导航状态、字体和图片，并记录 3D、动画等动态内容的保留效果及所需的静态替代或人工补齐。

代表性验证通过后，按实际清单跑一次全量转换。验收时逐项核对源页面或状态与 Figma 画板的对应关系，确认全量覆盖和无需逐页手工处理。保存本次输入、运行方式、画板链接、检查结果与差异。按实际情况记录通过、失败、缺前置和未执行，受阻项写明恢复条件。

### 转换方法复用

全量转换验收通过后，在需求末尾沉淀可复现的方法，供后续迭代使用。记录采用的工具、输入与权限、页面清单的维护方式、批量运行步骤、设计稿的组织方式、动态内容的处理以及失败后的重跑方法。
